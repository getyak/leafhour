# 安静的阅读细节验收

本轮由子代理实现，主代理在真实页面评测审美、阅读连续性与交互。测试页面使用独立临时服务和合成账号，没有向真实书房写入验收数据，没有调用翻译或解释模型。

## 书房续读

在320、390、768、1440像素宽度检查问题便笺。纸色背景、细分隔线、小字号标题与正文摘录区分，问题只保留三行视觉高度，完整用户文字仍留在页面供辅助阅读。没有横向溢出。

第一次评测发现便笺把主要的“继续阅读”按钮向下挤约120像素，已将按钮保持在原文节选后，便笺放到其后，并重新检查宽窄屏。点击“回到提问的原文”返回该问题自己的段落，正确打开个人问题面板，展示合成用户原话；继续阅读仍指向原来的阅读位置。

独立代码审阅发现个人记录服务失败会连带让原文预览失败，修复后复审通过。鉴权、书籍读取与段落校验仍正常拒绝错误请求，只有可选问题的读取降级。

## 阅读正文

宽屏从原文切换到对照时，同一段落顶部实测从170.625到170.797像素，偏移约0.17像素。390像素下选中原文，复制结果与选择内容一致；没有打开个人面板或切换语言。夜读模式没有横向溢出，正文中没有纸人物或新弹窗。检查期间没有浏览器错误日志。

## 收尾与保存

宽屏与320、390、768像素收尾页均实际检查，覆盖夜读与纸白。首次手机评测发现人物挤压标题，留下单字末行；修复为标题独占一行，小人物与关闭按钮在上方，320和390像素标题均完整，没有横向溢出。收尾人物在普通动态设置下所有元素的计算动画均为none。按Esc关闭，焦点回到原“读后记录”按钮。正文没有增加人物或自动弹窗。

模拟笔记服务失败时，提示文字已留在本机；在同一次提交等待期间继续写的新文字没有丢失。恢复服务后重试，确认旧提交，新草稿仍在输入框，提示明确说明尚未提交。再模拟浏览器写入失败与服务失败，实际页面提示文字仅在当前页，并建议先复制，没有误报本机已保存。临时存储故障注入已恢复。

结束页的位置重试确实发送保存，并在确认后隐藏重试按钮。后来将正常结束接入同一异步位置保存路径，无需额外点击。重新打开页面以及开启新计时，均没有旧时段的成功文案。上一次成功后让新一次时段服务失败，页面显示“本次时段已留本机，书房尚未确认”，位置仍单独显示成功。

独立代码审阅进一步验证了不匹配最终回执的恢复路径：无效、旧或不同来源的回执不得清掉可重试记录；修复后的专项测试覆盖保留队列、真正再次发送和正确确认。

最终版本重新进入阅读仍默认原文，无自动弹窗和正文人物；390像素原文切换中文后仍留在同一长段落的相近位置，没有横向溢出。正常动态设置与减少动态效果的临时覆盖已恢复。

## 自动验证与交付边界

`npm run verify:deploy`在同步最新首页更新后再次通过：462项测试，461通过，1项既有跳过，0失败；隔离阅读运行包成功构建并初始化，无模型请求。公开构建、256项软件文件发布白名单、静态资源与来源提交检查均通过。代码审阅和本机页面验证分别进行，没有用纯函数通过替代浏览器接线验证。

以上属于浏览器模拟尺寸验证，不代表实体手机验收。该记录描述本机与自动验证；PR、远端合并和线上发布以交付时的实际状态为准，真实账号的私有保存未在本轮重复写入。
