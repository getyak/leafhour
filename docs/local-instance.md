# 本机实例与数据

Leafhour 的本机入口使用同一套阅读领域服务和 JSON 持久化，不需要数据库服务器。Node.js 22.13 及以上，在仓库根目录安装并运行：

```bash
npm ci
npm start
```

`package-lock.json` 固定依赖版本与完整性校验，解析地址统一为 npm 官方 registry。npm 继续按原生规则使用用户配置的 registry，兼容 npm 12 的远程 URL 默认限制；不启用任意 URL 依赖、不关闭完整性验证、不改用户全局配置。

默认地址为 `http://127.0.0.1:8330`。先在网页明确进入“本机书房”，再上传自己的资料和保存记录。本机书房是本实例的单人身份，并不代表邮箱已经核验；邮箱与托管认证继续使用原有配置。

## 选择稳定目录

把下面的示例路径换成自己拥有的私人目录：

```bash
READER_DATA_DIR="/absolute/path/to/leafhour-data" npm start
```

也可以在既有 `.env` 中设置 `READER_DATA_DIR`，仍通过 `npm start` 启动。只维护现有 `.env`；外部提供的环境变量优先。目录含空格时按 shell 或 `.env` 规则加引号。

绝对路径能跨源码目录更新复用。相对路径按**启动工作目录**解析，例如在仓库根目录设置 `READER_DATA_DIR=./local/my-room`。未配置或设为空值时，继续使用源码根目录下原有的 `local/service/`。配置一个新目录会打开独立实例，不会自动寻找或搬迁旧书房；路径无法使用时启动失败，不回退另一份数据。

| 相对实例根目录的路径 | 保存内容 |
|---|---|
| `records.json` | 兼容单书入口的个人评论、问题与位置等记录 |
| `experience-records.json` | 兼容样书的互动与回声状态 |
| `portal/auth/` | 本实例身份与会话，属于私人授权资料 |
| `portal/library/users/` | 按身份隔离的书籍、原件、译文、个人记录、资料与 AI 对话 |
| `portal/library/limits/` | 本机阅读 Agent 的既有额度记录 |
| `portal/audio/` | 本机听读任务、状态与音频资源 |

`READER_BOOK_PATH` 仍只选择已有的来源阅读包，其文件不会被当作个人数据库。原文、译文与编辑注解保留各自字段和出处；用户评论、问题与 AI 回答保留不同来源，个人记录不写回原文。新建私人目录和文件继续采用现有私有权限规则；不要将实例目录放进公开静态目录、Git 或同步给未授权人员。

## 停止、重启与更新

1. 等待页面保存确认，然后在服务终端按 `Ctrl+C`，等进程结束。
2. 保留实例目录和来源阅读包，按同一个 `READER_DATA_DIR` 再运行 `npm start`；原会话、书籍和已保存记录继续从该目录读取。
3. 更新源码前先停止服务，保留私人配置；更新后执行 `npm ci`，继续选择同一绝对实例路径。切换到新检出目录时也要明确选择这份路径。

一个本机数据目录同时只运行一个服务进程。运行两个独立书房时，应使用不同实例目录与不同 `READER_PORT`；本机 JSON 模式不提供跨进程数据库协调，也不应把同一目录共享给多台机器。

首次从原默认位置迁出时，先停止原服务，再将自己确认的**整个** `local/service/` 复制到新实例根目录；保留原副本，启动并核对书籍和记录后再决定备份策略。不在运行期间移动文件，不合并两份书房目录，不单独覆盖其中一个 JSON。已有应用内书房备份/恢复是内容与个人记录迁移入口，备份不包含模型密钥或身份会话；需要邮箱身份迁移时继续遵守已有账号流程。

目录配置仅影响本机标准启动入口。Vercel/Supabase 仍使用既有托管持久化，不会因为设置本机变量而切换存储。选择目录和重启本身不会触发模型；翻译、对话、听读以及已开启的站内陪读继续遵守各自现有配置、授权与触发规则。
