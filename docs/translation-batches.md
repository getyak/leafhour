# 分批翻译与断点恢复（GET-151 工程切片）

本工具把「用户显式启动的全书翻译」编排成**有界、串行、可核对、可续跑**的批次：它只调用 Leafhour 现有的登录态 HTTP 翻译接口，不新增翻译供应商、不建立调度任务、不自动在翻页时生成译文，也不扩大任何模型额度。模型调用仍计入既有配置的翻译服务与配额。

实现说明与验证证据见 [GET-151 验收记录](verification/2026-10-18-get-151-translation-batches.md)；设计与计划见 [规格](superpowers/specs/2026-10-18-get-151-translation-batches.md) 与 [计划](superpowers/plans/2026-10-18-get-151-translation-batches.md)。

## 重要边界（先读）

- **演练默认**：不加 `--execute` 时只读取书籍并打印计划，不写检查点、不占用额度、不生成任何译文。
- **单次有界**：实际执行必须同时给出 `--execute` 与 `--max-requests 1..20`，一次最多 20 段，串行请求；单次调用不可能悄悄翻完一整本书。
- **结果全是 `draft` 草稿**。术语一致性、人工复核（`reviewed`）与来源页校对是另外的质量门，本工具不代替它们。
- **全书内容与人工复核尚未完成**：本工具只是工程切片。用户批准的实际全书内容、付费调用范围与本人复核仍未取得/未完成，GET-151 保持开启。
- 会话只从环境变量 `LEAFHOUR_SESSION` 读取；**不接受密码，也不接受命令行令牌**。

## 前置条件

1. 一个可访问的 Leafhour 实例（本机或自托管），以及该实例上**已登录**的浏览器会话。
2. 把会话 cookie `marginalia_session` 的值放进环境变量 `LEAFHOUR_SESSION`（只在当前 shell 会话有效，不要写入文件、命令历史或仓库）。
3. 目标书籍 ID（`bookId`）。

## 用法

```bash
# 演练：只打印计划（默认行为，零写入、零生成）
LEAFHOUR_SESSION='<session cookie>' \
  node tools/translation-batch.mjs --origin https://leafhour.com --book <bookId>

# 实际执行：显式 --execute 与 --max-requests 1..20
LEAFHOUR_SESSION='<session cookie>' \
  node tools/translation-batch.mjs --origin https://leafhour.com --book <bookId> \
  --execute --max-requests 20

# 再次执行即续跑：失败/未知的段落会重试，并按服务器实际译文对账
```

参数：

| 参数 | 说明 |
| --- | --- |
| `--origin <url>` | 服务来源，仅 HTTPS 或本机回环 HTTP；不允许账号信息、路径、查询或片段 |
| `--book <id>` | 书籍 ID |
| `--checkpoint <path>` | 检查点路径；默认 `local/translation-batches/<bookId>.json` |
| `--execute` | 实际生成；缺省时是演练 |
| `--max-requests <1..20>` | 本次请求上限，必须与 `--execute` 同时给出 |
| `--help` | 用法说明 |

退出码：`0` 演练完成或本次额度用尽；`1` 执行被拒绝或在第一个失败处停止（含 Ctrl-C）；`2` 参数或会话不正确。

## 计划口径（哪些段落会被翻译）

按现有正文/来源分节语义遍历，保持章节与来源顺序，并**排除**：

- 卷首（front matter）与附录（appendix）章节、元数据标题段（`source_heading`）；
- 中文原文段落（无需中文译文）；
- 两种译文齐备的段落（`complete`）；
- **部分译文（`partial`）**：只有一种译文的段落整体跳过并报告，绝不用一次生成去替换已保存的那一种；
- **已复核（`reviewed`）**：任一译文带人工复核状态的段落跳过并报告，永不覆盖。

只有「两种译文都缺失」的正文段落进入生成队列；每次请求前会重新读取实际状态，运行中新增的部分/已复核译文同样跳过并报告。

## 检查点（私有、原子、非机密）

- 位置默认 `local/translation-batches/<bookId>.json`；目录 `0700`、文件 `0600`，先写临时文件再原子改名。
- 绑定：`账号 user ID + 服务来源 + 书 ID + 原文版本 + 有序段落 ID 与原文文本的哈希`。账号、来源、书籍或原文版本变化后拒绝继续使用同一检查点（换新检查点再跑）。
- 同一检查点带执行锁：取得、恢复与释放均由短 guard 串行化，释放核对随机归属与文件身份；有效归属的已退出进程锁可恢复。未初始化/损坏的锁、崩溃遗留的 guard 均拒绝抢占，须先核对活动进程后人工恢复；不会因文件暂空而启动第二次生成。
- 检查所有现存祖先，拒绝符号链接、非普通文件与硬链接；已有检查点父目录非私有则拒绝，绝不改变共享目录权限。macOS `/var` 等别名路径请先解析为实际路径。绑定变化不覆盖旧文件。这些检查不构成对同一系统用户恶意进程的沙盒。
- **不含**会话令牌、原文、译文、注解或个人记录；只保存稳定段落 ID、状态（`saved | failed | unknown`）与原因码（如 `http-429`、`timeout`）。

## 断点恢复与失败处理

- 失败的请求记录稳定 ID 与原因后**停止本次运行**；401/403/409/429、网络与超时都不会自动循环重试。
- 网络/超时、POST 后响应体读取失败或缺少完整且匹配原文的保存回执，均记录为 `unknown`，不冒充成功。恢复执行时先按服务器**实际保存的译文**对账：已保存的段落标记为 `saved`（`reason: reconciled`），不再重复生成；检查点原先写作 `saved` 而服务器已缺失的段落也重新对账，仍未翻译的段落保持可重试。
- 来源在两次请求之间更新时本次停止（`source-changed`）；在生成过程中更新时由服务端在保存前拒绝（409），旧书不会被重建、旧译文不会盖到新来源上。
- Ctrl-C 后不再发出后续请求；正在进行的请求按实际结果记录，**不声称**已撤销或退款。

## 服务端保障（对旧调用兼容）

`translate(user,id,passageId,options={})` 与既有 `/api/library/books/:id/translate` 路由新增可选 `contentVersion`（预期原文版本）：

- 传入时，来源版本不符在任何模型请求**之前**被拒绝（409）；版本化批处理在取得预留后再次检查，部分译文拒绝（409），齐备译文直接返回，不产生新调用；不传版本的旧调用行为不变。
- 保存前重新读取来源与归属：来源更新（409）或书籍删除（404）都不会重建旧书或写入过期译文层。
- 保存时不覆盖**已复核**的译文，也不覆盖生成期间**并发新增/修改**的版本；只替换调用开始前就存在且未变化的草稿，兼容旧行为。

## 还没有做的事

- 用户明确批准的**实际全书内容**与**付费调用范围**仍未取得；本工具不会自行启动全书处理。
- 人工复核（`reviewed`）、术语一致性检查、来源页校对仍未完成；生成齐备不等于已审阅。
- 无调度、无自动触发、无站外通知；每次生成都要求操作者显式 `--execute`。
