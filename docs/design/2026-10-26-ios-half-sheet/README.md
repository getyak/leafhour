# Leafhour iOS：半屏陪读原型

日期：2026-10-26。用户选择「半屏陪读」，并授权制作核心流程图、关系设计和 iOS 交互原型。这里记录设计与演示范围；不是生产 iOS 应用或服务接入的验收。

## 已确定的方向

正常启动直接回到上次那本书、同一段文字与阅读偏好。陪读面板默认收起。先让缓存正文可读，随后同步；用户已开始阅读时，不因远端位置返回而跳页。首次使用进入书房；显式引用链接优先定位引用，并提供回程。

正文、讨论、临时出处各有自己的位置。选文发起问题时，绑定书、来源版本、段落及真实选区；读者继续翻页不会悄悄更换已发送问题的上下文。半屏时主动读到新段，关闭面板留在最新阅读位置；另设「返回提问原句」才跳回旧段。回看出处不覆盖正式阅读位置，返回时保留问题、回答滚动位置、输入草稿与面板分档。

新的选区不覆盖已发送问题或已有草稿的引用。「用这句提问」为新选文建立另一份草稿，原草稿仍可找回；只选择文字不会改变讨论上下文。

## 主流程

打开 → 恢复阅读 → 选择词句 → 解释这句 → 半屏读与问 → 展开讨论 → 查看出处 → 返回讨论 → 继续阅读。

辅助流程：书房选择当前样章；章节目录按真实段落定位；原文、直译、意译独立切换；输入自己的笔记后保存；从记录返回原句；断网时保留正文、选文与问题，恢复后显式重试。

## 面板与手势

| 状态 | 行为 | 返回 |
| --- | --- | --- |
| 收起 | 正文占据画面，底部「读到这里」入口 | 正常启动的默认状态 |
| 半屏 | 源句仍可见；上方正文可滚动，面板可独立滚动 | 下拉或「继续读」 |
| 展开 | 阅读对话、键盘与来源占据主要区域 | 下拉到半屏或继续读 |
| 出处 | 在讨论内部临时核对来源；保留明确的回程 | 「返回讨论」恢复原问题与草稿 |

主方案是原生系统 sheet 的连续拖拽与分档。设计稿中的按键和拖拽转场只表达关系；Web 原型的物理近似不代表 SwiftUI、触觉、真实键盘或 120 Hz 性能已经验证。减少动态使用静态位置与短淡入；所有手势都有可见按钮替代。

## 页面与对象关系

全局只有阅读、书房和记录。阅读页上方是书房、书名/目录、排版；下方是当前章节与陪读入口。设置归入书房，读书时不常驻多标签栏。

书 → 章 → 稳定段落。原文、直译、意译各自有来源与版本。选文快照指向段落与实际版本；问题绑定选文，回答保存实际引用。自己的笔记与讲解摘录分别归属，不把示例回答保存成用户原话。私人笔记不自动进入问题上下文。

`ReadingPosition` 与 `DiscussionPosition` 分开保存。前者含书、章、段落、段内位置与显示偏好；后者含问题、面板分档、回答位置与草稿。`CitationVisit` 只记录临时出处与返回帧。

原生实现需沿用服务的稳定锚点，明确 Unicode 码点、UTF-16 选区与 Swift 字符索引之间的换算，不能跨端直接混用像素或页码。原型只演示一份固定公版样章，不迁移或覆盖真实阅读数据。

## 内容与边界

演示使用 Henry David Thoreau 的公版《Walden》片段：[Project Gutenberg #205](https://www.gutenberg.org/files/205/205-h/205-h.htm)，章节 Where I Lived, and What I Lived For。四个稳定 ID 是原型的演示片段，不声称与原书段落边界或正式服务 ID 相同。第三片段在原句逗号之前截取，不给作者原文补句号，界面另标「节选」。中文是本原型独立撰写的示例译文，直译与意译分开；讲解、问题和记录都是固定演示。原型不接模型、不请求书房账号、不读取私人文件、不发送输入内容。

默认上下文为实际选文与有界邻文。若需要扩展，说明将查阅的内容范围；禁止把后文悄悄当成当前段的解释依据。站内陪读沿用既有开关和前台触发约定，本原型不启动后台生成或通知。

## 视觉取舍与参考

## 验证要求

核对阅读 → 选文 → 半屏 → 展开 → 出处 → 原路返回；重开后仍从阅读进入。分别检查来源/译文/讲解/笔记归属、选文后上下文固定、草稿不因引用或关闭面板丢失、重试没有伪造成功、字体增大后可读，以及深色、320 px 窄屏和减少动态。

Figma 写入前，必须读回文件名、页面与变量/组件，确认是本任务的 Leafhour 文件。仅在新建任务页面/节点写入。原始设计、其他产品文件与已有组件不重置。写入成功仍须截图和原型反应读回，才记录为完成。

最终证据写入 `verification.json`；该文件尚未出现时，只能说明设计方向，不能说明 Figma 或原型已验收。

## 实际验证与未完成项

2026-10-27，本机 Chrome 完成 11 项交互检查与 13 个状态导出，重复选词的真实选区、草稿隔离、出处回程、半屏正文续读、重开恢复、显式重试、笔记归属及 320 px 大字深色/减少动态均通过。原型没有页面异常或外部网络请求。单文件独立打开另验；详细结果与源文件哈希见 [verification.json](verification.json)。

独立设计审阅确认没有必须再向用户询问的缺项。独立代码审阅发现的草稿错绑、笔记串段、旧回程残留与过早显示恢复结果已修正；5 条最小 DOM 状态复现链通过，实际浏览器另验。首轮跨行选字的测试驱动错误及原始输出保留在 `evidence/`，不冒充最终应用失败。

通过 Computer Use 重启 Figma、处理其更新失败提示，并在 Drafts 新建本任务文件。初次连接失败与旧插件版本不匹配后，保留原插件，使用独立的 Figwright 0.7.0 与同版本本机服务完成写入。没有修改文件共享权限。

画布包含 13 个状态、三张流程/关系/导航图、4 个共享颜色变量、19 个文字样式和 5 个共享组件。165 个控件的跳转反应逐一读回；通过 Computer Use 在 Figma 演示中实际点通阅读、半屏、展开、出处、返回讨论与继续读。8 张实际导出图完成视觉核对，详见 [Figma 验证记录](figma-verification.json)。首次图表导入漏掉连线，已改为显式矢量箭头并重新导出。

Figma 是固定状态演示；文字输入、真实选区、独立滚动与草稿恢复由 Web 原型验证，不把保存的反应配置当成这些行为已经实现。

本任务不改生产阅读代码。在基线 `32662f8` 上，独立工作目录的站点构建和公开文件检查通过；完整本机应用检查没有通过：Node 22 下出现本地实例、PDF 打包与阅读运行时的超时/子进程退出，单独构建阅读运行时也在 DSH 初始化时超时。结果保存在 [应用基线检查](evidence/application-baseline-checks.json)，不把原型的 11 项通过写成正式应用全量通过；交付分支随后同步到 `062d307`，合并仍以同一提交的远端检查为准。

这里交付的是可评审的 iOS 设计原型。真实 SwiftUI、iPhone、Safari、触觉、系统键盘、120 Hz 性能与完整 VoiceOver 均未验证。原生实现的触控范围按 44 pt 设计，不能将浏览器原型的视觉命中盒当作原生无障碍验收。

## 重现

使用已有 Playwright 运行时，将其 `index.mjs` 绝对路径放入 `LEAFHOUR_PLAYWRIGHT_MODULE`；此约定沿用项目已有浏览器验证工具，不新增项目依赖。

```sh
node build-diagrams.mjs
node verify-prototype.mjs
node build-vectors.mjs
node render-artifacts.mjs
```

浏览器验证用隔离会话和只服务本目录的临时本机服务；不依赖正式 Leafhour、账号、密钥或模型。PNG 由实际浏览器画面导出，SVG 按实际字形基线和换行导出；渲染图表时使用浏览器字体，避免系统字体替换造成缺字。
