# 笔记保存与失败重试

GET-306 · Keep iOS note saves safe to retry。此批只处理原生本机保存、编辑页反馈和确认后的回程，不改书籍、引用或导出格式。

## 实际发现

在 iOS 26.5 Primary iPhone 的任务专用应用中，从“我的记录”打开草稿后，受控阻断该书状态文件的写入。保存失败时，根“阅读记录”弹窗出现在正文上，嵌套编辑页不再可见。恢复文件后，根重试只写入一条笔记，冷启动也保留一条。这里没有观察到重复笔记或数据丢失，不能把根重试说成重复添加。

另有两个实际宿主失败用例：原来的失败提交留下一条未确认笔记并移除内存草稿；原来的 `flush()` 会在调用时的旧写入完成后返回，即使后续编辑仍在排队。这是直接运行实际 ReaderSession 的受控存储验证，不等同于原生界面已复现提前关闭。

## 保存契约

同一编辑页持有一个提交 UUID，重试按这个 ID 更新；另开编辑页使用新 ID。因此两个相同原句、相同正文的独立笔记仍然可以并存。点击动作先锁住编辑和提交入口，领域方法也限制同一时刻只有一个笔记提交。

每次成功写入都登记回执。`flush()` 等待最新稳定版本，关闭时再检查该回执是否仍是当前版本，避免旧完成状态允许新编辑提前关闭。书房切换和阅读页返回使用同一确认规则。

失败只撤销本次尚未被成功快照包含的笔记修改，并保留最新草稿；不恢复整份旧状态。若笔记 N 已落盘，后续 N+1 写入失败，也不能撤销 N。根重试继续保存当前状态：未提交成功时保存恢复后的草稿，已确认的笔记继续保留，不另建笔记。

编辑页活跃时，保存错误留在编辑页内显示，根保存弹窗不抢走编辑上下文。反馈分别说明提交中、尚未全部保存、草稿已保存和笔记已保存；普通提示与保存错误分开，成功只清理对应的保存错误。已经确认当前正文的笔记，取消侧入口显示“关闭”。

## 实现边界与验证

将现有纯 Foundation/Observation 的 ReaderSession 和 SelectedQuote 移入 LeafhourCore，并用窄异步 ReaderStateStore 协议适配原有 OfflineLibrary。测试只控制写入暂停和失败，成功写入仍走真实本机库；不另写一套相似测试模型，不改存储 schema，不引入网络服务。

源代码、当前提交验证、截图和实际未验收项以 GET-306 的 verification 记录为准。故障仅作用于任务应用的隔离公版数据；host driver 负责退出恢复，不依赖 XCTest 失败时的 Swift defer。模拟器结果不扩展为真机、VoiceOver、硬件键盘或 TestFlight 验收。
