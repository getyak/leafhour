# 第四轮：留下的想法可以继续写

隔离探针证明草稿仍在；问题在于记录页只有已保存内容，读者看不到未保存的想法。本轮沿用已批准的阅读、记录与半屏方向，不增加全局入口或新的笔记产品。

选择在“自己的笔记”里条件显示“未保存的笔记”，点开恢复原引用与原文字。已有保存列表保持独立。没有草稿时不增加空分区；草稿存在时不再显示“还没有笔记”的大空态。来源版本与所选文字仍可辨认，不显示凭空制造的更新时间。

曾考虑单独草稿标签与每次返回时自动弹出编辑器：前者增加导航，后者打断阅读并可能错开讨论范围。因此采用记录内的轻量分区。这个选择由本轮执行者依据持续优化授权作出，不冒称用户单独挑选了版式。

从记录打开草稿，保存/返回都回原记录位置；从讨论打开仍回原讨论，从阅读打开仍回阅读。笔记临时引用不更换当前讨论，也不把笔记传给讲解。

保存后沿用轻量反馈，提供8秒“撤销”。焦点在撤销按钮时保留反馈，离开后再结束。撤销只移除本次且内容未改变的那一份保存，恢复原始编辑文字为草稿并打开它；另一条笔记不受影响。若同一引用已有不同的新草稿，不覆盖、不删除，明确说明两份内容都已保留。重复撤销不产生重复内容。撤销是本次运行的短暂机会，不承诺跨重开保存撤销栈；草稿找回本身必须跨刷新。

稳定的六字段引用键和样章版本不改；坏键/不属于样章的引用不用于伪造出处，也不删除原存储。普通、窄屏夜读、大字、减少动态与键盘聚焦都以实际网页检查。Figma只连接固定状态真正一致的跳转，保留之前所有版本。仍不接模型、不读私人笔记或写真实书房，不把网页当作原生iPhone验收。

审阅后收紧恢复入口：六字段键必须与既有标准序列化一致，并对照样章中同版本、同层的真实文字校验范围、完整Unicode代理对与所选文字；旧空范围仅在文字确实属于该段时恢复。不通过的值保留，但不能显示成可以带确定出处继续的草稿行。
