# Leafhour：纯读与意图

本轮按用户提供的完整《Leafhour 沉浸式阅读 · 判断》及 [GET-272](https://linear.app/getyak/issue/GET-272)、[GET-273](https://linear.app/getyak/issue/GET-273)、[GET-274](https://linear.app/getyak/issue/GET-274) 更新现有原型。参考入口为 [Cursor Canvas](https://cursor.com/canvas/store-c99d88ad-6360-4f7d-83d2-751c40e37d9b/b7610ca6-6488-4687-b72b-968cc548af8b)，正文由用户直接补充；不声称从空白的嵌入画布读到了正文。此前取消的持续任务保持删除，本轮是一次新的按需请求。

## 判断与取舍

纸感字阶与半屏保留。改变的是出现时机：默认正文铺到模拟安全区，工具只在明确意图下出现。正文普通点按严格无操作，采用参考中较克制的选项，不增加点按唤醒正文的例外。不增加全局标签或常驻 AI 气泡。

顶栏和进度分开唤醒，覆盖在正文上；显隐不改变排版或文字坐标。底区以可拖动的章内进度为主，“读到这里/继续讨论”是次要的明确召唤，不在纯读态出现。键盘聚焦和进度调整时不让工具突然睡去。

原型采用3秒工具空闲收起、420ms长按判定、8px移动取消与80ms菜单淡入；这些是本轮的实现选择，非参考声称的系统常数。手机滚动取消尚未成立的长按。桌面拖拽选字沿用原生选区；浏览器的文字选择/复制能力保留，范围调整只更新待选引用，不更换既有讨论。

## 状态机

| 主意图 | 可见内容 | 离开 |
| --- | --- | --- |
| pure | 满安全区正文，极淡模拟时间；无锚点、工具岛、选区菜单、AI正文 | 点顶部/底部边界，或长按正文 |
| top | 仅书房、书名/层、Aa | 空闲、滚动、Esc或其他明确意图 |
| progress | 仅章内进度与次要陪读召唤 | 空闲、滚动、Esc或打开陪读 |
| selection | 原生选区与贴边三动作 | 点空白/取消、选区移出、或解释/原文/笔记 |
| sheet | 一个阅读辅助面板；半屏上方可继续读书 | 继续读后1秒内恢复pure |

同一时刻只有一个主意图。若在半屏上方长按新的原句，先收起已有面板并保存其编辑状态，再进入选择；原文/笔记的回程可以恢复原讨论，不丢原草稿。展开面板不再叠完整顶/底工具。新选句解释保留上方可读的选中原句；继续已有讨论不把阅读位置拉回旧段。

## 必须保留

稳定段落、样章sourceVersion与会话键不改。原文/直译/意译、讲解、自己的笔记独立。已有问题/草稿/未完成提问保持原引用；只选字不改变讨论。笔记草稿找回、保存撤销与冲突保护不退化。测试仍为固定公版样章及新建合成浏览器会话，不调用模型、真实书房或私人笔记。

模拟安全区的边缘按钮不覆盖正文。真实iOS系统状态栏/主屏手势的边界与选区手柄还需原生实现验收；本轮网页不承诺操作系统层行为。屏幕阅读与键盘有等价唤醒/菜单路径，减少动态保持静态反馈。

## 验收

实际静读10秒的截图没有解释或对话入口；正文上下留白只为安全边界。普通正文点按不打开菜单；长按成立后0.5秒内有贴选区动作，滚动不误触；原生选区改变时范围与工具同步。顶/底只唤醒自己的工具，字形坐标与阅读锚点不移动。进度能拖动并保留位置。解释打开半屏且上方可见书/新选句，继续读1秒内无chrome；引用/草稿/笔记与减少动态、窄屏夜读及大字另验。

本轮操作代码仍在 `../2026-10-27-ios-polish/prototype/`，以保持现有8937入口。截图、状态图与实际结果在本目录记录；网页/Figma与原生iPhone验收分开。
