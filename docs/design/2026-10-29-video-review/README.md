# 从录屏到书房：设计分析与改动

这次最值得保留的是书与正文的存在感。书架已有自己的样子，进入正文后也能安静地读。需要补上的，是搜索、笔记与日历的清晰反馈，以及记录多起来以后仍然稳定的操作。

依据是 2026 年 10 月 29 日提供的 4 分 34 秒录屏，以及当前应用的代码和浏览器复现。视频没有音轨，下面不推测口头意见。时间为视频内的大致位置。原始画面包含浏览器信息与个人记录，不随公开仓库保存。

## 值得保留的设计

| 画面 | 好在哪里 | 本次取舍 |
| --- | --- | --- |
| 00:00，书架 | 书封有辨识度，书是页面的主要对象 | 保留现有封面与排列，调整标题和作者的阅读层级 |
| 01:35 左右，侧栏展开 | 图标收起后节省空间，展开后能找到日历和笔记 | 保留现有导航，检查关闭浮层后能否回到原入口 |
| 01:47 左右，首页 | 真实书页摄影与大标题建立了阅读氛围 | 保留。这一幕是首页，不能当成书房加载失败 |
| 02:00 后，阅读日历 | 阅读记录与具体日期相连，可以返回原页 | 保留实际记录与时长口径，修正选中日期的反馈 |
| 02:30 后，我的笔记 | 个人想法、问题、引文和来源已有区分 | 保留原话和引用关系，优化大量记录的载入与滚动 |
| 03:30 后，双语阅读 | 原文与译文按段对应，深色背景没有多余装饰 | 保留段落对应与正文样式，增加轻量的译文侧线 |

## 问题与处理

| 问题 | 视频依据或复现 | 已采用的处理 |
| --- | --- | --- |
| 搜索面板偏小，像通用表单 | 00:00–00:55 | 调整为靠近屏幕上方的宽面板，搜索栏成为明确的入口 |
| 书名、作者和命令挤在同一层级 | 同一段搜索操作 | 书名与作者分行，加入操作标记和键盘选中反馈 |
| 搜索宽度受通用弹窗限制 | 当前代码与浏览器复现 | 移除继承的 480 像素上限，窄屏仍保留边距 |
| 长书名、作者容易截断 | 书架；窄屏及长作者名复现 | 书名完整换行，作者最多两行，阅读入口保持可见 |
| 日历选中今天，却仍提示选择一天 | 02:00–02:25 | 区分载入中、失败、没有记录和未登录，右侧跟随选中日期 |
| 日历与笔记窗口的比例、间距不统一 | 两个记录窗口切换 | 统一纸面、边线、控件尺寸和标题层级，保留各自内容结构 |
| 小屏日历底部可能被裁切 | 独立审阅在 320 × 568 复现 | 修正关闭按钮的旧定位规则，重新检查滚到底的内容边界 |
| 笔记逐书载入，书多时等待很长 | 约 03:00，仍显示 97/112 | 改为按批读取个人记录，避开书籍正文、译文与简介的额外读取 |
| 加载进度更新时重建整张记录列表 | 代码复现 | 复用未改变的记录行，保留来源链接焦点和展开的引文 |
| 笔记加载中重开可能发起重复请求 | 回归测试复现 | 同账号、同一批加载复用未完成任务，切换账号立即失效 |
| 笔记滚动后标题与关闭按钮离开视野 | 约 03:00–03:20 | 固定标题、筛选和关闭区域，让记录列表独立滚动 |
| 双语长段落对应关系不易辨认 | 03:30–04:33 | 用译文侧线帮助定位，保留原段落边界；手机仍逐段上下排列 |
| 笔记分页重载可能清掉选定的书籍筛选 | 本轮实现后的独立审阅发现 | 保留当前账号已知的书籍选项，重开和重试仍限定原来选择的书，导出范围也保持一致 |

批量读取每页最多处理 12 本书，服务端同时读取最多 3 份记录。112 本书的隔离验收使用 10 次分页请求。这个数字说明请求数量减少，不代表所有网络环境下的实际等待时间。归档书也参与读取。超大记录通过原有入口完整读取，失败仍会提示重试。

## 保留的边界

视频中的部分书名看起来像测试文件。这些属于账号里的真实数据，本次没有改名、删除或隐藏。浏览器调试条与扩展按钮也不归入产品缺陷。右上角悬浮角色的归属，仅凭录屏不能确认。

中英文长度不同，会使同段对照出现留白。为了保持来源锚点，本次没有重新切分作者段落。中文试读结束的位置继续明确提示，后文保留原文。没有用新译文填满页面，也没有发起全书翻译。

## 验证范围

已检查简体中文、繁体中文、英文、日文，以及 320、390、768、1440 像素宽度。笔记与日历另外检查了短窗口、固定控件和滚动边界。书架与搜索使用真实公版目录，个人记录使用临时隔离样本。

完整路径覆盖笔记载入、搜索筛选、引文展开、导出、返回原文、刷新和日历关闭。程序检查、独立审阅、合并及线上验收的最终结果见本次验收记录。

这些结果来自 Chromium 浏览器与自动化检查。没有把它们当作真实读者研究，也没有完成实体 iPhone、Safari 或屏幕阅读器语音验收。
