# GET-209 PDF 路径评估执行计划

**Goal:** 核对直接 OCR 的收益与代价，交付可复核的离线证据及真实 A/B 方案。

**Architecture:** 保持产品运行代码不变。工具只生成三份各一页的合成 PDF，调用既有原生检查与导入编排；内存中的假供应商与捕获式书房出口不访问网络或真实书房。真实 OCR 缺少账号免费额度与费用上限证据时保留阻塞。

**Tech Stack:** Node.js 22；锁文件中的 pdf-lib 1.17.1、pdfjs-dist 6.4.299、@napi-rs/canvas 1.0.11；现有 PaddleOCR SDK 0.2.3 的接口审计。

**Spec:** [GET-209](https://linear.app/getyak/issue/GET-209) 及本轮有界执行授权。

## Global Constraints

- 仅 GET-209 隔离工作区；不改默认 `auto`，不重解析已有书籍。
- 不读取私人原件、凭据或 Token Plan Key；不调用模型/OCR API、安装大型模型或开启付费服务。
- 真实对照至多三种版面、每份两页、每路径一次、总识别不超过十二页；没有费用凭据不得开始。
- 正式证据进入公开仓库；合成 PDF、依赖和临时日志使用登记产物目录。
- 独立原生 sub-agent review；PR 当前 head 的 CI 与合并读回；核心真实对照未完成时 Linear 保持未完成。

## Review Focus

1. 假供应商输出或本地耗时不能被当成真实 OCR 质量/性能。
2. 两条路径需使用相同字节、各自独立存储，避免去重把第二条实验吞掉。
3. 双栏与脚注的预期顺序独立声明，原生检查通过不等于顺序正确。
4. 工具没有真实供应商开关、输入私人文件入口或产品书房出口。
5. 同一原件的重新导入不等于有版本化 OCR 比较；段落 ID 不能跨重识别推断稳定。
