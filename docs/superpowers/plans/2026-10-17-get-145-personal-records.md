# GET-145 · 自己的评论与可继续的问题

## 已复现的缺口

真实隔离领域服务可创建并在重新打开后读回评论；同 ID 更换文字返回 409，旧原话完整保留。没有独立编辑操作、修改时间或记录 revision。网页 recordNode 只显示创建日期；我的记录跳转直接使用 p.section，来源段落不存在时会报错。现有问题、用户/AI 归属、创建草稿、导出、阅读器锚点已有实现，不重新搭建。

复现收据保存在本聊天 `issues/GET-145/current-behavior.json`，使用登记临时目录、纯合成书和账号，模型调用 0。

## 目标、边界与方案

读者能修改自己的评论/未解决问题，保留原话、归属、创建/修改时间及稳定来源；另一处陈旧编辑不能覆盖较新的文字。刷新、重启、译法变更和备份恢复后仍可继续阅读/查看自己的记录。

比较三种方案：把原创建接口改成覆盖写会破坏创建重试的幂等保证；建立通用 CRUD/新数据库/重做对话超出当前缺口；在现有服务上增加独立、带版本检查的编辑操作，能保留既有架构及访问边界，因此选择第三种。

1. 保持创建接口行为，增加 `POST /api/library/books/:bookId/(comments|questions)/:recordId/edit`，本机兼容入口使用相同操作。输入只接受 `text`、`contentVersion`、`baseRevision`、`editId`。服务端验证登录/owner、书、记录、原文版本、字段及 2,000 字限制，保持 ID、bookId、passageId、contentVersion、quote、origin、createdAt 和问题 status 不变。
2. 新建记录带服务端 `updatedAt` 和 `revision: 0`；旧记录缺少编辑元数据时按 revision 0、创建时间读取。成功编辑 revision 加一并记录服务端 updatedAt、lastEditId。相同 editId/baseRevision/text 的确认重试返回原结果；同 ID 不同请求或陈旧 revision 返回 409，不能静默覆盖。MAX_SAFE_INTEGER/非法时间等拒绝。
3. 这些是兼容的可选记录元数据；保留现有 records schema 与整书备份格式，新增字段的严格校验。不重解释或自动重写旧原话；完整备份保留新字段，干净实例恢复验证，重复导入仍不覆盖已有记录。破坏性格式/数据迁移不在本范围。
4. 正文、编辑注解、AI 回答、用户原话分开呈现。记录增加自己的归属和创建/修改时间、修改/保存/取消入口。文本继续用 textContent；引用和来源不因编辑改写。编辑复用既有 durable draft 引擎，按 owner/book/contentVersion/记录分离 scope，不与新建想法草稿冲突；失败、模式变化、关闭再开、刷新保留编辑文字/冻结请求。明确提示未保存修改仅在本机，导出前先保存修改；不把这种本机草稿冒充云端已保存或现有书房备份已包含。
5. 409 后保留草稿，允许明确读取较新原话/版本，用户核对后再次保存才创建新编辑请求；不自动把旧草稿重发到新 revision。成功应答必须匹配当前冻结请求，更新前端记录时按 revision 合并，迟到的旧读取不能覆盖已确认的新编辑。
6. 来源版本/书籍/段落不匹配时保留文字和引用，明确显示“原文位置待确认”，停用猜测跳转/编辑。正常“我的记录”返回正确书、段落及问题入口。更新译文不改变个人记录，不自动宣称问题已解决。

非目标：生成真实模型/语音、重建已有 AI 对话、自动重定位旧来源、删除用户记录、推广旧草稿到新书/新账号、重做 MCP 授权、批量搬迁真实账号数据。
