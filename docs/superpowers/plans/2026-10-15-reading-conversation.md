# 阅读对话浮窗实施

用户已确认 2026-10-15 的第二版交互设计，并要求实现 Agent 与独立审阅 Agent 协作交付。范围是现有阅读对话的呈现和入口，不重写对话领域服务。

## 已确认的界面

右下角松鼠入口，默认收起。桌面展开约 420px 宽、590px 高的非模态浮窗，正文和书架仍可操作。手机适应可见窗口和键盘，保留显式收起按钮。打开、收起不发送模型请求；收起不取消已提交的任务。

聊天框使用白色或对应暗色面板、22px 圆角、极细边框与柔和分层阴影。标题为小号「阅读对话」，书名位于下一行。正文使用平台无衬线字体，约 15px、1.9 行高；用户问题用轻灰气泡，AI 回答直接排在白底上，明确保留 AI 归属。字号、边框和颜色须在纸面、暗色和移动端保持可读。

上下文位于输入框上方，收为一行，可展开核对原文、独立直译与意译及草稿状态。每条回答保留真实引用与回到原文入口。输入区为柔和底色的整体，发送为小圆按钮；保留输入法保护、停止、重试、字数限制和真实错误状态。导出放进轻量的更多菜单。没有真实问题时不显示伪造的对话。

设计依据为当前聊天服务和已确认的交互稿。最终实现须融入现有站点主题和书页，不把演示固定回复或样例问答带入应用。

## Task 1: 浮窗、角色与真实聊天界面

负责范围：`app/library-chat.mjs`、`app/library-chat.css`，可新增单一职责的 `app/chat-launcher.mjs` 与对应测试。不要修改 server、reader、portal、home、发布清单或其他工作区。协调者负责这些接入点。

保留现有 `mountLibraryChat` 参数和返回接口，并新增可选参数 `getCurrentPassage=()=>null`、`onNavigateToPassage=null`。前者返回当前段落 ID；仅在打开时且没有草稿、运行任务或不确定重试时采用当前段落，输入期间不悄悄改变讨论对象。后者为 `(bookId,passageId)=>boolean`，返回 true 表示宿主已在当前阅读页定位，组件应阻止链接导航并收起；否则使用真实阅读链接。

组件自行创建唯一右下角 launcher，默认挂在 dialog 相邻的页面末尾。保留旧侧栏按钮作为兼容绑定，但设为 hidden，避免重复入口。`root` 仍为原生 dialog：桌面使用非模态 `show()`，不锁正文、不创建背景遮罩。移动端如继续采用非模态浮层，必须保证遮挡范围、触摸滚动与输入键盘可用。ESC 只在对话内部或入口有焦点时收起，不抢其他 dialog。打开/收起时正确回焦。真实模态登录或设置打开时 launcher 不越过浏览器顶层覆盖它。

保留账号和书籍隔离、幂等请求、持久草稿、取消和不确定请求恢复。关闭停止前端轮询但不取消后端；重新打开按原请求 ID 恢复。不要为了收起标记完成，不为轻提示增加长驻后台轮询。输入更新不重建消息 DOM、不重建书籍选择器、不打断选择、输入法或消息滚动；阅读历史顶部时新回答不把读者强拉到底部。初次打开手机不应强制唤起键盘。

角色用简单、可维护的本地矢量/CSS 图形；松鼠耳朵、眼睛和卷尾可辨，主体不抢阅读。静止为默认，只响应用户操作和真实等待状态，遵循减少动态效果设置。无新运行时依赖、外部字体、第三方脚本或假状态。所有图标按钮有明确名称与键盘焦点，触屏点击区域足够大。提供卸载接口仅在有真实宿主需要时添加，避免无关扩展。

先写有意义的行为回归检查，验证非模态开合、草稿保留、账号切换后清理、IME 期间不发送、运行中收起恢复；沿用现有状态与 HTTP 测试。CSS 不写镜像式断言。自查当前文件差异与聚焦测试，再交给协调者做浏览器验收。不要提交或推送；协调者统一提交完整任务。

## Task 2: 接入与验收（协调者）

将同一组件接入真实阅读页，带入当前书与当前段，引用在本页定位；书房继续通过现有真实账号与书目使用。更新资产路由和发布清单，保留其他聊天尚未完成的修改。阅读页内选中文字、点击词语和输入聊天不会误触段落切换。

在隔离测试数据中跑真实浏览器交互，覆盖桌面与窄屏、暗色、缩放、开合、已有历史、空状态、缺模型配置、引用和键盘。持久联调资源若需要保存，必须归入 `test@cubxxw.com` 的真实账号；单元测试使用临时隔离数据。不得为 UI 验收发起未授权的付费模型调用。

## Task 3: 独立审阅与交付

独立 Agent 只读审阅任务完整差异、测试证据、账号边界及浏览器证据。修复重要问题后复核。执行相关测试、完整测试、构建与发布检查。只提交本任务文件，在公开仓库创建 PR、等待检查后正常合并，核对远程与已有发布流程。明确区分已实现、已合并、已发布和已实测。
