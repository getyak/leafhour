## 聚焦视觉修订

用户问题气泡改为随实际文字收缩、右对齐，最大宽度 87%，长文字继续换行。手机面板从可见窗口底部及安全区计算位置，键盘收起时紧邻右下角入口上方；键盘缩小时继续按 VisualViewport 的高度与偏移约束顶部和高度。输入区底部只保留 12–15px 留白，原上下文说明以 aria-describedby 保留给辅助技术，并放入更多菜单供查看；真实运行状态及错误提示继续可见。

本次新增上下文说明可访问性回归。聚焦 UI 与状态检查合计 36 / 36 通过；未修改接口或宿主接入。

## 短键盘窗口修正

独立审阅指出可见高度约 300px 时，固定区块总高度可能超过面板并裁掉发送区。现按实际 VisualViewport 高度（不依赖屏幕宽度）在不超过 500px 时启用紧凑布局：面板限制在可见窗口内，整个内层滚动，标题及收起按钮吸附顶部；消息不再使用独立受限滚动区，展开原文限制为 100px 可滚动区域。输入与发送可通过整层滚动到达，横屏宽度超过 600px 同样生效。

新增可见窗口缩小、偏移、恢复的事件回归，验证样式变量和紧凑模式随真实事件切换，且不发模型请求。UI 与状态检查 37 / 37 通过。此测试验证事件接线；实际 300px 高度下的滚动可达性由协调者浏览器验收。

## 宿主样式与阅读工具避让

真实浏览器检查发现书房 `dialog:not(.auth-dialog)` 规则覆盖了聊天面板颜色。使用限定非模态聊天 dialog 的更高优先级规则明确背景、文字和边框，同时保护输入框及书目文字色；不改变尺寸与紧凑窗口规则。阅读页全局 dialog 规则也已检查，其优先级低于组件规则。

当阅读页存在聊天入口时，阅读工具按钮移至松鼠左侧，保持 12px 间距并兼顾安全区；工具展开面板向右补偿 60px，继续贴近视口边缘并限制可用宽度。改动仅在聊天样式文件；实际颜色与几何由协调者浏览器复验，不增加 CSS 镜像测试。

紧凑窗口实测发现 `overflow:hidden` 的外层 dialog 仍能被浏览器焦点行为程序化滚动，导致吸附标题移出视口。紧凑模式外层改为 `overflow:clip`，只保留内层 frame 滚动容器；尺寸和内层滚动规则不变。协调者继续复验输入聚焦后的收起按钮和发送区几何。

协调者复验 `overflow:clip` 后，390×300 窗口外层滚动为 0，标题顶边 9px、发送按钮位于 237–269px，可正常到达。发现松鼠入口与发送按钮重叠后，追加仅在紧凑模式且浮窗展开时隐藏相邻入口的规则；收起后入口自动恢复，普通桌面入口不受影响。
