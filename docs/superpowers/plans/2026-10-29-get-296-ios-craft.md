# GET-296 iOS reading craft

Goal: make native reading preferences understandable before the reader dismisses the sheet. Work is authorized through 2026-10-30 12:00 Asia/Shanghai; this document does not prove that a scheduler was installed.

Architecture: retain the existing SwiftUI Form, ReaderSession preference binding, UIKit reader and device-local persistence. Use the current chapter's first non-heading text as a local preview, with the reader's existing serif sizing and spacing. No new data format, service or model call.

Tech stack: SwiftUI/UIKit, iOS 17+, existing LeafhourCore.

## Decisions

A full reader redesign would overlap GET-276 and the existing quiet-reader work. A preview alone would leave unusable PDF controls and ambiguous numeric values. The chosen small batch adds a live current-book preview, explicit pt units and accessibility values, a typography-only reset, and accurate fixed-page PDF guidance. It retains the theme and reading position. This is the agent's implementation choice under the user's explicit autonomous optimization request.

## Review focus

Current-book preview must remain on device and retain author text; no invented translation. Very long paragraphs must not create an unbounded preview layout. Reset must not erase theme, notes or reading anchor. PDF must not show typography sliders that do nothing. System and explicit themes, Dynamic Type, narrow sheets and return paths need separate evidence.
