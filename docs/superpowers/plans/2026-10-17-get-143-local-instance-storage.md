# GET-143 · 本机实例目录与持久化交付

原 issue：[GET-143](https://linear.app/getyak/issue/GET-143/建立本地阅读服务与稳定内容个人记录存储)。开始基线：`1ca9bcc0e9214cf60abf2f5b8d8e64411424f76c`。以下设计和验收表在实现前固定。

## 当前行为与目标

领域服务已经实现本机 JSON 存储、书房身份、稳定书/章/段落 ID、来源版本、幂等导入、个人记录和按书授权。`createReaderServer` 接受 `recordsPath`，其父目录又决定个人书库、会话、对话和音频目录；但标准 `npm start` 没有把实例目录配置传进去，因此数据默认随源码位于 `local/service/`。换检出目录或运行多个独立实例时，标准入口没有清楚的数据归属选择。

目标是让标准启动命令选择稳定实例目录，并用真实进程与 HTTP 验证原任务的持久化和安全契约。界面、OCR、真实模型生成和数据库迁移不属于本次修改。PR #62 的 PDF OCR 已合并；本任务已安全同步其最新 main 基线 `62d89cfc9a4119c62d00384b8f9d76e573c30109`，只改启动入口底部、安装元数据、实例说明与独立测试，保留其工作。

## 方案选择

1. 重写为旧 issue 提议的 TypeScript/SQLite：不选。当前 `_briefs/private-library-architecture.md` 已明确这两项是后续候选，现行 Node/JSON 服务及托管适配已上线；此次无迁移需求。
2. 让用户自写 Node 包装脚本传 `recordsPath`：不选。能绕过问题，却让标准运行说明和实际入口继续分离。
3. 增加可选的 `READER_DATA_DIR`：选用。按现有 `READER_BOOK_PATH` 的方式解析路径，将根目录下的 `records.json` 交给现有构造函数，复用其派生路径。未配置或空值继续使用原默认路径；不自动移动既有数据，不切换托管存储，不从 HTTP 接收文件路径。

绝对路径可跨源码更新复用；相对路径按启动工作目录解析，含空格的路径须按 shell 或 `.env` 规则引用。实例目录是私人状态；阅读包仍由 `READER_BOOK_PATH` 指向只读来源，密钥仍在现有受保护配置中。一个本机数据目录同时只运行一个服务进程；多实例使用不同目录和端口，本次不引入多进程数据库锁或跨机器同步。

内容按现有契约分别保留原文、译文版本、编辑注解、用户记录及 AI 对话字段/文档，不为实现“分开”而迁移已存在的 JSON 格式。用户原话不能被 AI 字段覆盖，来源和个人记录仍在不同持久化文档。任何校验失败都不能清空已有书籍或记录。

## 执行与证据

安装阶段新增定位：npm 12 在默认 registry 为 npmjs 时拒绝锁文件中的 npmmirror tarball（`EALLOWREMOTE`），并非 SDK 声明了 URL 依赖。锁文件有 743 个镜像解析地址，版本、依赖图及 integrity 已锁定。首个仅映射旧镜像的 `.npmrc` 方案通过默认 npmjs 安装，但独立 reviewer 发现配置镜像 registry 时仍有混合主机回归。按 npm 官方 [allow-remote](https://docs.npmjs.com/cli/v12/using-npm/config/#allow-remote) 与 [replace-registry-host](https://docs.npmjs.com/cli/v12/using-npm/config/#replace-registry-host) 契约，最终只将锁文件的 743 个旧镜像 resolved 地址规范化为官方默认主机，移除该 `.npmrc`；由 npm 原生规则继续映射用户配置的 registry。机械比较确认所有非 resolved 字段完全一致，保留远程 URL 拒绝策略与全部 SRI，不重算依赖图或升级依赖。S1–S8 标准保持不变。

- 先写真实启动失败回归，再将实例路径接入标准 CLI；随后补齐重启、幂等、错误恢复和边界验证。生产行为变更应当使测试失败，不使用源码字符串断言或模拟 HTTP 服务。
- 使用现有 `node:test`，模型/SMTP 凭据从子进程环境移除，工作目录内无 `.env`。Node [Permission Model](https://nodejs.org/docs/latest-v22.x/api/permissions.html) 仅作为可信测试代码的误写保护，不能视作恶意代码沙箱；只允许子进程写入注册的合成测试目录。
- 测试前运行存储 audit，重型任务前检查 resources。当前内存压力较高，不在本机并行启动完整构建；使用一个串行进程测试组，完整套件及发布构建由当前提交 CI 执行。不启动 Simulator，不触碰真实书房或模型服务。
- 正式验收记录写入 `docs/verification/` 与本任务永久证据目录；临时依赖、合成数据库和子进程在证据保存后逐项清理。没有 UI 变化时不重复截图，也不以本机服务夹具冒充托管数据库或真人阅读验收。
