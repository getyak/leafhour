# GET-152 scoped MCP reading: design and frozen acceptance

Base: b5e9455650edc48e27925736d06bf8f00a264b66, getyak/leafhour. Issue GET-152. Existing user authority covers implementation, independent review, PR/current-head CI, normal merge and existing production acceptance. No automatic brainstorming approval gate applies.

## Current behavior and outcome

An actual official SDK stdio preflight reproduces the absent chapter resource and missing manifest source metadata. A single synthetic Unicode paragraph makes reader_get_chapter return 118783 JSON bytes. Existing per-book grants already gate content, notes, activity and explicit comment writes. Generated hosted configuration pins an older immutable commit fb6141fc, which would omit new MCP functionality. Evidence: private current-behavior.json; no model requests.

Outcome: a host can read only the selected book/data types, follow stable versioned citations, and page complete authorized text without oversized responses. The browser and MCP continue using the same domain records. Knowing a URI, embedding instructions in source, or presenting a different account/book ID cannot widen a grant.

## Selected design and tradeoffs

1. Keep stdio and the installed @modelcontextprotocol/sdk1.32.1/zod4 line. Official v1 maintenance documentation implements through protocol2025-11-25 and remains maintained; report the actually negotiated version. Do not mix in v2 APIs or claim2026-07-28 compatibility without testing.
2. Add a focused bounded read projection/paging module for manifest/context/chapter/passage/search/notes/activity, used by the Agent HTTP routes. Permission/owner resolution remains in the existing library authorization boundary before any book lookup. Audio and explicit comment:write behavior stay intact. No authority may come from record text, resource query parameters, model output or resource annotations.
3. Provide real manifest/chapter/passage resource templates with optional paging/version fields. Existing tool names and offset/nextOffset remain available; add explicit lossless continuation for oversized original/literal/interpretive layers. Every returned passage carries stable ID/chapter/contentVersion, distinct missing/draft/reviewed translation status and source locators. Cursor continuation is version-fenced, measured in Unicode code points and makes progress without dropping/duplicating characters. Citation URLs identify the same book/passage/version/layer; relative reader links resolve on the configured service. Original/editorial content remains separate from private comments.
4. Canonical JSON data <=24576 UTF-8 bytes; encoded MCP tool/resource result <=98304 bytes (JSON text plus structured data can duplicate/escape payload). At most20 passages/records per page. Metadata uses an explicit bounded projection; do not dump raw correction history, private record snapshots, credentials or arbitrary stored book keys. Oversized text uses continuation; intentionally omitted optional metadata must be indicated, not silently advertised as complete. Manifest/chapter metadata and search/notes/activity use explicit pagination and byte limits. Input IDs/ranges/version/cursors and resource URI queries are validated; malformed or stale continuation fails clearly without reading a different book.
5. Content grants alone reveal no saved position, notes or activity. Notes and activity still require their own existing scopes, and read-only grants reject comment writing. Recheck grants on every resource/tool request; revoke immediately blocks subsequent access. No new grant, share, delete, backup, schedule, model, speech or implicit write tool is introduced. Historical AI conversation is not newly exposed by this issue; existing notes output remains comments/questions, each with explicit origin and stable source association.
6. Hosted setup returns validated deployed source provenance and generated configuration pins that exact immutable commit. Avoid another hardcoded new commit, mutable main or an old-version fallback. Preserve local absolute executable/argument paths and explicit remote opt-in; missing/invalid provenance yields an actionable error. Use runtime Vercel source metadata / verified release provenance according to the existing deployment path and test the actual production setup result.
7. Exercise a genuine official MCP Inspector GUI host against an authorized test fixture, including grant/read/revoke and opening the returned citation location. Report Inspector/SDK/protocol versions and exactly what host was tested; do not portray an SDK-only script or Inspector as a user's already-configured Personal Agent. Test default test@cubxxw.com ownership in production, isolate/revoke task grants and cleanup only owned fixtures. Source books, account credentials and grant values stay outside Git/log output. Inspector gets a temporary registered profile/cache and loopback-only access; no paid models are required.

Rejected alternatives: add only a chapter template (leaves size/provenance failures); return an entire chapter then slice in the MCP adapter (does not bound HTTP/domain output or all clients); reuse free-reading Agent tools directly (different authority and source/notes contract); silently truncate paragraphs (loses source/citation correctness); automatically upgrade the entire SDK major (unnecessary migration scope).
