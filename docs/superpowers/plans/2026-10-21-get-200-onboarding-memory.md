# GET-200：对话引导与阅读偏好

执行：当前 Codex worker 直接实施；独立原生 sub-agent 审查。仅本工单，不调用模型供应商进行验收。

1. 复用账户 `reading-preferences.json` 的原子 CAS（托管时为现有数据库文档行），增加有界 memory 元数据、来源记录、候选偏好与引导事件。主题单独存储；阅读方式与纸面直接使用既有快照。先验证隔离、并发、候选不生效、确认/删除和备份恢复。
2. 在聊天中先展示真实可读书目，再依次询问主题、语言/译文显示、纸面。每题 3–5 个选项，单题跳过与整体跳过均可持久保存。两种固定顺序按账户分配，开始/回答/跳过/完成事件含顺序，可计算完成率与跳过率。
3. 设置的“我的阅读偏好”独立展示主题、候选与来源，支持直接修改、确认和删除。明确选择立即更新首页筛选与新书默认值，保留每本书自己的选择。
4. 阅读 Agent 增加 `get_preferences`、`update_preference`、`delete_preference`。推测只保存候选；有效偏好增删需当前轮次的用户授权，注解/陪读无此写权限。工具不能传入用户身份或自授权限。
5. 完成相关测试、全套测试/构建、真实文案检查和浏览器验收；独立审查后创建关联 PR、等待当前提交 CI、正常合并，检查同提交生产发布与行为，最后更新 GET-200。

审查重点：账号切换与迟到响应、未知字段/越界输入、候选未确认前无副作用、并发与重复请求、引导失败不能误报完成、导出不包含凭据。

研究依据：StoryGraph 的偏好可从推荐与资料页重新编辑；Readwise Reader 在资料库内放入入门内容，先提供可读价值。其余竞品的当前引导流程如无一手证据则不作已验证声明。
