# GET-327：阅读性能与可靠性优化

关联：https://linear.app/getyak/issue/GET-327

用户要求深入分析并并行优化 Leafhour，包括 Web。当前会话最多同时运行主 Agent 与三个子 Agent；采用按模块划分的并行审查与实现，统一排队执行浏览器、Swift 与完整构建，避免共享主机的交换内存压力放大总耗时。基线为公开仓库 `getyak/leafhour` 的 `d64cfd8`。

## 方案与边界

保留现有 Node、原生浏览器模块与 SwiftUI 架构，修复有触发路径和回归证据的问题。全站重写需要重新验证既有数据和阅读交互；只写分析报告无法完成用户要求的优化。本轮采用现有模块内的有限修复，并记录尚未验证的范围。

不调用收费模型、不生成翻译、不修改真实账号书籍与记录，不创建 PR 预览或新的发布入口。账号隔离、稳定段落 ID、两种译文和旧存储标识保持兼容。

## 并行任务

1. Web 性能：`app/book-upload-controller.mjs` 仅在任务能自动推进且页面可见时轮询，回前台刷新；`app/palette-book.mjs` 按需截取 grapheme 摘要；`app/reader-api.mjs` 将取消信号传给全部正文分片。对应测试覆盖等待人工处理、前后台、恢复操作、Unicode 和中途取消。
2. Web 交互：审查选文、高亮、对话框和焦点；优先处理慢保存完成后覆盖用户新选文或抢回焦点的问题，文件归属确认后实施。
3. iOS 同步：`CloudBookSync.swift` 合并运行期间的新同步请求并在旧快照完成后处理，保持同书串行；云端回读在身份与原文可核对时保留本机精确笔记锚点。Core 测试覆盖并发 push/pull、冲突解决顺序、Unicode 与错配引用。
4. 主 Agent 负责复核根因、基线、集成验证、独立交叉审阅、PR/CI/合并和正式发布读回。

## 验证与审阅重点

- 先取得失败回归，再修改行为；性能优先用确定性工作量断言，计时仅记录为本机观察。
- 上传任务等待同意、失败和待复核时不得持续请求；后台停止轮询，前台恢复，显式操作不被旧请求覆盖。
- 搜索摘要不拆开 emoji/组合字，取消正文请求后不得继续下载后续分片。
- 高亮保存回执不得覆盖后续选文或把读者拉回旧位置；持久化成功仍保留。
- 同步队列不得丢新保存、无限重试或并发覆盖元数据；云端缺偏移时不能破坏可核对的本机锚点。
- 完整宿主测试与 Web 构建、真实浏览器隔离数据测试；原生通过 `dev-ios-session run` 使用既有设备池验证。
- 独立 Agent 审阅所有最终代码，修复确认的严重问题；同步最新主分支，最新提交适用 CI 通过后正常合并。
- 合并、正式发布和线上验收分别读回；TestFlight 与真机未测试就明确保留边界。

## 已取得的基线

62 项选文、阅读对话、阅读工作区和书房宿主测试通过；Web 构建通过。更完整结果在交付记录中补充。
