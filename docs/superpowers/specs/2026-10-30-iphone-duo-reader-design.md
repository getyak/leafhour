# Leafhour iPhone Duo 阅读页设计

日期：2026-10-30。范围：可交互设计稿与布局、状态、验收契约。正式应用尚未实现本设计。

用户要求先出设计，随后明确要求正文减少干扰、专注内容，并继续细化审美。本版默认打开为单栏静读，原译文对照与笔记均按需打开。iOS 原生阅读页为首期对象，网页保留相同阅读意图并按浏览器可用能力适配。

## 体验目标

合上时，读者能单手继续读；展开后，可以把正在使用的译文、笔记或陪读放在正文旁边。设备改变形状时，书、位置、语言、译法、笔记草稿和对话仍属于同一次阅读。

正文沿用纸面、衬线字体、墨绿交互。阅读文本直接排在纸面上，辅助内容有明确归属。目录和设置短暂出现，阅读区最多同时呈现正文与一个辅助区。

安静页面只显示章名、一行章节与内容状态以及正文，页角保留一个有 44pt 触控区域的阅读工具入口。译文草稿显示为「第一节　中文意译草稿」，明确区别作者原文；切为原文时仅显示章节。没有常驻品牌字标、假时钟、整排功能栏、默认段落高亮和「回到当前段」按钮。菜单入口使用省略号并有「阅读工具」可访问名称；首次打开不自动弹出教程。

审美依靠字面、行长与段落节奏。普通单栏起始字号 21pt、行高 1.95、正文最大宽约 420pt；中文首段顶格，后续段落缩进两字，英文保留自然左对齐。字号随用户偏好增长，不能为并排而调小字号。预览用纸面 `#faf8f2`、墨色 `#32362e`、次级文字 `#68715e`、墨绿 `#3d6048`，均有深色对应；这些是本稿的视觉值，不替代原生动态系统色与可访问性验收。

旁页与正文共享纸面，不包在大色块里；内容的角色通过「我的笔记」「AI 陪读」「原文摘录」与留白区分。保存操作保持轻量，未保存／失败状态仍要明确。对照模式只在栏头显示原文与当前译法、草稿状态，缺译文在对应位置就地说明。

展开本身不打开辅助内容，不改变语言或阅读目标，不开始翻译、对话或听读。既有松鼠陪读开关和有界触发契约继续有效，折叠事件不增加触发次数或上下文范围。

## 方案取舍

| 方案 | 优点 | 成本与适用范围 |
| --- | --- | --- |
| 连续双页正文 | 适合长篇沉浸阅读，书本式姿态自然 | 需要真实双页分页、跨页选择与章节边界处理；列入后续 |
| 原文与译文并排 | 与 Leafhour 的语言学习和精读直接相关 | 需按稳定段落 ID 对齐，处理长短差异与缺译文 |
| 正文＋按需旁页 | 可以接续现有翻译、笔记和陪读工具 | 需把工具数据与弹层生命周期分开；作为本设计基础 |

推荐后两者共用一套呈现与状态管理。首期保留原生已有的滚动／翻页选择，不把对照阅读变成两套独立进度，也不重新实现整套阅读器。

## 形态与布局

设计稿中的外框与中缝表达布局关系，不是 Apple 的精确硬件尺寸、相机位置或折痕测量。

1. **展开静读／随手单页**：优先展示当前主要语言，展开也不自动出现第二栏。窄屏打开辅助内容时切为独立工具页，固定引用当前选文；显式关闭后恢复正文。原生可用等价的系统呈现承载这一独立工具页，不把工具接到长章末尾。页角保留一个紧凑入口，尊重系统安全区域。原文、译文、笔记与陪读在窄屏仍可访问。
2. **展开对照**：原文和选定译文分别成栏。直译／意译明确显示，按相同段落 ID 配对。允许段落内容长短不同，共享一个语义阅读位置。
3. **笔记旁页**：正文在一侧，用户主动打开的笔记在另一侧。笔记引用固定到选文锚点；正文继续移动时不悄悄更换笔记对象。对话遵循相同规则，需要用户主动选择「使用当前段落」才更新引用。
4. **桌面半折**：系统报告横向分隔且空间足够时，正文在上、正在使用的辅助区在下。无辅助区时正文放入一个完整可读区域，保留空白；不擅自开启笔记或听读。布局的功能与层级保持一致。

竖向折痕存在时，两栏分别落入系统报告的可用区域，并为曲面保留内边距。单栏阅读在书本式半折时放入一个完整区域，提供轻量的「换侧」操作；不会把一行正文横跨折痕。具体默认侧由系统布局方向与用户最近选择决定。完全展开后可回到舒适的居中单栏。

系统分屏、大字号和键盘可能使双栏不可用。此时保留阅读意图，辅助区改为独立紧凑工具页；不能通过缩小用户选择的字号硬塞双栏。「双栏不可用」与「是否存在折痕」分别判断：大字号单栏及其工具页仍位于一个完整区域，换侧操作继续可用。并排条件由当前窗口、尺寸类别、可用区域和内容最小可读宽度共同决定，不按机型名或物理屏幕宽度判断。内侧避让来自系统区域，不写死中缝宽度或角度阈值。预览在窄窗口不绘制整块折叠屏的中缝，仅示意当前单侧可读区域；真实折痕状态仍需系统 API 验证。

## 页面与操作

正文上方显示章名与章节定位。完整书目信息、版本状态、目录、正文语言／译法、字号、对照、笔记与陪读集中在阅读工具里。菜单显式打开，不常驻遮住文字；菜单出现和收起不参与正文排版。点菜单外、按 Escape 或选择「继续阅读」可收起，关闭后焦点回到入口。正式原生界面返回书房仍有可访问的标准导航操作，不绑定隐藏手势。

旁页只显示正在使用的一项内容与显式关闭按钮，其他工具通过统一菜单切换。关闭后继续同一段阅读。目录、搜索和外观设置为临时呈现，不增加第三个常驻栏。选择文字和点击链接不打开工具菜单；工具入口的触控区域始终独立于正文。VoiceOver、选文与编辑期间保留必要操作。

文本可正常选择、复制。点选文字、链接、术语、引用或选文菜单不翻页、不切换整段。对照中的辅助定位使用独立按钮。切换直译和意译只更换已有的对应内容；缺少该版本时显示「尚无译文」，保留原文，不从另一个版本复制补齐。导入 PDF 首期保留 PDFKit 原页与页内锚点，辅助区只对已有可信选文工作；不把扫描 PDF 当作已可重排双语文本。

「对照」是整章阅读模式，按段落配对，共享一个滚动／翻页容器和主要进度。主要语言由读者选择，与物理左右位置无关：以中文为主的读者读到右栏新段落时，同一来源段落锚点随之更新，合上后接着该段中文。译文中的精细位置需要带译文版本与译文偏移，并映射到来源段落；不能把中文字符偏移当作原文字符偏移。缺少可靠的句内映射时，回到同一来源段落的可读开头，并明确不承诺逐字等位。

「译文」工具则固定当前选文的翻译，可独立滚动，不推进主要阅读进度。它与笔记、陪读属于同一个辅助区，默认固定引用；提供「使用当前段落」的显式操作，正在写笔记或生成回答时锁定本次引用。整章对照期间打开笔记或陪读，暂时以主要语言显示正文；关闭工具后恢复对照。紧凑空间保留对照意图，通过原文／译文切换核对同一段，宽度恢复后回到并排。

## 会话与切换契约

阅读会话负责内容、主要阅读锚点、阅读意图、用户记录和请求；布局负责区域和呈现方式。弹层变旁页时移动呈现，不新建一个有独立进度的阅读会话。

必须保留的状态：

- 账号、书籍和来源版本；章节／段落 ID 与来源字符偏移；PDF 原页内坐标。
- 主要语言、选定译法、滚动／翻页偏好、字号和主题。
- 辅助区类型、引用对象和辅助阅读位置；笔记 ID、草稿及保存失败状态。
- 当前书的对话、正在生成的请求 ID、取消状态及输入框草稿。
- 当前有效阅读计时所有者。两栏不产生两份时长；后台或被辅助弹层完全遮挡时按已有前台可见口径暂停。

宽度、区域或字体发生变化前，捕获主要语义锚点；完成排版后恢复同一来源字符附近的可读行，并验证它没有被工具栏、键盘或折痕遮挡。旧布局回调携带布局代次，不能覆盖更新后的定位。跨来源版本不复用字符偏移。

折叠时若正在编辑，保留草稿和逻辑编辑焦点，输入区转为可用的紧凑呈现；不因设备变形提交笔记或消息。系统可能改变键盘可见性，应用不得反复强制唤起键盘。普通阅读时保持正文焦点；VoiceOver 焦点应回到等价内容或同名操作。选文可安全重建时保留来源范围；无法保留原生选区时留下明确的引用片段，不错误引用另一段。

请求运行对象归会话所有。视图重新挂载不得重发模型请求，不自动取消用户仍在等待的回答。结果回到原书、原引用；用户切书后不可误插入新书。

## 当前代码与实现边界

设计核对基线：`430cf68`（PR #272）。当前原生阅读器已包含滚动／翻页、可测量工具栏、原生选文和来源锚点恢复；这些能力应保留。主要接入点为 `ReaderScreen.swift`、`ReaderPanelPresentation.swift`、`ReaderPanels.swift`、`ReaderBottomBar.swift`、`TextReadingView.swift`、`ReaderTextPagination.swift` 与 `ReaderSession.swift`。

建议新增单一布局解析层，输入当前窗口、安全区域、系统保留区域、尺寸类别、大字号和辅助区意图，输出单栏、并排或上下排列。新系统的区域与排列接口放在可用性隔离层，旧系统沿用标准布局和弹层。最低支持系统版本是否调整不在本设计范围，默认继续 iOS 17。

当前选中的工具链是 Xcode 26.6／iOS 26.5 SDK。完整 Duo 专属体验需要合适的新工具链。后续实施时核对实际 SDK 声明与可用性，不能把原生类型名写成未经编译确认的伪代码。窗口布局优先读取当前 view/window，清理 `UIScreen.main` 的布局回退。

连续调整尺寸期间，重点测量整章 attributed text 重建、图片解码、选文和锚点恢复的成本。优先复用内容、映射和排版缓存，仅对真实变化的区域重新布局。后续验收以实际测量为准，不在本设计稿中承诺帧率。

网页复用阅读意图与稳定内容锚点。浏览器没有可用的折叠区域接口时，只承诺正常响应式布局，不声称已获得原生折痕识别或系统侧边工具栏能力。

## 设计稿内容与边界

可交互源稿：`docs/design/iphone-duo-reader.md`。六个视图为专注正文、原译对照、手边笔记、合上续读、书本半折与桌面半折，共用一段新写的虚构短文、两种示例译法和预览笔记。内容不是用户书房资料，示例译文不是正式已审阅译文。

切换形态、译法、旁页与笔记编辑仅在预览中发生。不连接书房、不提交模型请求、不保存真实阅读记录。预览中的笔记仅在当前预览生命周期保留，不保证关闭聊天后的恢复。设计稿中的视觉折痕为示意，真实避让需用系统数据验收。

## 后续正式应用的验收

1. 从段落中部在合上、展开、旋转、半折与系统分屏之间往返，同一原文位置仍可见；连续快速切换不出现旧定位覆盖新定位。
2. 选字、复制、链接、术语、跨段选文与翻页保持既有边界。中文、英文、组合字符、RTL、长译文与缺译文分别检查。
3. 编辑笔记时折叠、旋转、显示键盘、切换旁页，引用、草稿与保存失败提示仍在；重复布局不重复保存或发送。
4. 原译文长度差异、直译／意译状态、大字号与长章节不能破坏可读宽度。双栏空间不足时能操作所有入口。
5. 真实折叠区域、非对称安全区域和系统边侧工具栏不遮挡正文、选文菜单和发送按钮。PDF 分别验证页内恢复与缩放。
6. 同一阅读会话只计一次前台有效阅读；辅助浏览、后台与 Agent 访问不能新增阅读时长。
7. 新 SDK 构建、Duo 模拟器、实际设备、TestFlight 分发分别记录结果。设计稿浏览器检查不替代上述验收。
