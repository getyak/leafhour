# GET-164: choose a verified sentence by identity

The published gift flow preserves exact source attribution and rejects fragments. A real configured-model request on production f6e01b1 returned the labelled `original-excerpt` fallback. Historical production evidence had accepted the bare name “Alice” before the full-sentence guard. Neither receipt establishes successful current AI sentence selection. The provider's current raw response is unavailable; do not claim its precise failure cause.

Keep the complete-source-sentence guard, private receipt, account/book/version isolation, public attribution and explicit sealing boundary. Change only the built-in provider protocol: compute complete sentence candidates inside the existing eight-passage/12,000-character source pool, and ask the model to choose a candidate ID. The server owns identity, source text and Unicode code point offsets. A model must never compute offsets or rewrite a sentence.

Candidate construction uses the existing sentence segmentation and structural guard. Retain at most three eligible sentences per passage and at most 24 overall, in source order. Every candidate is at most 240 code points and includes its source passage/chapter internally. IDs are request-local and deterministic. Send only candidate IDs and their original texts, not notes, reading records, translations or content beyond the existing pool. No eligible sentence means no provider request. A clipped pool edge must still pass the existing full-book validation before it becomes an AI selection.

The provider response must be exactly `{candidateId:string}`. Reject unknown IDs, extra properties, prose, fences, invented text and legacy offset responses. Resolve the ID only against that request's candidates, then produce the existing internal selection shape. Preserve compatibility with injected service generators and stored gift receipts. The public schema, model, one-request limit, timeout, response-byte limit, concurrency coalescing and success-only cache remain unchanged. The output token ceiling may be reduced for this small response; never increase any budget or add retries.

For future production diagnosis, emit only a whitelisted fallback category from the hosted portal: no source text, raw provider body, URL, account/book ID, receipt, key or exception message. Categories distinguish unavailable provider, invalid response/schema, unknown candidate, source rejection and no eligible candidate. Diagnostics must not affect a successful fallback, and caller-injected diagnostic failures must be contained. Logs are evidence of a category, not proof of model quality.

Acceptance: meaningful RED then GREEN tests for selection of a later sentence, Unicode offsets and repeated text, pool clipping, candidate caps, empty input avoiding a request, invalid/unknown IDs and existing receipt/sealing/cache/stream limits. Inspect a real public-catalog Alice pool to confirm candidates are complete source sentences and contain no bare heading/name. Run the focused gift suites, release check and independent review. The parent then runs full deployment verification and current-head CI. Actual AI selection on the deployed commit and source-linked gift read/revoke remain separate gates; no real call or production write is authorized to the worker.
