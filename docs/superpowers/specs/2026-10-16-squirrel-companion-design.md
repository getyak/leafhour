# 松鼠陪读：可忽略的异步消息

日期：2026-10-16。状态：用户已审阅并要求将后续间隔调整为 5 分钟，然后开始实现。采用当前会话内执行。本文中的时间、条数和文本长度是第一版试验值，不是已经验证的最佳参数。

## 用户要的体验

复用右下角的松鼠。用户主动开启陪读后，AI 根据当前及之前阅读中遇到的有限内容，异步发来像朋友一样的短消息。消息可以联想、回望、表达不同看法，也可以保持沉默。点气泡进入现有 IM 接着聊；不回复不影响阅读，随时可以关闭陪读。

成功的体验是：读者在阅读中偶尔收到一句接得上前文的话，愿意继续读或接着聊。不能以点击率、聊天条数或停留时长替代理解与陪伴感。

本次用户请求授权开启后的站内主动生成，补充旧文档中“只在显式提问时生成”的边界。授权限于用户开启的当前书籍，不延伸为系统通知、邮件、离线推送、其他书籍或私人笔记访问。默认阅读仍安静；开启陪读是独立选择。

## 现有基础与方案选择

`app/library-chat.mjs` 已有松鼠、非模态阅读对话、草稿、书籍切换和导出；`app/reader-conversation.mjs` 已接上当前阅读位置。`server/reader-chat.mjs` 已有按身份与书籍保存的对话、跨段历史、幂等、取消、租约和共享额度。`harness/chat-generator.mjs` 已接官方 DSH。

考虑三种做法：只在章末发一句实现最小，但不能覆盖长章节内的陪伴；让自由 Agent 频繁观察页面自主行动范围过大；第一版选择规则判断触发资格、AI 决定说什么或保持沉默。这样可以分别验证时机与内容，不新增调度平台或另建聊天产品。

## 开启、阅读与关闭

松鼠的原有点击仍打开阅读对话。阅读页的对话头部增加“开启陪读”控件；尚未登录时沿用登录返回当前书的流程，登录成功后仍由用户明确开启。

开启处显示一句范围说明：“根据当前和最近阅读的内容，偶尔聊一句。使用当前 AI 服务，可随时关闭。”开关按账号与书保存。首次开启只改变状态，不立即请求一条欢迎消息；松鼠旁出现一个小型“陪读中”控件，点击即可关闭。

刷新后可恢复当前书已开启的选择，但本次前台阅读的暖场和新增内容条件重新计算。切换到另一书，不自动替它开启。设置未读到或服务不可用时，不默认启用或发请求。

| 用户操作 | 结果 |
| --- | --- |
| 开启陪读 | 当前书开始观察本次前台阅读，松鼠保持原位 |
| 收到气泡 | 页面不跳动、不滚动、不发声、不抢焦点 |
| 点气泡正文 | 打开现有阅读对话，并定位这条松鼠消息 |
| 点气泡的“收起这条消息” | 只收起当前气泡，陪读继续 |
| 不理气泡 | 约 12 秒后收起，松鼠保留一个静态小点 |
| 点击“陪读中／关闭陪读”或 IM 中的开关 | 立即停止本机观察、撤下气泡并撤销未完成任务 |
| 关闭 IM | 回到阅读；陪读开关保持用户原来的选择 |

气泡里不摆一排快捷回复。可以回，也可以让这一句话停在那里。悬停、键盘焦点或文字选择期间暂停自动收起。收起后消息仍在当前书的聊天历史中；读过或收起的同一消息不重复弹出，不显示催促回复的倒计时或数字角标。

## 气泡与聊天如何接上

气泡放在现有松鼠上方或靠正文外侧的位置，桌面宽约 240–300 px，手机不超过可见视口减左右各 16 px，并避开安全区。气泡短暂淡入，遵守减少动态效果设置。2026-10-16 用户补充要求松鼠有生机：复用现有身体、头、眼睛和尾巴，加入小幅呼吸、间歇眨眼及稀疏摆尾；悬停或聚焦时侧头，按下时轻点头，真实生成期间才轻摆尾与思考，消息到达时抬头一下。人物不离开原位置，不新增声音、素材或模型请求。后台、失焦及减少动态效果时停止动作，恢复后不补播。一次只出现一个气泡。

AI 消息在当前书的同一对话记录中保存。聊天内标为“AI · 陪读”，直接展示原消息，不生成“你问了……”这样的虚构用户问题。用户接着回复时，该消息作为 assistant 历史进入模型；不必复制气泡内容或另开话题。

点气泡只滚动聊天内部到该消息，不改变正文位置。如果用户已有未发送草稿，完整保留，禁止自动填入或覆盖。后续回复以消息所关联段落为起点，同时提供当前阅读位置；原文入口清楚说明消息来自哪一段。关闭后从松鼠普通入口重开，继续按当前阅读位置工作。

在普通 IM 已打开时不再弹气泡，也不启动新的主动生成。已有完成消息由历史读取展示；若用户开始手动提问，优先取消尚未完成的陪读生成，避免自动任务占用手动对话。

## 触发资格与出现时机

“何时可以生成”与“何时可以露出气泡”是两个判断。没有满足资格时，不调用模型；结果回来后仍须重新检查展示条件。

### 怎样观察最近阅读

只在已开启、前台可见且窗口有焦点时观察正文。某段至少 50% 可见，或超长段覆盖正文视口中部，累计停留 8 秒后记作“本次前台可见过的段落”。打开目录跳章、刷新恢复和程序定位本身不构成连续阅读证据；观察不得据此把中间跳过的章节标为已读。

开始计时前要求一次真实的正文滚动、翻章或键盘阅读操作，避免刷新后静置页面就发消息。观察只存书、版本、稳定段落 ID 与可见事件时间，不增加阅读时长、完成率或掌握状态。

### 何时生成

首次候选需开启后累计 90 秒前台有效阅读，且至少有两个符合上述条件的正文段落。后续候选需距上次生成尝试累计 5 分钟前台有效阅读，且至少新增三个符合条件的段落。一次尝试无论说话、沉默或失败，均消耗本次机会，禁止紧接着重试。

跨章后至少在新章停留 45 秒，才可生成或展示；跨章不能绕过暖场、冷却或新增内容要求。回望前一章的内容只是候选话题，不是每次换章都必须弹消息。

一次阅读时段最多三次主动生成；账号每滚动小时最多三次，跨标签页和跨书合并。连续 30 分钟没有有效前台活动，下一次按新阅读时段处理，但服务端小时上限与冷却不会重置。时间与次数都由服务端复核，刷新、反复开关和多标签页不能制造新的额度。

浏览器在计算资格的过程中可以暂停观察，但在用户选字、写笔记、翻译、聊天或操作其他浮层期间不启动生成。前台连续 60 秒没有任何输入或阅读操作则暂停有效阅读累计，直到用户恢复操作；静置不是读懂或读完的证据。

### 何时展示

结果返回后，仍是同一账号、书籍、内容版本、开启版本及阅读会话，且满足以下条件才可出现：正文在前台，停止滚动至少 6 秒；未选字、未输入、未打开笔记或翻译工具，且没有其他弹层；IM 关闭；本次消息未曾展示。停止滚动只是试验性的可用时机，不能声称已经识别到用户思考完成。

等待安全窗口最多累计 60 秒前台时间。到时仍不适合展示，则只保留在聊天历史和静态小点中，不在之后突然补弹。用户已经换章，旧候选也不补弹；需要新的阅读资格才能再生成。

窗口隐藏、失焦或进入页面离开状态时，立即撤下气泡，暂停所有前台计时，并请求取消运行中的主动任务。恢复后不补发积压，不自动展示上一条，重新观察安全窗口和新增内容。断网时不连续重试；恢复后重新校验服务状态。

## AI 可以依据什么说话

服务端从当前身份与当前书重新读取正文。浏览器只提交稳定 ID，不提交可被当作原文的文本。当前段落最多 4 KiB；最近符合可见条件的段落最多 24 个，按实际经过顺序选择并注明章节。所有正文加本书近期对话总输入不超过 24 KiB，单段截断有标记。

近期可见段落的 ID 在当前账号、当前书和内容版本下有界保存，最多 48 个。换版本后不复用旧观察。第一版不会把保存进度之前的所有章节当作已经读过；历史位置只用于定位，已有且明确的可见观察才用于回望。

只使用这些正文与本书近期真实对话，不读私人笔记，不读取未经过的章节，不查网络，不检索其他书。这里的收窄只作用于主动生成；用户进入 IM 后，沿用现有手动阅读 Agent 的授权与工具。

消息写成一个完整、简短的念头，目标约 25–100 个中文字，容量上限 180 个 Unicode 码点。可以联系前文、提出不同理解或举贴近内容的例子，不要求每条以问题结尾，不连续发送“对吗”“你觉得呢”索取回复。禁止补写用户没有说过的想法、理解程度、情绪或经历，也不透露后文。

生成结果只能是 `{kind:"message", text, sourcePassageIds}` 或 `{kind:"silence"}`。引用的 ID 必须在本次实际提供的材料中；直接引语须逐字核对。说不出贴切的话时返回 silence，不用问候或模板励志语补位。文字使用纯文本显示，不执行模型返回的 HTML。

## 存储、异步与取消

新增按账号和书保存的陪读偏好与观察文件，并带递增的 `consentRevision`。每次任务绑定 owner、bookId、contentVersion、sessionId、consentRevision、idempotencyKey 和 runId。任务开始及提交结果前均检查有效状态。

消息继续保存在原聊天记录中，增加 `kind:"companion"`、`origin:"ai"`、触发段落与关联观察 ID；用户轮次继续保留原结构。历史构造、渲染、导出、轮询和取消都须识别两类记录，不能把主动消息变成用户提问、用户草稿或问题笔记。旧聊天文件向后兼容。

开启和关闭均是服务端持久变更。关闭时先在本机立即停止；服务端成功保存后才显示“已关闭”。若断网或失败，保留本机关闭并明确显示“本机已停止，关闭设置尚未同步”，持续撤下气泡、禁止新请求；用户可重试同步。不能把尚未保存的撤销报告为全局完成。

关闭后，旧 consentRevision 的任务即使返回也不能发布或重新启用。另一标签页收到偏好变化时同步关闭；同一本书同一候选只有一个服务端租约。取消和最终提交通过同一数据事务串行化，已完成且早于关闭的历史保留，尚未完成的候选不得补写成可见消息。

站内异步沿用现有“前端发起、服务端在请求生命周期内 await、另行读取状态”的托管方式，不把后台 Promise 当成可靠工作队列。状态读取和取消可在另一实例处理。超时、关页和进程重启后的过期租约不能恢复为新消息。

主动生成最多一次模型请求，单次预留上限 0.10 元，不自动重试，不开放工具。复用官方运行时、来源检查、共享并发及账号总额度；主动上限独立收紧，不能绕过现有每账号每小时十次总额度。预留不是实际账单。

## 第一版的代码落点

实现时在独立工作分支接入，不覆盖当前其他任务。当前 `origin` 为公开的 `getyak/leafhour`；查询旧名 `getyak/marginalia-reader` 也返回同一仓库的新名。保留现有远程，不根据旧文字擅自改名或切仓库。

新增 `app/reader-companion.mjs` 管理观察、触发与取消，`app/reader-companion-state.mjs` 管理可用时钟和消息状态，`app/reader-companion.css` 管理气泡和开启状态。通过 `app/reader-conversation.mjs` 接入现有松鼠；不复制角色或另建 IM。

扩展 `app/library-chat.mjs` 与 `app/library-chat-state.mjs` 支持 AI 发起消息、按消息定位和保留草稿。扩展 `server/reader-chat.mjs` 的消息类型与历史构造，新增 `server/reader-companion.mjs` 保存偏好、观察和任务约束，再由现有 `server/portal.mjs` 统一鉴权路由。

新增有界 `harness/companion-generator.mjs`，复用官方运行时与预算机制。具体函数签名、路由和任务拆分在本设计通过后形成实施计划。必要时为消息与任务存储提取小型共用模块，但不借此重写聊天服务。

同步更新发布资源清单与文档中的生成触发边界；原有手动对话、回声、阅读计时和外部 MCP 维持各自契约。

## 验收与交付

先用可控时钟和隔离模型验证暖场、冷却、非连续跳章、长段、失焦、隐藏、多标签页、限额、重复请求、取消与迟到结果。关闭、账号切换、版本变化后不得新发布；模型失败、silence 和原文校验失败不得出现假消息。主动消息不得污染用户问题或草稿，导出与重载仍保留 AI 归属。

真实浏览器验证 390 px 与桌面阅读：开启后继续阅读、松鼠冒出气泡、忽略自动收起、点气泡定位 IM、保留已有草稿并接着回复、关闭陪读，以及选字、笔记、后台和移动键盘期间的阻塞。补查 320 px 无横向溢出、键盘可操作与减少动态效果。不得用“静态界面出现了”代替这些流程。

生成质量另用少量、有界的真实模型试读核对。隔离材料的机制测试不证明真实陪伴感；真实账号的持久验收数据遵守 `test@cubxxw.com` 默认归属，不向其他真实用户写入。

设计通过后再实施、验证与审阅；按仓库默认授权提交当前任务改动、创建 PR、检查通过后正常合并，跟踪已有发布并核对生产版本。已合并、已发布与已完成人工式试读验收分别报告。

## 设计自检

已明确区分：开启／收起单条／关闭；生成资格／展示资格；可见过／读懂；主动 AI 消息／用户提问；当前书主动上下文／手动 Agent 工具范围。触发值可调但第一版有确定默认值。跨章不绕过冷却，silence 也消耗机会，后台不补弹，偏好未同步时不虚报关闭成功。

仍需真实试读才能判断的问题是：90 秒与 5 分钟是否适合书的节奏、哪些短消息值得出现，以及人物小点是否容易被理解。实施验收会记录这些限制，不把初始参数写成研究结论。
