# Book-first library and daily arrival

The library should open onto books. The calendar belongs to the existing dedicated calendar view (`/library?calendar=1`), reached from navigation; it must not fetch activity until opened. All books stay in the shelf; the former featured excerpt is removed from this page. Saved positions remain in book links and the companion continuation link. Cards continue rendering in batches of 12 with the existing accessible load-more fallback.

Approaches considered: keeping the month above books contradicts this request; opening the full chat automatically obscures books and steals focus. Use a compact, dismissible bubble anchored to the existing lower-right reading companion instead. The user delegated research, design and implementation in this request; implementation choices below are ours.

Loading: return index metadata through `/api/library?view=books` first, with explicit `personalizationPending`, then hydrate the existing complete account-aware list asynchronously. Keep search, ordering, identity fences, and retry behavior. Personal reading status is unknown until hydration, never presented as an asserted history. Cache only immutable public catalogue summaries in the service, never account data. Load archive compression and export/restore parsing only after an explicit data action. Delay optional daily inbox loading until its settings tab opens and move its display into that tab.

Arrival: after books are available, request `/api/library/arrival?timeZone=…` for the signed-in owner. Use the server's date in that time zone. Build a short factual recap from yesterday's actual intervals (merge overlap, clip midnight/DST), counts of user activity, and the most recent real reading interval. Do not return note/question text or call a paid model to restate recorded facts. Explain tracked/estimated/manual time accurately. Provide a continuation link, a way to open the existing chat, dismissal and a remembered disable choice. Guest visits show no personal recap. No off-site notification or background schedule.

Show once per owner, local date and time zone on this browser. Refreshes and duplicate tabs must not repeat it; a failed or hidden request does not count as shown. Account switch/sign-out clears the bubble synchronously and discards stale replies. Delay while a dialog, chat, text selection, editing or hidden document is active. Do not move focus, animate continuously or auto-dismiss text before it can be read. Reduced-motion remains respected. No raw personal content enters local storage, source control or public screenshots.

Validation: isolated domain and HTTP tests for date boundaries, overlap, unknown/zero history, ownership and absence of private text; controller tests for once-a-day, failures, focus and stale owner; real browser at desktop/mobile for first shelf, absent calendar/inbox, lazy card loading, calendar navigation, bubble controls, and keyboard accessibility. Full CI/build, normal PR merge, Production deployment and same-commit production checks remain distinct gates.

Research: https://web.dev/articles/browser-level-image-lazy-loading (defer offscreen work; reserve layout); https://www.nngroup.com/articles/progressive-disclosure/ (secondary views on demand); https://www.nngroup.com/articles/indicators-validations-notifications/ (match interruption to urgency). This product uses typographic covers rather than downloaded cover images; image lazy attributes alone do not address its bottleneck.
