# 旁读登录体验与身份接入

日期：2026-10-14，验收更新于 2026-10-15。状态：设计与计划均已获用户确认。代码已实现并完成独立复核，166 项测试和构建通过；正式网站邮箱验证码、Google 与 Apple 的真实登录、刷新保持登录、退出和退出后刷新均通过。Google 已正式发布，Apple 已验证返回原书原段落与笔记面板。

## 用户要达到的结果

在 `https://reader.cubxxw.com` 用邮箱验证码、Google 或 Apple 进入自己的书房。验证码邮件通过 Resend，以 `旁读 <hi@cubxxw.com>` 发出，真实收信测试也使用 `hi@cubxxw.com`。登录界面参考 Notion：清楚、简洁、方便，有精致而克制的动效。匿名试读继续开放。

验收以实际收到邮件、完成验证、刷新后仍登录、退出后会话撤销、第三方授权后返回自己的书房为准。配置存在、按钮出现、模拟测试通过，分别记录，不能当作真实登录成功。

## 实施前核对的现状

项目已经用 Supabase 验证邮箱身份，并把访问令牌和刷新令牌放在服务端；浏览器只持有不可读的随机会话 Cookie。私人书籍和记录按 Supabase 用户 ID 隔离。线上邮件发送入口关闭；Supabase 的公开认证配置显示 Google 和 Apple 均未启用。

当前页面同时露出邮箱和验证码表单，没有重发倒计时、明确的更换邮箱步骤或第三方入口。发送和验证的错误提示过于笼统。会话刷新需要补充并发请求协调，避免多实例同时使用同一刷新凭据。原有本机登录、账户切换时清除私人界面和安全的阅读返回地址需要保留。

## 接入方案

| 方案 | 对现有书房的影响 | 后续维护 |
| --- | --- | --- |
| Supabase 管身份，Resend 管邮件，三种登录共用现有会话 | 保留用户 ID、私人记录与既有隔离 | 推荐；增加第三方回调和配置即可 |
| 应用自行生成验证码，并直接接 Google、Apple | 要重新承担身份映射、验证码和凭据管理 | 增加安全和迁移工作 |
| 更换完整身份服务 | 要迁移现有账户、会话和授权关系 | 本轮收益不足 |

采用第一种方案。邮件使用 Resend 的 SMTP 接入 Supabase，验证码仍由 Supabase 生成和验证，不在应用中再造另一套验证码。默认六位、十分钟有效、同邮箱至少间隔六十秒重发；实际界面参数与生产认证配置一致。发信域名的验证、邮件模板和发送额度核对完成后，才开启生产发送入口。

## 登录面板

面板在当前页面内打开，桌面宽度约 380px，手机保持边距与键盘可见空间。保留旁读标志、暖白背景和少量墨绿；表单使用清晰的无衬线字体。标题为“进入你的书房”，辅助说明为“保存自己的书，也接着上次读”。

入口依次为 Google、Apple，再以“或使用邮箱”分隔邮箱输入。只有后台已正确配置的方法才能发起登录；尚未配置的方法明确说明状态。不会把可点击但必然失败的按钮作为已完成接入。

输入邮箱后点击“继续”，面板切到验证码步骤。展示完整收信地址和“更换邮箱”，保持一个支持粘贴、手机自动填充及键盘提交的输入框。发送按钮显示倒计时，到期才能重发。倒计时根据绝对截止时间恢复，切到后台、关闭后重开均不重置额度。

验证期间防止重复提交；错误后保留邮箱和用户输入，明确区分验证码错误或过期、发送过于频繁、网络暂时不可用。更换邮箱会清除旧验证码、使旧请求结果失效；快速关开面板不能把旧结果覆盖到新邮箱。验证码不写入持久化浏览器存储。

动效用于面板出现、步骤切换、等待和成功反馈，约 160–220ms，成功后自然返回书房或原阅读位置。尊重系统减少动态效果的偏好。支持 Tab、回车、Esc、焦点恢复、屏幕阅读器状态播报，触摸控件至少 44px。

## 邮件与发送

邮件主题为“旁读登录验证码”，正文突出验证码、十分钟有效和“如果不是你发起的请求，可以忽略”。提供纯文本版本，不加入营销信息。模板必须使用 Supabase 实际验证码变量，避免把登录链接误当验证码。发件地址固定为 `hi@cubxxw.com`。

核对 `cubxxw.com` 在 Resend 的验证状态，以及现有 SPF、DKIM 和邮件路由。新增解析先检查冲突；保留现有邮件接收配置。Resend 配额与 Supabase 发信限制保持一致；界面倒计时不能替代服务端限流。配置和验证不向日志、代码、导出包或聊天输出验证码、私钥及会话凭据。

## Google 与 Apple

两种登录都先到本站的启动接口，再经 Supabase 转到官方授权页，回到本站的固定回调。服务器生成一次性登录事务和校验材料；授权码只能在同一浏览器、限定时间内交换一次。回调必须核对有效事务，拒绝伪造、过期和重复回调；用户取消时回到可重试的登录面板。

浏览器不接收 Supabase 的访问令牌、刷新令牌或第三方服务令牌。成功后建立与邮箱验证相同的本站会话，登录事务 Cookie 清除；安全的返回地址只能是本站允许的书房或阅读路径。仅请求身份验证所需的基本信息，不请求 Google 邮箱、文件或日历权限。

账户归属以 Supabase 确认的用户 ID 为准。同邮箱的已验证身份关联沿用 Supabase 的规则，不在应用层按相似邮箱猜测或合并书房。Apple 的隐藏邮箱可能形成不同账户，不能根据姓名或推测的真实邮箱合并。当前用户主动关联另一种登录的账户设置，不扩入本轮。

Google 需要该网站的客户端配置和 Supabase 官方回调地址；Apple 需要有效的开发者服务配置、网站服务标识和签名材料。现有配置优先复用。本轮不购买开发者会员或创建额外收费服务。Apple 网页登录密钥有有效期，交付时记录到期维护要求；不据此自动创建提醒。

## 会话与失败恢复

沿用七天的本站会话和服务端身份校验。刷新令牌协调使用现有持久化存储的版本比较与短期租约：并发请求复用最新结果，租约超时可恢复；退出与刷新竞态时，撤销优先，不能重新激活已退出会话。认证服务暂时不可用时不误报验证码错误，保留安全的重试入口。

登录前产生的用户草稿继续按原账户隔离。登录后恢复触发入口：从书页请求登录则回到同一本书；从“带来一本书”登录则重新打开上传入口。跨站授权期间不把私人文本、文件或笔记放进跳转参数。

主要修改 `deploy/hosted-auth.mjs`、`server/portal.mjs`、认证 API 路由、`app/home.html`、`app/portal.js` 与登录相关样式。将登录状态和交互从书房脚本中拆成专门模块，保留书籍、笔记、上传和 Agent 的领域服务。补充登录事务、重发参数、回调与会话并发的接口契约。
