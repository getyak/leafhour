# GET-186 + GET-190 reader repair batch

Date: 2026-10-18 (implementation + parent-review repair round). Status:
implemented on public main `d8d211baaf61bd393b1c61a1bcd8a4253929ee2f`.
This batch follows the settled parent design (`get190-reader-repair-design.md`);
it contains production implementation only — no acceptance is claimed here.
Actual native Chrome QA, independent review and delivery remain parent-owned
(see [verification record](../../verification/2026-10-18-get-186-190-reader.md)).

## GET-186 — fresh opening must show the generated chapter heading

Root cause: `app/reader.js` boot restored
`restoreAnchor({...book.readingStart, offset:160})` in the no-valid-position
branch, scrolling the first paragraph to the reading line and clipping the
generated chapter number/title on first opening (e.g. fresh public Alice). That
fixed-160px root cause is removed.

### Entry policy — `app/reader-entry.mjs`

The real boot decision now lives in one module the boot calls directly
(`resolveReaderOpening`). Precedence is unchanged from the historical boot:

1. explicit passage / citation / translation / note entry (`resolveReaderEntry`),
2. the published Chinese sample entry (`chineseSampleEntry`),
3. a validated saved position (remote + local via `chooseReadingPosition`),
4. genuinely fresh or invalid-position opening.

Only case 4 returns `position: null`, and the boot renders the opening chapter
from its top (`window.scrollTo(0,0)`): the full generated chapter number and
title stay visible. Validated resumes keep their saved `offset`/`withinParagraph`
so some context above the paragraph remains; explicit entries keep their
deliberate paragraph alignment (`offset:160` from the entry, `withinParagraph`
cleared). Chapter navigation offsets in `commitChapter` are untouched.

Preserved behaviour:

- local/remote resume precedence and pending-local adoption
  (`chooseReadingPosition`), including the raw chosen record's revision handed
  to `progressSync.adopt` exactly as before (an unloadable paragraph blocks the
  anchor but keeps its revision for conflict handling);
- late-remote adoption guards in `adoptLoadedRecords` (no interaction yet,
  superseding explicit entry, `recoveredPositionNeedsChoice` conflict notice);
- all explicit entries: paragraph, citation (`contentVersion`/`layer`),
  translation action, note/records and `?sample=zh`;
- no progress erasure, no fake zero position, no source heading paragraphs or
  IDs removed, no `history` API changes.

Note on scrolling/history: the code-side fix is exactly one programmatic
chapter-top scroll in the fresh/invalid branch after render. Whether native
reload or history restoration can still reintroduce clipping in any particular
browser is real-browser acceptance and remains parent-owned; this document does
not claim it is impossible.

Tests: `tests/reader-entry.test.mjs` exercises the policy with real catalog
books (fresh, invalid saved positions, validated local/remote resume anchors,
citation/note/sample precedence, revision pass-through) plus one boot-wiring
check that `reader.js` consumes `resolveReaderOpening` and no longer restores
`readingStart` with a fixed clip offset. No mirror helper was created.

## GET-190 — conservative source emphasis as pure presentation

Formatting never rewrites source. One pure tokenizer,
`app/source-emphasis.mjs`, runs over the FULL immutable source string and only
returns presentation ranges; saved excerpts, share model text, exports and all
offset conventions keep their raw UTF-16 characters.

### Supported subset (not Markdown, no CommonMark claim)

`_content_` single-underscore emphasis for eligible content: non-empty content,
no underscore inside the pair, no whitespace beside either delimiter, delimiters
are not escaped (`\ _`), not intraword, not inside conservative literal regions,
and content contains no backtick or literal-region character. Everything else
stays safe literal text. No `innerHTML`, no HTML parsing or execution anywhere.

Boundary rules (repair round, from confirmed review findings):

- **Word boundaries use full Unicode code points including combining marks**:
  astral letters (`𐐀_a_`, `_a_𐐀`) and combining marks (`a`+U+0301 `_b_`) keep
  underscore runs intraword and literal.
- **Path boundaries**: a delimiter glued to `/` or `\` (either side) stays
  literal (`/tmp/_cache_/file`).
- **URL/query boundaries**: an opener glued to `? # & = : % + @ ~` or a closer
  glued to `# & =` stays literal (`?_key_`, `_key_=1` outside a URL).
- **Literal regions**: bare URLs (`https?://`, `ftp://`, `www.`) and Markdown
  links with simple square-bracket labels (`[text](balanced_target)` or
  `[text][reference]`, including collapsed references) keep every underscore literal; a pair whose
  delimiters or content cross such a region stays literal
  (`https://example.test/?_key_=1`, `[some _label_](https://example.test)`).
- Prose punctuation after a closer (`,.;:!?`, quotes, brackets) does **not**
  block emphasis — conservative boundaries must not eat real prose emphasis.

The stricter boundaries do not change the frozen catalog baseline: the same
218/31/279 = 528 conservative pairs are reproduced (the trio contains no
path/URL/link/mark/astral adjacency at any delimiter; inspected directly rather
than assumed). Source hashes remain frozen.

### Eligibility

`sourceEmphasisEligible(book)`: `book.visibility==='public'` and
`book.source.format==='txt'` — the default public plain-text catalog originals
(Alice, Meditations, Walden). Structured/non-txt public books,
private uploads (PDF/EPUB/code/data strings) and every translation layer remain
literal even when their text contains underscore pairs.

### Rendering — `app/passage-layers.mjs`

- `passagePresentation` registers `emphasis` (full-source content ranges) on
  original layers only, next to existing `lineBreaks`.
- `applySourceLineation` stores registered full ranges in the node registry;
  `sourceLineatedNodes` intersects them with each highlight segment using the
  segment source start — a detached segment is never reparsed, so a highlight
  may split a marker or an italic word.
- `sourcePresentationNodes` builds the DOM: plain text nodes, hidden syntax
  marker text nodes (`.source-syntax`, `display:none`, `aria-hidden`) and real
  `<em class="source-emphasis">` content (`font-style:italic` on the self-hosted
  family's declared italic face; no synthesized tilt is authored and no new
  fonts/dependencies were added). Every raw UTF-16 character stays in the DOM
  exactly once, in order; a `<br>` contributes no character and verse
  `lineBreaks` keep their exact prior split semantics.
- Consequences preserved: `textRange`/`captureDOMSelection` offsets, highlight
  paint/removal/repaint, overlapping highlights, reference fallback marks and
  surrogate/emoji boundaries.

### Original quote panel — validated slices only

`quotePanelSourceNodes` (used directly by `renderPanelSource`) formats a saved
slice from its full immutable source **only when** the snapshot book/version
identity, integer bounds and raw `full.slice(start,end)===part.text` all
validate. A historical excerpt whose saved text no longer matches the current
source is rendered as literal text (never re-tokenized as a stale detached
fragment). Inter-part joins (`　`), snapshot metadata and raw `part.text` stay
exact. The panel `aria-label` describes the presented excerpt (markers omitted
exactly where formatting was valid; literal saved text otherwise).

### Canvas share

Canonical `buildShareModel` text, `sourceStart`/`sourceEnd`, `before`/`after`
strings and the offset convention are untouched; model fields never strip
markers. Presentation-only metadata (`emphasis` per block; `beforeEmphasis`/
`afterEmphasis` per context) carries slice-relative ranges computed from the
FULL originals with independent windows (intra-paragraph prefix/suffix or whole
adjacent paragraphs, in the correct original/translation language).

- Wrapping (`wrapEmphasisRuns`): each candidate string is measured whole in the
  same style it is drawn (never summed per grapheme — kerning/ligature measure
  contracts hold), explicit `\n` hard breaks always break the layout, soft wraps
  stay at word/space boundaries (a space never starts a wrapped line), and
  long tokens split at grapheme boundaries with exact-candidate measurement.
  The older `wrapText` shared the leading-space soft-wrap behaviour; it was
  pre-existing (not a newly introduced regression) and both wrappers now break
  cleanly. Canonical text is unchanged by any of this.
- Context adapter (`layoutShareCard`): trim/truncate happen only here, on the
  display runs derived from the full-source ranges; the chosen two lines keep
  their run styles and the ellipsis adopts the adjacent run's style.
- Accessible display: `displayQuoteText` produces the presented text (markers
  omitted exactly where formatting is valid) and is shared by the canvas, the
  `share-preview-description` text and the panel aria-label. Canonical model
  text/raw offsets stay exact.
- Fonts: Latin share display uses the existing self-hosted `"Leafhour Serif"`
  (Newsreader, OFL-1.1). `ensureShareFonts` explicitly loads and checks the
  upright **and** italic faces before the first measurement (Canvas text alone
  never starts a face load). If either face is missing the card is measured and
  drawn with the plain serif fallback stack and the status line says so — an
  honest fallback boundary instead of any "real italic / no synthesized tilt"
  claim. The implicit whole-secondary-English italic is removed; italic appears
  only for authored emphasis runs, so measurement and drawing never disagree.

### Coverage and known limitations

| Surface | Emphasis | Notes |
|---|---|---|
| Reader DOM (original layers, parallel pairs) | yes | hidden markers + real `em`; raw `textContent` exact |
| Original quote panel | yes (validated slices only) | historical/mismatched excerpts stay literal |
| Canvas quote/translation blocks | yes | full-source ranges, per-run measure/draw |
| Canvas before/after context | yes | independent full-source windows; trim/truncate display-only |
| Canvas accessible description + panel aria | presented display | canonical model text stays raw |
| Share model text, snapshots, exports, MCP/provider strings | unchanged | raw UTF-16 source always |
| Translations, structured public books, private PDF/EPUB/code/data | literal | eligibility is metadata-driven |

Remaining limitations (not claimed as fixed):

- Native word selection/copy behaviour with hidden markers, actual rendered
  italic faces, and touch/cross-OS acceptance require real browser QA
  (parent-owned). The hidden-marker copy model comes from the parent design's
  private discovery note (human-unreviewed); it is not final product proof.
- Share `wrapText`/`wrapEmphasisRuns` measure-contract and hard-break cases are
  synthetic contract tests. Independent code review used local Canvas
  measurements at Georgia 56/408 without finding the earlier ligature/newline
  counterexamples in eligible catalog paragraphs; this was not browser proof.
- Font fallback can only state what the code does (identical measure/draw on
  the fallback stack plus an honest status); actual font network/rendered
  responses are inspected by the parent.

## Wiring

`app/source-emphasis.mjs` and `app/reader-entry.mjs` are registered in
`release-files.json` (release allowlist + reader bundle inputs),
`server/server.mjs` (local reader assets) and `server/portal.mjs` (portal module
map). The hosted reader bundle (`tools/build-reader-web.mjs`) picks them up
through the same allowlist; `tools/build-vercel.mjs` ships `app/` wholesale.
Local paper/night themes, shared controls/focus tokens and reader settings are
unchanged; only `app/styles.css` gained the two presentation rules above.
