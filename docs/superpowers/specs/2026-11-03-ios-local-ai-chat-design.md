# iOS local-book AI and immediate chat

The user approved implementing local tools on 2026-11-03 and requested an IM-like native conversation, smaller assistant text, clear streamed loading, less repetitive information and responsive return navigation. This explicit implementation request authorizes proceeding without another design gate.

Keep the official DSH runtime and account-bound model/billing service. Books need not be imported into the cloud library. Local read tools execute on iOS against the captured OfflineLibrary/book/version. Only requested text and conversation context reach the model; no original upload or private-note access is implied. Existing cloud books keep their current routes and authority. Image-only pages have an honest unavailable-text state.

Use an authenticated NDJSON generation request with progress/result/tool-request events. Local tool results return through owner/run/call-bound authenticated endpoints backed by shared authority, so hosted instances do not depend on process affinity. Cancellation, duplicate retries and stale replies must fail safely. The server never grants access from client source text. Local identifiers, source versions and passage anchors remain distinct from cloud-book identity. Keep original chat history and retain interrupted requests for recovery.

After Send, append the user's immutable message immediately, clear only the submitted draft and quote, and show one assistant loading state. Stream provisional answer text without marking it completed before the authoritative result. Retain one compact per-turn retry for failure. Reduce assistant body type using Dynamic Type. Collapse sources, remove routine scope/footer/provider labels and redundant global refresh/recovery controls. Back navigation must not wait on AI or network; protect durable local saving and do not render the full underlying reader repeatedly while chat is open.

Validation covers local read/search/paging/citations and cross-book/version rejection, authenticated cross-instance relay and billing idempotency, incremental native stream parsing, optimistic send/recovery, account switch/cancellation, long Markdown and large-book return navigation. Simulator, production and installed-device evidence are recorded separately. Follow the repository's default PR/CI/merge/release workflow; no preview deployments or repeated provider attempts.
