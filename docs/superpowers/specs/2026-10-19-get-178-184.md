# GET-178 / GET-184 — one reader entry, one command palette

Source scope, interface contracts and honest acceptance limits for the
GET-178/184 implementation on main 9e5777e. Design authority is the settled
parent design `get168-reader-entry-design.md`; the five interface gaps reviewed
by get150_review are binding requirements here.

## GET-184 reader entry

`#reading-tools-trigger` remains the sole floating reader entry in both focused
and unfocused layouts. The floating `#exit-focus` / `#focus-fullscreen` pair is
removed; browser fullscreen stays on the revealed header control and is
reachable only through the revealed tools surfaces. Live timing, manual
recording, local drafts, pending save/retry and attention labels are untouched.

One tools coordinator (`app/reader-tools.mjs`) owns the expanded state, the
single five-second concealment and the pointer/keyboard/dialog holds across both
the panel and the focused header. `mountReadingToolbar` exposes explicit
`reveal`/`conceal`/`hold`/`setControlMode` hooks plus one `onExpandedChange`
callback; `mountReaderImmersion` exposes explicit `show`/`close` hooks for the
header surface. There is exactly one pill click handler and one conceal timer,
both inside the toolbar state machine the coordinator drives. Concealment or a
failed fullscreen request returns focus to a connected, visible, non-inert pill
(or the visible header fallback).

Chat integration is injected, never duplicated: one chat trigger ("Ask AI") in
the tools surface, the shared pill used only as the companion bubble/unread
anchor, an explicit focus-return callback and an explicit unread callback. The
shared pill's ARIA and any drag behaviour stay owned by the tools coordinator;
`mountLibraryChat`'s optional launcher configuration skips generated launcher
DOM, cartoon motion, drag positioning and launcher ARIA ownership entirely, and
never receives the mutable pill as its launcher. The companion keeps one
instance, its default-on behaviour, presentation bounds, cancels and every
owner/epoch/revision fence; opening tools never re-mounts it, resets its clock
or reconfigures it. The library launcher becomes the monochrome Leafhour mark
with no character motion, keeping its chat semantics and existing positioning.

## GET-178 command palette

One accessible command palette serves every scoped page entry: home, library,
reader, the four `/mcp` and four `/privacy` locales, source-review, evals and
gift/preview. `app/palette-bootstrap.mjs` is the shared small trigger (visible
Cmd/Ctrl+K keycap, shortcut handling, one on-demand import);
`app/command-palette.mjs` (lazy) owns the native dialog, result keyboard model
and page adapters; `app/palette-library.mjs` owns full-library data.

Page adapters are explicit objects (documented `window.marginaliaPaletteAdapter`
registry plus `data-palette-page`); the palette module imports no unrelated page
controller. The sidebar keeps exactly one palette entry and the local
`#book-search` input stays a filter; slash focuses that filter when it is
visible and otherwise opens the palette. Both shortcuts defer on handled events,
IME composition (isComposing/keyCode 229), editable targets, another open
modal/popover and any unintended modifier combination. Exact pointer predicates
(`(pointer: coarse)` / `(any-pointer: fine)`) decide whether the keycap hint is
useful, including fine-primary + coarse-secondary devices.

The palette announces its result name, count, loading, empty and error states.
Escape/Tab/arrows/Home/End/Enter stay coherent with the native dialog; a modal
handoff (settings, calendar, Aa) closes the palette without stale focus
restoration, while a plain Escape restores the actual opener or a connected
fallback. Settings and calendar destinations are built with the exact GET-179
owned view codec; reader paper/night/font actions call the existing reader
appearance hooks and preserve paragraph and progress state. Current-book
navigation uses real resume/citation URLs; no search-in-book claim is made.

Full-library data comes from the exact `/api/library` endpoint called directly
(no readerFetch path remap) with a captured `X-Reader-Owner` and `no-store`,
after `/api/auth/session` bootstrap for private results. Request generation and
owner revision are fenced; `X-Reader-Session-Changed` invalidates immediately;
late private results are rechecked against the current session before adoption.
No private book names reach a persistent cache, the URL query or cross-owner
recents. Guest catalog results stay available without login; loading, empty and
error are distinct states.

## Build budgets

The reader initial JS budget (320 KiB) and CSS budget (200 KiB) are unchanged.
The small shared trigger `palette-bootstrap.mjs` is statically bundled with the
page (it is the whole initial cost of the palette); `command-palette.mjs` and
its data adapter are dynamically imported only on a real user gesture from that
bootstrap, behind the same release allowlist check and exact importer/kind
fence in `tools/build-reader-web.mjs`. The fence keeps exactly the prior five
exceptions plus `command-palette.mjs` from `palette-bootstrap.mjs`; there is no
reader-to-bootstrap lazy edge and every other static import stays bundled. The
launcher drag positioner moved behind dependency injection (portal.js supplies
it for the library launcher), so the reader bundle carries no launcher drag
code. Actual built bytes are recorded in the verification record.

## Owner boundary and async data

A known owner source (page adapter getter; `null` means known guest) rejects
any incompatible session identity before `/api/library` and again at adoption;
pages without an owner source treat the session identity as authoritative.

The full-library adapter fences owner state in view, search, load and adoption
— not only at request settlement. Real account transitions wire in
synchronously: home/library through `ownerScope`'s `clearPrivateUI`/adopt
(`invalidatePaletteLibraries`), the reader through its established
session-change lifecycle (`reader:session-changed`), and support pages without
an owner source clear cached private results before fresh session verification
on every reopen. Session and library responses must be `ok` before adoption;
HTTP failures render as error with a retry action, never as ready-empty.

## Focus and hold semantics

All tools close/reveal transitions route through the single coordinator
(immersion's outside pointerdown, focus-mode and fullscreen changes call its
close request), so the pill state and the header surface cannot split; a
bubbling click on a handoff control (or any open dialog/popover) never
re-reveals concealed tools.

Pointer hover previews reveal the tools without ever moving `activeElement`;
only explicit click/keyboard activation may focus the revealed header. The
single conceal timer is held while either surface (panel or focused header) is
hovered or focused, and dialog holds keep working as before.

## Labels

New visible labels live in explicit exported dictionaries in the owning
component (`PALETTE_TEXT`, chat trigger labels, tools labels) so the future
locale task (GET-192) never needs a global DOM translator. This task makes no
all-language completion claim.

## Acceptance limits

Local evidence covers node controller tests, the focused build commands and the
release checks. Native browser inspection (real 1200/390 geometry, idle/keyboard
night states, screen readers, cross-OS or touch hardware) is parent-owned and
not claimed here; see the [verification record](../../verification/2026-10-19-get-178-184.md).
