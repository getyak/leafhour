# GET-192 — Four-language interface and persistent navigation

Status: agreed execution design; implementation and acceptance are pending. GET-188 is merged at `e44e83ef79f2470e87027689f1098e22774e9c51`; refresh main before implementation. This document consolidates the independently reviewed transaction design and the classification of 69 ambiguous source paths. Those reviews establish design boundaries, not a localized product.

## Product outcome and aesthetic constraints

The English entry must lead to an English interface. An explicit choice among English, 简体中文, 繁體中文 and 日本語 must remain coherent through home → library → reader → settings, login returns, owned citations and browser Back. Interface language is distinct from book language, translation target and reading preferredLanguage. Retain the existing paper/night palette, typography, quiet controls, mobile menu hierarchy and accessible choice patterns; add a clearly labelled Interface language choice within existing appearance settings, not a separate onboarding flow or duplicated floating control. Authored home language links remain real links.

Success requires complete visible control labels, accessible names, loading/empty/error/confirmation states and owned links, not just translated headings. Source passages, real titles/authors/descriptions, existing translations, filenames, notes, user questions and AI answers remain authored content. Code, routes, locale identifiers and export schema are not prose to translate. Unknown service failures get an honest localized generic message without an invented cause.

The current compiled reader is 327670 bytes, only 10 bytes below its existing 327680-byte cap; CSS is 169008 bytes under 204800. No cap increase, arbitrary externalization or inference from a source file's raw size is allowed. The implementation must measure the real bundled and external module graph.

## Runtime and pure boundaries

- `app/ui-locale-codec.mjs`: pure exact four-code validation, browser-language
  fallback mapping, owned URL/ui parsing. No document/storage/loader/TLA. Server
  safe-return/auth policy may import it. Duplicate/conflicting/unsupported query
  UI values are rejected, navigator zh-CN/ja-JP may map to canonical codes.
- `app/ui-catalogs/en.mjs`, `zh-Hans.mjs`, `zh-Hant.mjs`, `ja.mjs`: fixed public
  stateless ID→string catalogues, equal keys and explicit interpolation parameters.
  English is complete default data, also safe for server/static English shells.
- `app/ui-locale.mjs`: ONE physical browser module/ready promise/mutable state.
  Static pure-codec+English imports; selected non-English catalogues through
  exactly six static literal dynamic imports (three base + three fixed retry URLs). No component imports/cycle.
  Initial catalogue failure resolves a usable English fallback and visible retry,
  never leaves application bootstrap rejected or body indefinitely hidden.
- Proposed explicit API: `t(id, params)`, `getUiLocale()`, `setUiLocale(code)`,
  `onUiLocaleChange(fn)` returning unsubscribe, `uiReady`, and owned `uiHref(url)`.
  UI roots may use component-scoped `bindUi(root)` over ONLY explicit trusted
  data-ui message IDs/attribute IDs; no text matching, automatic MutationObserver,
  DOM text walker, global textContent patch or translating assembled dynamic data.
  Callers own dedicated UI text nodes/attributes. Binding must not replace a
  container holding source/user content, inputs, selected source ranges or dialogs.

## Initialization, persistence and real state

Canonical library/read raw HTML has complete English default text, lang, loading,
error and return entries shared by static and server rendering. Explicit source
markers/known template structure are acceptable at build/server time; translating
arbitrary runtime text is not. Native first meaningful controls must be coherent:
all independent entry modules depend on the same initialization. No whole-body
blanking. Authored home/support route remains authoritative over conflicting ui,
with authored prose/SEO intact. Initial dictionary failure must clearly disclose
English UI fallback on that authored route; annotate the interactive UI roots'
actual language separately rather than relabeling Japanese prose as English.

For canonical in-place switching, load/validate the selected catalogue FIRST,
then commit active language/lang/owned history/device preference and notify
component bindings once. Request generations reject late success AND failure.
Catalogue failure retains old UI/query/preference and offers retry. No pagehide,
reload, model/record writes or state reset to cause rerender. UI message caches
retain ID+params so completed/failed chat/translation/PDF statuses can reformat
without restarting the same operation or changing task IDs/epochs/drafts.

Commit matrix is settled in the normative v2 rules below: canonical history
failure retains all prior active UI/lang/URL/preference; storage failure after
successful history becomes honest session-only. These are sequential same-event-
loop rules, not a browser multi-resource or cross-tab atomicity claim.

One new UI preference key `leafhour.ui.locale.v1`, preserving all marginalia/cookie/export/source-language
keys. Home link follows selected authored route; canonical library/read and safe
auth/citation targets carry one ui. Every login outer URL and inner safe-next has
the same one validated ui; legacy no-ui returns remain compatible. Invalid or
conflicting values cannot broaden next or alter book/passage/version/layer/hash.
Changing UI language does not change reading preferredLanguage or source lang.

## Normative v2 rules closing review150's five design gaps

1. **Unique mutable API graph:** only exact ./ui-locale.mjs static import-statement
   from the actual reviewed owner subset becomes /ui-locale.mjs. Reject wrong
   importer/kind, dynamic/require/query/hash/alias or server/pure edges to that
   resolved mutable file. After compilation assert app/ui-locale.mjs is absent
   from all bundled inputs; this catches normalization aliases that might evade
   literal spelling checks. Validate the public external/lazy source graph too,
   because the reader metafile cannot see its transitive imports. Aa/gift and
   initial reader must resolve the same absolute URL/API identity. Existing lazy
   modules retain prior behavior; only this stateful API is additionally strict.
   Both endpoint release entries required. Catalogue data must remain immutable
   strings only, never a place to move product logic outside the reader budget.

2. **Bounded initial and switch attempts:** deadline 3000ms per catalogue attempt,
   an engineering failure limit, not a measured network/performance result. Initial
   timeout/rejection resolves uiReady ONCE to usable complete English controls,
   with requested-language failure and a retry target. Existing UI switching
   timeout keeps its old active UI/lang/query/preference, ends pending state and
   offers explicit retry. Timeout/supersede/cancel invalidate publication before
   any later result. Release each owned timer on settle/cancel/supersede; settle
   the old UI attempt as stale rather than leaving its caller promise hanging.
   Native import itself is not cancellable: consume late success/failure, allow
   code caching only, never publish/notify/write URL or preference late. Core
   runtime/English data loading is an existing JS availability prerequisite;
   do not claim general offline functionality if the application entry itself
   cannot load. Never hide the whole body while awaiting a catalogue.

3. **Finite catalogue retry:** each non-English catalogue has exactly its base
   literal and one literal ?retry=1, six exact loader/dynamic-import edges in all,
   backed by the same three release-listed data files. An initial rejection or
   timeout permits the corresponding variant on explicit retry only. No random,
   timestamp/incrementing query, API cache-busting or automatic retries of other
   languages. Repeated clicks cannot create further module URLs. After variant
   failure/timeout, retain the current UI/drafts and offer an honestly labelled
   manually activated page reload; never automatically reload/pagehide. If an
   already validated immutable catalogue is cached, a later explicit selection
   may reuse it without a new module URL. Actual native503 receipts must prove
   the exact second URL and successful publication; parity/probes are insufficient.

4. **Commit matrix:** validate/prepare a safe target URL preserving current
   history.state and unrelated pathname/query/hash/book/passage/contentVersion/
   layer/overlay data. Load and validate the catalogue and recheck generation
   immediately before the first side effect. After the catalogue settles, read
   the LATEST location.href and history.state again and rebuild/revalidate ONLY
   the owned ui merge synchronously before writing; never replay a URL/state
   snapshot captured before loading. Preserve intervening search/filter/overlay
   changes. Do not overwrite a concurrent path transition: settle stale if this
   document is no longer the same canonical navigation context. No await between
   this final read/validation and the history commit. For a user canonical switch, try
   necessary history.replaceState FIRST. History failure rejects before any
   preference/active UI/lang/commit notification; keep all old state, report the
   local error in old language, no assign/reload/back. After history succeeds,
   attempt ONLY the new UI key. Storage failure keeps its old value/other keys,
   still commits the new UI/lang/URL as SESSION-ONLY, explicitly not saved; owned
   links carry the new effective ui. Storage success is committed+saved. No await
   in this synchronous commit. Subscriber exceptions are isolated, cannot become
   catalogue failures or prevent other owners' label updates; report as separate
   UI-update fault and keep its owner review/verification open. API results are
   committed+saved, committed+session-only, rejected(reason) or stale, not a vague
   boolean. Initial loading does not rewrite/persist fallback en; a valid authored
   route records its explicit choice only after successful catalogue activation,
   with the same honest session-only handling if preference storage is unavailable.

5. **Requested vs effective:** getUiLocale() is the actual active formatter
   locale. getUiLocaleState() exposes a readonly requested/effective/fallbackReason/
   retryTarget/attempt/persistence snapshot; no credentials/content. Language
   commit listeners and loading/error-state listeners must be distinguishable
   (for example onUiLocaleChange vs onUiLocaleStateChange), so a phase update
   cannot silently rerender source-bearing controllers. Initial fallback never
   overwrites a saved choice or requested canonical ui query. It clearly says
   English is active while retry still targets the originally requested code.
   Owned links follow the EFFECTIVE UI, not an unfulfilled target. After success,
   one transaction/one locale notification activates the target. Authored route
   prose/SEO/document lang remain authoritative; fallback interactive roots get
   their actual English lang, not an English relabel of Japanese authored prose.
   A later retry does not reinitialize the entire application or replace uiReady.

Cross-tab automatic switching is OUT of this task: no storage-event broadcast
that could override an explicit query or create loops. A later navigation or
reload may resolve the stored preference through ordinary precedence. Existing
reading/account cross-tab owner guards stay unchanged. No cross-tab atomicity
claim. The provisional owner list is not a permanent permission grant: refresh
it after GET188, prove actual imports, and remove unused owners before final graph acceptance. All13 helper boundaries including atmosphere-
state and squirrel-position remain mandatory; caller formatting, no browser
singleton import or task/audio restart in those helpers.


## Additional navigation settlement rule (v4)

Canonical view history already uses push/replaceState. Browser Back may reach an
older entry with a different valid ui while keeping the same live document.
Retaining ui in new view URLs alone is insufficient. UI runtime listens to native
popstate (not a monkey patch of history methods), validates the CURRENT canonical
URL and runs the same bounded generation-fenced catalogue transaction for its UI.
Do not reload, write a reading record or reset filter/overlay/source/drafts to
change labels. New user selections supersede older pending history requests.

- Explicit language-picker success uses the v2 history-first/device-save commit
  matrix. Authored route success records its explicit route choice after catalogue
  activation; fallback never records English over the authored/requested choice.
- Incoming canonical query and browser popstate are route overrides, not a new
  device-setting action: they may activate a different effective locale without
  overwriting the last manually saved UI choice. Missing/invalid ui falls through
  to the unchanged valid device choice/browser resolution. Outgoing owned links
  use the actual effective locale, retaining one valid ui through view/overlay
  URL writers. Existing source filter lang is a separate field.
- Native Back has already changed the URL before the locale handler runs. This
  actor NEVER calls back/assign/reload/replaceState to undo that navigation or
  rebuild history.state. On catalogue failure/timeout keep old effective UI and
  the browser's CURRENT URL/view, expose requested-vs-effective fallback/retry,
  preserve device preference. This is an explicit route-fallback case, not a
  false claim that an externally navigated URL stayed at the old value.
- A later retry remains a route actor: no extra URL or preference write. After
  success labels/lang update once. Results/state distinguish committed+route
  from committed+saved / committed+session-only. A language picker invoked during
  this pending work is a newer explicit transaction and may replace/save normally.
- uiReady resolves once; onUiLocaleChange is for actual language commits, phase
  subscribers are separate. A same-effective-language history transition must
  not republish all labels or mutate language preferences. It MUST still first
  advance/invalidate the request generation, settle any old picker/import/retry
  attempt as stale, cancel its owned timeout and clear obsolete pending/error
  state. A same-effective shortcut skips formatting only, never cancellation;
  late old success/failure cannot alter the newer route. Existing view-history
  listeners independently apply their owned filter/overlay; do not duplicate or
  replace those controls in the locale listener.

Acceptance adds actual production view-codec preservation of ui with shelf/q/
topic/source lang/overlay, synthetic Back ui=ja→en and pending-Back→explicit-choice
races, plus native Back after switching language within a library history stack.
No cross-tab auto synchronization is introduced by this rule.


V5 acceptance additions: a same-effective Back cancels a pending different-locale
picker/retry before returning, including its late rejection; while a catalogue
waits, real library view writers change search/filter/overlay/history.state, then
selection success preserves those latest values and changes only ui. These remain
planned cases, not executed evidence. V4 and its review are retained unchanged.


## Concrete owner and state decisions from source classification

1. Remove `book-introduction.mjs` from mutable browser owners. It is a pure validator shared by server code and returns real description/AI draft content. `reader-book-actions.mjs` and its bootstrap own labels and cached errors; language events never call open/generate/close or clear epochs. Every other pure/shared helper remains server-safe.
2. Add `control.updateLabels({label})` to the existing choice primitive. The owner first updates its native options, then explicitly refreshes the owned root/input/listbox names and keyed option labels. Preserve value, open state, query, focus, active option and IME composition; defer input-display writes that would disrupt composition. No change event, callback, remount, preference write or new mutable-locale import in the primitive. The existing `sync()` retains its business option/value responsibility.
3. Calendar/duration/progress helpers accept explicit locale/formatter arguments or return stable descriptors to their actual UI caller. Real chapter names, stored chapter labels, revisions, timezones and source/mode/variant remain intact. Reformat cached calendar errors without clearing request state, activity reloads or progress writes.
4. Audio must use a stable local cause/status for its original-audio fallback before localizing display; preserve the current functional branch that tests for a translation failure. Do not replace it with a translated-message or remote-error regex. The listening scene question is a NEW user-requested draft, not a notice to rewrite on language change. Only its fixed framework may use a caller-supplied formatter at creation; preserve transcript/quote/passage IDs and already-entered drafts. No audio/session/task restart or target-language change.
5. Localize the fixed chrome of NEW Markdown and ICS artifacts only at their existing explicit generate/preview/download actions, using pure formatter/label parameters from the UI caller. Preserve JSON/archive fields and values, UID/UUID creation timing, time/zone/URL escaping and folding, source content, citations, authorship and all existing exported files. Language events do not regenerate previews or download/package anything. Add serializer regressions for these real production paths.
6. Keep cached UI state, persistent history and internal failures distinct. Reformat auth busy/error/countdown without replacing the flow or resending; palette labels without reloading its catalogue/query/index; PDF/translation/chat statuses without restarting work. Existing imported `turn.error` is historical data and must not be rewritten. Map only existing trustworthy local codes; any new transported code needs actual server→client transmission coverage. Unknown remote prose is never a dictionary key.
7. Preserve GET-188's identity/book-only resume, synchronous refresh clearing, owner revision and stale-generation fences. Apply effective UI to current outgoing account/resume links without refetching. Remove `landingMake → homeText` for dynamic title/author/description and use explicit UI-only writes plus direct data textContent. Relabel an already visible palette retry/reload notice in place, even before palette import succeeds; no synthetic gesture/import/retry, focus reset or retry-budget change.
8. Authored MCP/privacy prose, source excerpts and SEO retain route language. Runtime labels belong to existing owners. `home-locale.mjs` remains a server-safe authored renderer. `reading-arrival` changes only its own UI context/provenance/loading/retry nodes, preserving true original/translation/lang and lifecycle timers. The CSS `content: '调整位置'` hint becomes an explicitly owned localized hint node/attribute. Complete canonical English shells, their document lang/loading/return entries and shared server/static rendering are separate acceptance requirements.
