# GET-151 · Explicit, bounded translation batches

The reader already stores per-account independent literal/interpretive drafts via its shared library service. Prior full-book candidates exist; this work must not regenerate them. Build an operator CLI that orchestrates the existing authenticated HTTP translation API, serially, from stable section/passage IDs. No scheduler, new provider, automatic page-load generation, or new standing authorization. The CLI is dry-run by default; actual execution requires both --execute and an explicit --max-requests integer in 1..20. One invocation cannot silently translate a whole book. Model calls remain charged to the existing configured translator and quotas, without extending its budgets.

Authenticate with an already authorized session via LEAFHOUR_SESSION (no password login, token CLI arguments, or token persistence). Read /api/auth/session and bind checkpoint to returned user ID + origin + book ID + source version + a hash of ordered passage IDs and original text. Only HTTPS or HTTP loopback; reject URL userinfo/path/query/fragment and redirects. No tokens, original text, translations, notes or personal records in checkpoint/logs. Checkpoints are atomic private JSON (0700 parent/0600 file), lock out concurrent execution for the same checkpoint, refuse symlink writes and binding changes. Failed/unknown outcomes remain retryable and are re-reconciled from actual server translations on resume. Dry-run must not reserve quota, create checkpoint, write, or generate.

Use the existing per-book GET response/transfer protocol and bounded responses; respect source/chapter ordering and exclude front matter/appendices/metadata using existing body/source-section semantics. Eligible untranslated paragraphs only: both existing translations skip; partial translations and any reviewed translation must never be overwritten by the batch. Explicitly report skipped partial/manual-review cases; do not fill one missing version by replacing the other. A failed request records stable ID/reason and stops; 401/403/409/429/network/timeout never auto-loop. Reopening/resuming reads actual source and states again, so a crash after server success does not duplicate generation. SIGINT/abort stops future requests; never claim an in-flight provider call was refunded or undone. All results stay draft. Glossary/review/source-page checks remain separate quality gates.

Extend translate(user,id,passageId,options={}) and the existing route with an optional expected contentVersion. Reject stale version before any provider request. Before saving, re-read current source/ownership and reject stale source, prevent overwriting concurrently added versions/reviewed translations, preserve original IDs/records. Existing unversioned callers stay compatible. A source update/deletion during generation cannot recreate the old book or publish old overlay. Do not pass notes/history or a whole book to the provider: retain the existing current-and-neighbors translation context.

Acceptance: real local HTTP + isolated synthetic library, no live provider: dry-run zero POST/writes; explicit bounded serial execution; correct section ordering; resume/crash idempotence; failed reason/retry; source/account/origin mismatch; stale source before/after generation; partial/reviewed preservation; concurrent checkpoint refusal; atomic non-secret output; redirects/oversized responses; Ctrl-C future-request stop. Run applicable tests, full verify:deploy before delivery, independent review, current-head CI and normal merge. Actual user-approved full-book content/paid run/human review remain open; this engineering slice must not close GET-151.
