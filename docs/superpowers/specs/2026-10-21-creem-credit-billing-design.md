# Leafhour 按需额度包、Creem 支付与真实用量统计

日期：2026-10-21。状态：用户已确认开始实现本设计；真实接通、支付与 Creem 审核仍按验收证据分别记录。

## 1. 目标与已经确定的方向

用户要求结合 Leafhour 的产品设计收费与支付集成，做到真实可用、可以统计。用户已在本轮选择「按需额度包」。本提案将付费对象限定为官方托管实例提供的 AI 处理服务，保留安静阅读、原文与双译分层、个人记录控制、本地运行、自托管和免费导出。

成功标准是同一账户能完成：看清收费范围 → 购买额度 → 付款核实后到账 → 明确请求 AI → 保存结果后结算 → 核对消费与余额。运营者能把订单、赠送额度、模型调用、服务失败、退款与成本对应起来。漂亮的支付成功页和模拟统计不算完成。

假设：首期用 USD 定价、一次性购买、无自动续费、无自动充值；不把个人书籍或未经授权的译本作为出售商品。价格与赠送数量是以下建议值，尚未成为公开承诺。

## 3. 收费方式的取舍

| 方案 | 好处 | 首期问题 |
| --- | --- | --- |
| 按需额度包，按功能事先报价 | 没有续费负担，读者能预知消耗；失败可以明确退回 | 需要真实的额度账本与任务结算 |
| 按月订阅 | 收入较稳定 | 尚无真实使用分布，难以定义公平的月额度；多出续费与取消流程 |
| token 成本乘系数后直接扣款 | 与供应商成本接近 | 工具调用、上下文与缓存很难让读者预知；缺 usage 时无法准确扣款 |

采用第一种。供应商 token 与费用用于内部成本统计，客户按公开的服务点数结算；两套口径分别保存。付费点数代表本实例的服务权益，不宣称是现金钱包、可投资资产或可跨实例转移的资金。

### 建议的首发商品

先只上一个商品：**US$5 / 100 阅读点**，一次性购买，无自动续费。新增档位应由真实成本和使用数据决定，首期不做复杂套餐和「最受欢迎」标签。可能适用的税费以结账页为准，官网须与 Creem 商品的含税/未含税设置一致。

| 能力 | 首期建议价格 | 范围 |
| --- | --- | --- |
| 阅读已有原文、已有译文、查词定位、复制与调整排版 | 0 点 | 不生成新内容 |
| 高亮、笔记、阅读记录、已保存结果的再次查看、导出 | 0 点 | 不以购买额度为前提 |
| 单段新翻译 | 1 点 | 同时生成独立的直译与意译；目标原文完整、至多 4,000 Unicode 码点，总上下文至多 24 KiB |
| 一次阅读对话 | 4 点 | 现有当前书最近六轮和授权分页工具；一次有界任务，不按内部工具次数向用户多次收费 |
| 一次选文 AI 注解 | 4 点 | 用户明确发起，来源范围和成本上限同样受控 |
| 自动松鼠陪读、系统自动导读与赠书短句 | 0 购买点 | 平台赞助，单独记成本，受现有触发规则与赞助预算限制 |
| 新生成语音、OCR、复杂导听或整本自动翻译 | 尚不纳入购买点 | 保留既有可用性与运营预算边界，待相应计量和报价通过验收再开放收费 |

这里的「0 点」不代表平台无限承担生成费用。自动功能沿用已授权的有界触发，另受赞助预算保护；赞助耗尽时安静暂停，不转为付费、不借用购买额度。系统自动行为、历史任务和切换页面都不能获得扣费授权。

试用建议：每个验证账户只发一次 10 试用点；试用与购买分账，试用先用，试用赠送有平台总预算和防重复领取限制。已有账户不追溯扣费，切换至付费模式时先展示新规则并发试用权益。

购买点首期不设常规到期日；试用点也不在首期引入到期规则。退款、拒付或服务终止按公开政策处理。不得营销为永久运营或无限量使用。

### 定价约束

Creem 当前公开标准费率为每笔成功交易 3.9% + US$0.40。US$5 的示例手续费为 US$0.595，扣费后 US$4.405；这不包括税费口径差异、退款、提现、汇率、基础设施和模型费用，不称作利润。

建议运行保护：一次收费阅读对话的模型与搜索费用上限 US$0.12，单段翻译上限 US$0.015，按供应商当前已核验费率保守预留。按 4 点/对话，一包可完成 25 次对话；全部用在这种对话上时，模型成本上限示例为 US$3，手续费后仍有 US$1.405 覆盖其他支出。该结果只是边界计算，不是实测毛利。

报价时费率未知、过期或无法约束最大成本，就暂停该收费操作并保留阅读功能。实际成本分布测得以后再调整对未来任务的售价；已购买的点数数量不变，旧任务仍用创建时的价目版本。

## 4. 产品界面

### 官网

保留现有精简方向。页首只增加一个清楚的「价格」入口；隐私、服务条款、退款政策和联系邮箱放页脚。各语言公共页面都能免登录访问，进入价格页保持语言。

价格页主要内容：

> 阅读免费，AI 按需使用。
>
> US$5 · 100 阅读点。一次性购买，无自动续费。
>
> 一次单段双译 1 点，一次阅读对话或选文注解 4 点。没有购买点，已有书籍、译文、笔记与导出仍可使用。

页面再用简短表格说明成功标准、失败退回、税费、支持邮箱、书籍来源与自托管方式。不展示未经验证的用户量、成功率或「可翻译整本书」承诺。

未登录点购买时先登录，返回相同商品；官方收款尚未启用时显示「支付尚未开放」及真实状态，不能将沙盒按钮伪装成可付款商品。

### 账户内的「额度与账单」

余额放在设置里，不常驻正文。默认显示可用点、处理中预留点和最近消费。试用/购买来源可展开。

消费行示例必须来自实际记录：时间、功能、关联书籍（仅本人可见）、消耗、结果、操作编号。失败行显示「未扣点」；预留显示「处理中」，不是已消费。订单列表单独列金额、币种、支付状态、到账点数、退款和 Creem 凭证入口。

不足时在用户主动点 AI 功能后内联提示「本次需要 4 点，当前可用 2 点」，提供购买或继续阅读，不弹出遮挡正文的营销层。

### 发起 AI 的过程

第一次收费前显示准确点数与规则。后续按钮直接标注「翻译 · 1 点」「发送 · 4 点」，不为每个普通请求增加模态框；多段批处理则必须展示总段数、总点数和本次上限。

进入处理中先预留，结果通过校验、保存且可取回后才消费；再次打开已保存结果不收费。点击取消、失败、来源变化或未交付不扣购买点，即使供应商已经发生费用。用户因此获得的退款与平台承担的成本分别记账。

## 5. 服务与数据边界

网页、批处理、MCP 共用 Billing 领域服务。支付供应商只是适配器；自托管使用自己的模型 Key 时默认关闭商业计费，不要求连接 Creem，仍可选择本地用量记录。网页没有添加「用户自带 Key」能力的隐含承诺。

账户身份始终取服务端会话或已有 grant 的 owner，不接受客户端提交的 ownerId 作为授权依据。当前 MCP 授权不自动获得使用购买点的权限；后续收费 MCP 需要独立的 `credits:spend` 范围、功能限制及单次/每日上限，旧 grant 保持不变。首期 Web 与既有批处理可完整收费，MCP 新增收费调用在取得这项授权前拒绝。

### 关系型商业账本

为实际托管收款新增 Postgres 表与事务 RPC，不把钱相关状态塞进不断增长的单份 JSON 或浏览器存储。现有书籍、笔记和正文继续走领域服务与原有 CAS。

| 实体 | 主要内容 |
| --- | --- |
| billing_accounts | owner ID、环境、可用/预留、账本序列、争议冻结状态 |
| billing_orders | 本地订单、Creem checkout/order/customer ID、金额币种、商品及价目快照、实际优惠、状态 |
| billing_credit_lots | 每次购买/赠送的来源批次、原始点数、剩余和退款关联 |
| billing_entries | 不可变的 grant/hold/consume/release/reversal/refund_adjustment；关联订单、任务与来源批次 |
| billing_operations | quote、功能、来源版本、模型任务、幂等键、状态、最终回执 |
| billing_webhook_inbox | 已验签事件 ID、内容摘要、处理状态和重试记录 |
| billing_provider_calls | 每次实际请求的尝试 ID、供应商/模型、usage 状态、计价版本和成本状态 |
| billing_outbox | 已持久化的结算、发布、通知或对账工作及租约 |

点数存整数微单位（1 阅读点 = 1,000,000 单位），金额存对应币种最小单位，禁止二进制浮点余额。正常可用与预留余额不能为负。多设备、多实例对同一账户扣点须锁定账户行，在同一数据库事务中核验余额、分配 lot、写 entry 和更新投影。幂等键和供应商事件/订单 ID 均有唯一约束。

账本是额度事实来源，余额是可重建投影。错误用冲正分录修复，不能编辑或删除历史消费。后台调整必须有原因、操作者和关联依据。

所有表启用 RLS，拒绝 anon/authenticated 直接写商业表；账户查询经会话校验的领域 API。事务函数只允许受控服务端角色执行，校验 owner、环境、允许状态和数值范围。管理权限用服务端配置的 Auth user ID 授予，不根据浏览器角色或邮箱后缀推断。

### 报价

报价包含 owner、action、bookId/sourceVersion、输入与上下文策略摘要、priceVersion、精确点数、成本上限和有效期（10 分钟）。客户端只能选择服务端允许的 action 与商品 key，不能指定扣点额、商品价格或最终 owner。

用户实际提交与 quote 不同、来源变化、授权变化、quote 过期则返回重新报价，模型尚不调用。运行中的价目不被新版本更改。已经存在且可复用的结果先检查缓存，命中直接返回，不建立消费。

首期 translation 仍只针对当前支持的翻译方向；当前接口为翻成中文，不因官网多语言就宣称已支持任意目标语言。超长目标段落不截断收费，返回明确限制，后续按完整片段另行设计。

## 6. Creem 付款闭环

1. 登录后由服务端创建本地 pending 订单并绑定 Auth user ID、环境、商品与价目快照。
2. 服务端从固定商品映射选择 Creem product ID，创建一次性 checkout，写入内部 request ID 与最小必要 metadata；返回受信 checkout URL。
3. 用户在 Creem 完成付款。返回页只显示「正在核对付款」，不凭 URL 参数、截图、前端事件或邮箱发放点数。
4. webhook 独立读取有大小限制的原始请求字节，验证 `creem-signature` 的 HMAC-SHA256，随后才解析 JSON。
5. 核对环境、已持久化本地订单、checkout/order/product、状态、币种、数量和经优惠/税费拆分的金额。财务金额字段不能把含税总额与产品未税价机械比较。
6. 在同一数据库事务中去重 inbox、推进订单、写购买 lot 与 grant entry、更新余额。该事务提交后才返回成功。
7. 返回页轮询当前账户的订单状态，只有已核实到账才显示成功；回调晚到、页面关闭都不影响后续到账。

优惠券须在订单快照中有明确策略，核对供应商的真实折扣；100% 审核优惠可产生测试权益但销售收入为 0，不能把标价计作收入。正常用户不能用客户端指定优惠后价逃过校验。

网络超时下不能假设创建 checkout 失败或 request_id 自带幂等保证。保持订单的未知状态，查询或恢复已创建 checkout；没有供应商确认时不盲目重复创建。页面双击复用同一本地 purchase intent。

webhook 至少按「环境 + event ID」去重，并按供应商 order ID 防止不同事件重复发点；同一事件 ID 不同摘要进入隔离。真实订单可由服务端主动检索供应商对账并走同一入账事务，不能另开一条「手动加点」捷径。事件乱序时先读取订单最新事实，退款/争议不能被迟到的 checkout.completed 覆盖。

测试与正式商品、Key、webhook secret、客户、账本和统计完全分开。未知事件不改额度；数据库失败返回可重试错误，已成功的重复事件返回成功。敏感 payload 限制保存字段，不保存卡号、完整地址、Key 或任意 webhook 全文。

## 7. AI 任务、结果与结算

状态：quoted → reserved → running → result_saved → settled → published。终止分支为 failed/released/cancelled；供应商提交状态不明时另标 provider_unknown，禁止自动重发收费模型请求。

- hold 先分配试用 lot，再按购买先后分配购买 lot，其他并发任务不能用同一份点数。
- 现有全局/账号次数、并发、超时和上下文保护继续有效；持有点数不是绕过安全额度的许可。
- 每次模型调用前先分配稳定 attempt ID 并持久化提交状态，记录实际 dispatch 时间。仅建任务或计划请求不计模型调用。
- 所有模型和付费工具调用都必须经过预算，主模型、工具内部模型、搜索、抓取分别记录；内部重试不额外扣客户点数但要记平台成本。
- 结果使用真实稳定段落 ID 与原文版本校验，直译/意译分别保存且标为 draft。校验失败不结算。
- 结果持久保存后写 completion receipt，账本事务消费原有 hold。对结果发布和结算使用持久化 outbox 协调；现有 JSON 文档和关系型账本不是同一次跨存储事务，不能只靠 finally 或内存 Promise 保证。
- 状态查询能触发有租约、有限次数的恢复；只恢复保存/结算/发布，不再次请求模型。正式收款前需有经过重启验收的内部恢复入口，由部署平台周期性唤起，取消后不重启生成任务。
- 崩溃发生在结果保存之后时，根据 completion receipt 补结算或发布；结算完成但发布失败时继续发布同一结果。若最终因原文/授权变化不能交付，写唯一冲正并退回点数，保留供应商成本。
- 15 分钟预留过期只触发核对，不直接放款。确认 worker 已失去提交资格且没有可交付结果后才释放；迟到 worker 通过 fencing token 被拒绝，不能消费已释放余额。
- 用户取消在服务端持久化，以既有任务归属和租约撤销。若完成早于取消，返回真实已完成回执；若取消先成立，后来结果不发布、不结算。

原有逐段翻译 CLI 继续遵守显式 --execute 与最多 20 段：增加整体最大点数和 quote，按实际成功段落结算，不把「购买额度」解释为授权全书翻译。购买、支付或页面浏览不触发模型任务。

## 8. 退款、拒付与迁移

建议售后口径：购买后 14 天内，未使用的购买点可联系客服申请原路退款；部分使用按可退的购买 lot 剩余权益和该订单实际支付情况核算，法定权利与 Creem 实际规则优先。该文案须在上线前核对，不能先宣称已有自动退款功能。

首期退款由运营者核对后通过 Creem 执行；没有让 Agent 或网页用户自动发起实款退款的隐含权限。支持工具先计算、预留该 lot 可退额度并锁定退款意图，再执行供应商操作；提交结果未知时先对账，禁止盲目重复。退款成功事件完成扣回，失败释放退款预留。

对同一订单的累计退款和每个 refund ID 去重。税款、折扣和部分退款按供应商 transaction/order/refund 数据处理，不以退款总额直接除标价换点。拒付或外部退款超过剩余权益时记录待核对损失/债务并冻结新的收费生成，正常余额不写负数，也不清空书和笔记。恢复后通过补偿分录修正，保留完整历史。

书房备份可附只读订单/消费回执，但恢复书籍或导入他人的备份不能增加商业余额。购买点绑定本实例，不能承诺在别的自托管实例兑换；完整运营迁移须另外备份恢复账本数据库并核对总账。免费阅读数据导出不依赖购买额度或账户有无争议。

## 9. 真实统计

### 用户侧

可用 = 已发放 - 已消费 - 退款/撤回调整 - 有效预留；已消费与预留分开。用户可按功能和日期查看消费，点击回到本人相应结果；他人书名与内容不进入该接口。

### 运营侧

先做一个权限保护的「经营与用量」页，提供今日/7 天/30 天/自选日期、币种、环境和来源筛选。无数据时显示暂无数据，样例只出现在明确标注的设计稿或沙盒。

| 指标 | 真实口径 |
| --- | --- |
| 已支付销售额 | 已核实订单的实际商品金额，按币种分组；不含代收税，不把标价或 pending 算收入 |
| 买家支付总额 | 含税实际收取金额，另列税费，和商品销售额分开展示 |
| 退款、争议、Creem 费用、实际结算 | 从已确认财务事件/供应商对账取得；缺字段则标待对账 |
| 付款用户/订单数 | 当前筛选范围内去重 owner/供应商订单；100% 优惠与试用单独列 |
| 已卖/已赠/已用/已预留点数 | 分来源汇总账本，不混成同一个收入数字 |
| 实际 AI 调用数 | 稳定 attempt 的真实 dispatch 去重，含失败请求；缓存/只读工具另列 |
| 服务交付成功率 | 已持久化并可取回的成功任务 / 终态任务，运行中单列 |
| token 用量 | 供应商/SDK 返回值；按非缓存输入、缓存输入、输出分别汇总；缺失显示未知 |
| 成本覆盖率 | 有完整 usage 且能计价的调用 / 全部已提交调用；失败和工具内部调用都计入分母 |
| 模型成本 | 供应商报告用量 × 对应生效费率，标「按用量计价估算」；供应商账单核对后才标已对账成本 |
| 毛利估算 | 已核实净销售 - 退款 - 已知支付费 - 覆盖范围内模型费用；缺成本/支付费就标不完整，并列未知调用 |
| 购买转化 | 已产生首笔实付购买的用户 / 同窗口内请求过收费报价的用户；明确不是全站转化率 |
| 阅读活跃与留存 | 复用前台有效阅读事件，用户主动阅读与 Agent 访问分开；不把它当成掌握指标 |

预付额度销售先显示为收款及未使用权益，不能把全部充值立即称为已实现会计收入。点数消耗的权益分摊与现金收款分栏，正式会计收入确认由相应政策决定。不同币种不直接相加；换算必须保存参考汇率与时间，默认原币展示。

### 计量字段与隐私

每次 attempt 保存 owner、operation/attempt ID、功能、调用发起者（user/agent/companion/system）、模型、提交/结束时间、状态、usage、费率版本、费用币种和 costStatus。书籍仅保存必要内部 ID/版本；运营默认统计不展示书名、正文、提问、回答、私人笔记或登录凭据。

成本状态至少区分 reported_usage_rated、partial、unknown、invoice_reconciled。未报告 tokens 不填 0，不拿 UTF-8 字节估算回填。DSH 单条 assistant/message usage 只算一次；缓存输入与总输入去重，reasoningTokens 若已含 output 不再相加；attempt stream 和工具子调用不能漏计或和主事件重复计。

Search/Fetch 的额外请求费根据调用时生效规则单独记录，不默认已经包含在模型 token 费中。若当前 SDK 没有完整的子调用 usage，就明确计量覆盖缺口，不发布「精确利润」。暂停/取消、生成成功但校验失败、未交付的供应商费用由平台承担并可统计。

统计从不可变账本、已持久化操作和调用记录聚合，不依赖页面 console 或仅本机日志。使用 UTC 存储；运营报表明确显示所选时区，默认 Asia/Shanghai，半开时间窗口，避免午夜重复。个人阅读日历继续沿用用户自己的时区。

## 12. 交付顺序与验收门槛

先完成领域账本与假供应商测试，再接真实沙盒 checkout/webhook，再接两种收费文本能力与计量，再交付账户/运营界面和官网政策，最后验证正式配置与审核。详细代码任务另写实施计划。

必须覆盖的故障与结果：

1. 同一成功 webhook 重放 10 次只到账一次；不同事件引用同一 order 也只到账一次。
2. 无签名、错误环境、未知 product、错误币种、篡改 userId、税费拆分错误均不发点。
3. 用户未返回网站、webhook 先到或晚到、成功页刷新都能恢复同一已核实订单。
4. 同时发起两个超出余额总额的请求，最多一个成功预留；多标签页和多实例一致。
5. 同一操作幂等提交只生成/消费一次；相同幂等键不同输入返回冲突。
6. 模型失败、JSON 无效、原文变化、取消、保存失败不消费购买点；供应商可能发生的成本保留。
7. 在预留后、模型提交后、结果保存后、结算后、发布前各模拟进程中断，恢复不重复请求模型、不重复扣点、不永久锁住余额。
8. 退款重放、部分退款、退款先于 checkout、拒付后迟到成功事件不会重新授予已撤回权益。
9. 试用、100% 审核优惠、平台赞助和正式实付订单在余额及财务报表中分别显示。
10. 用户 A、匿名或未授权 Agent 不能读取用户 B 的余额、订单、书名；非管理员不能看运营报表。
11. 缓存结果、翻页、设置、导出、自动气泡都不能扣购买点；MCP 旧授权不能绕过收费。
12. 缺失 usage 显示 unknown；缓存 tokens 不重复计；统计总额与底层分录可核对。
13. 在 390/768/1440px 验证公共价格、账户账单、购买返回和错误状态；正文无付费浮层干扰。
14. 自托管未配置 Creem 时免费阅读、本地 Key、原有导入导出和 MCP 不受商业功能牵连。
15. 在隔离数据完成全部单元/HTTP/数据库并发测试；持久联调证据归当前 Supabase Auth 查得的默认测试账户，绝不读取其他真实用户资料。
16. 当前提交 CI 测试与构建通过、代码审阅后按仓库约定 PR 合并；不建立 Preview 部署。合并后核对同提交 Production 和线上验收，分别记录状态。

验证等级分开记录：设计审阅、单元/假供应商、真实 Creem 沙盒、真实模型用量、正式账户配置、正式发布、真实付款到账。前一等级不冒充后一等级。真实付款或退款涉及实款，由用户在明确金额与用途后完成相应操作。
