# 阅读缓存与离线阅读设计

日期：2026-10-29。状态：用户于 2026-10-29 确认实施与完整发布链路，当前按此设计交付。本文件不代表功能已实现、发布或验收。

## 目标与已确认范围

用户希望充分利用缓存加速，并已明确要求同时支持断网阅读。读者再次打开书、前后翻章和断网续读时，应尽量复用设备上已经保存的内容。

本轮设计让读过的章节自动保存，也允许主动下载整本书。断网后可以打开书页并恢复阅读位置，重新联网后核对内容。离线阅读保留现有原文、直译和意译的独立归属与真实状态。未下载章节不能冒充空白正文，未生成译文不能靠补生成实现离线。

离线期间可以调整排版和留下笔记草稿。首版不增加离线高亮或评论发布队列，不增加离线模型任务。已有生成结果可随对应章节保留，但不自动下载听读音频、原始上传文件或私人对话。整本书下载只读取现有正文，不生成译文，也不消费阅读点数。

## 当前实现与实际观察

`app/reading-book.mjs` 已经合并同一章节的并发读取，并在当前页面内保留已加载章节。刷新后这部分正文没有持久缓存。`app/reader.js` 在连续阅读时会预取下一章，翻页模式则没有相同的预取路径。

`server/chapter-read-store.mjs` 已经把正文编译成按内容哈希保存的章节快照，并通过持久写入隔离与发布前检查避免混合修订。应沿用这套快照。`deploy/hosted-store.mjs` 每次读取文档仍请求持久存储，适合只对不可变章节补充有容量限制的进程缓存。

`contentVersion` 主要标识原文修订。个人译文可以在原文版本不变时更新，因此客户端不能只用原文版本号判定整章是否仍然有效。现有章节哈希包含原文与已保存的译文，可以作为新的缓存依据。

本轮从当前执行环境匿名读取正式站公版《爱丽丝梦游仙境》，得到以下样本。时间是单次请求从发出到完整接收的耗时，不能视为稳定性能基线。

| 请求 | 样本耗时 | 实际响应 |
| --- | --- | --- |
| 阅读页 | 1328 ms | `private, no-store` |
| 带内容哈希的阅读脚本 | 1272 ms | 325007 字节；`public, max-age=0, must-revalidate` |
| 正文读取，第一次 | 1010 ms | 87411 字节；`private, no-store` |
| 相同正文读取，第二次 | 630 ms | 仍传输 87411 字节；`private, no-store` |

这些观察支持优先减少重复正文传输与静态资源复查，尚不能证明实施后的提速幅度。

## 方案取舍

只延长网络缓存并增加内存缓存，改动较小，但不能可靠覆盖关页后断网重开。让 Service Worker 统一缓存全部接口，容易把账号状态、阅读记录和收费操作一起带入过期恢复逻辑，也不符合本项目的数据边界。

建议采用一条与现有服务边界吻合的路线。Service Worker 只负责公开界面资源和不含私人数据的离线页面。IndexedDB 按账号保存明确读取过的章节。领域服务继续负责权限与内容修订。用户已确认离线需求，并在设计交付后授权按此路线实施与发布。

## 缓存如何配合

### 界面资源

构建时从现有公开发布清单生成离线资源清单，绑定本次发布与文件摘要。阅读页需要的脚本、样式和四种界面语言一起准备。网络字体不能成为显示正文的前提。离线书房只列出设备上实际保存的书和章节。

带内容哈希的静态文件使用长期缓存。尚未带版本的延迟模块不能直接设为一年有效，必须随整组离线资源绑定发布。入口 HTML 与 Service Worker 保持可检查更新。私人接口继续禁止共享缓存，Service Worker 不拦截保存、登录、授权、付费或生成请求来伪造成功。

新资源完整准备后才允许下一次页面启动采用。正在阅读的旧页面保留配套资源，不能在激活时混用两次发布的模块。离线资源损坏时停止宣称可离线，联网后重新准备。

### 正文与本机书库

新增受现有身份检查保护的阅读清单读取，返回书籍元信息、章节结构、来源修订、快照标识和各章内容哈希。在线首次打开可继续由现有正文响应携带清单，避免为了建立缓存额外增加一次等待。已有本机内容时先用清单核对，再只下载变化的章节。

本机键包含站点数据格式版本、服务端确定的账号范围、书籍 ID、章节 ID 和章节哈希。游客公版内容与登录后的个人译文分别保存。不能用“这本书是公版”推断包含个人译文的响应可以跨账号共享。

章节先通过现有稳定段落 ID 与结构检查，再校验内容摘要并写入事务。页面中刚完成翻译的章节立即替换对应本机快照。另一个页面的更新通过当前清单发现。原文、译文和来源状态一起更新。未完成的写入不能被标为已下载。

读过的章节自动保存。整本离线阅读由读者点击“保存到此设备”发起，逐章下载同一快照的现有内容。下载支持取消、失败后续传和按章节展示实际完成范围。全部章节与必需界面资源通过检查后才显示“可离线阅读”。下载期间快照变化，则重新核对清单并复用未变化的章节，不能把混合内容标为完整下载。

默认正文容量上限建议为每个站点 100 MiB，由实施者结合实际样书核验。自动缓存按最近使用淘汰。主动保存的书保持固定，不静默淘汰。额度不足时停止新下载并提供管理入口，不删除未同步草稿。音频不计入本轮自动缓存范围。

### 服务端热点章节

在现有章节快照读取周围增加有容量限制的进程内缓存，并合并同键并发读取。建议起始容量 32 MiB，按实际编码字节计量并淘汰最近最少使用的项。返回对象隔离可变引用，避免某次请求污染缓存。

缓存键必须包含账号范围、书籍和章节哈希。命中后仍执行当前身份检查、持久清单读取和现有 `assertCurrent` 检查。可变清单、授权与阅读记录不依赖进程缓存判断新鲜度。冷启动和不同实例之间的正确性仍由现有持久快照保证，不增加 Redis 等外部服务。

### 预取

复用现有章节加载合并逻辑，补齐翻页模式。当前正文可读后，仅在页面前台且网络允许时空闲预取下一章。并发上限为 1。开启节省流量、网络很慢或页面进入后台时，以及切书、换账号时，暂停或取消。整本下载属于读者明确发起的独立任务。

预取只读已有内容，不调用模型，不产生用户阅读时间，也不把预取章节记成已读。

## 离线启动、权限与恢复

离线页面不能继续依赖 `app/reader-api.mjs` 当前的在线会话请求才能启动。增加独立的“本机阅读”模式，使用上次成功在线确认且没有退出的本机账号范围，读取该范围内已经保存的内容。它不是云端登录凭据，不写入伪造会话，也不保存访问令牌来绕过登录。

网络不可达时可以进入本机阅读。在线明确返回未登录、拒绝访问或书籍已删除时，不能自动退回旧副本绕过结果。对应本机内容转为不可访问，并清理书籍缓存。重新登录后由服务端身份和清单决定是否可以重新下载。离线期间无法核实新的远程撤权，这一限制需要在首次“保存到此设备”的说明里交代。

退出账号或确认账号变化时，先停止下载并使在途任务失效，清除该账号的正文缓存与离线目录，通过跨页面事件清空已展示内容。清理失败也必须先撤销本机可访问范围。以后启动不能仅凭残留 IndexedDB 行恢复。未同步笔记沿用现有按账号隔离的草稿保留规则，不作为普通缓存删除，也不能在另一账号中显示。

离线重开默认恢复到本机最后实际阅读的位置。进入本机阅读后的所有网络写入保持关闭。笔记明确为本机草稿，联网并确认身份后由用户提交，不能后台自动发布。阅读位置与现有有效时段可以在本机保留待确认记录。只记录实际前台阅读，后台和预取仍不计时。

重新联网后先确认当前身份，再核对正文修订，最后按原有版本冲突规则提交待同步位置与时段，重试使用相同标识。另一设备已有较新位置时保留双方候选，让读者选择续读点。不能直接用“最后写入者覆盖”消除冲突，也不能重复累计时长。原文更新后，待提交记录须先走现有锚点解析。无法映射的内容保留待处理，不猜位置。

## 页面反馈

界面沿用阅读器现有层级。正常缓存命中不弹提示，不常驻命中率或容量统计。“保存到此设备”和清理入口放在书籍操作中。本机书房允许读者查看已下载范围。

断网后用一条短状态说明“离线阅读”。未下载的章节显示“这一章还没保存到此设备”，并保留已下载章节的入口。下载失败或空间不足只在操作处反馈。取消不影响已保存正文。模型操作在离线时说明需要联网，不排入后台自动收费任务。

界面取舍按 `design-judgment` 的功能减法执行：优先让正文和可用范围清楚，技术指标留在诊断里。以上是交互设计要求，尚无正式界面或真实画面验收。

## 验收与性能口径

性能验收分别记录首次打开、在线重复打开、断网重开、预取命中翻章和缓存缺失翻章。使用同一公版书、同一设备和相同网络条件，各取多次样本，报告中位数与较慢请求，连同正文请求数、传输字节和缓存命中情况保存。正式浏览器验收使用匿名公版数据。确需持久私人验收数据时才使用项目指定账号，不读取其他真实用户数据。

功能必须实际验证以下场景，不能用设计稿或纯模型测试代替：

1. 在线保存整本公版书后断网，关闭并重开阅读页，仍可恢复位置并翻遍已保存章节。未保存章节给出真实状态。
2. 原文版本不变而个人译文变化时，在线重新打开取得新译文。其他章节仍可复用。原文修订时不混用旧锚点和新正文。
3. 隔离身份 A/B 的缓存、下载任务和页面互不显示。A 的迟到请求不能写入 B 的书库。退出与跨页面换号即时清理可访问内容。
4. 离线后恢复网络，身份变化、远程新位置、重复重试与原文迁移均不覆盖未提交内容，不重复累计时长，不自动发布草稿或发起模型任务。
5. 存储不足、浏览器清理、损坏缓存、下载中断与新旧 Service Worker 并存时，状态与实际可读范围一致。
6. 保留文字选择、段落稳定 ID、双译切换与排版体验。离线缓存或预取不产生阅读活动。

目标是缓存命中的正文无需重复下载，断网阅读路径没有外部网络依赖。缓存命中后翻章的本机处理目标可先设为中位数 100 ms 内，作为待实测的工程目标，不能写成已达到。首次从未下载过的正文仍受网络和服务端耗时影响。

Chromium 自动化、Safari 与真实 iPhone 的离线重开和存储清理要分别记录结果。没有设备证据的部分保持未验证。浏览器可能清理站点存储，因此“已保存”只反映当前实际文件，不承诺永久留存。完整书房导出仍保留独立入口。

## 留给实施者的选择

实施者确定模块拆分、IndexedDB 库表名称、离线资源清单生成细节和测试夹具。继续使用现有构建、领域服务、稳定 ID 和公开发布边界。100 MiB 与 32 MiB 是本设计建议的起始值，实施时应记录调整依据。既有存储键、未同步草稿与原账号数据不得因引入缓存而清空。

实施按本仓库的工作分支、测试、审阅、PR、CI 与正式发布约定完成。
