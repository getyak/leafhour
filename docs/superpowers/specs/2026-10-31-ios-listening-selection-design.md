# GET-347: listening that follows the text, paragraph-first selection

Start from the visible sentence, keep a real local speech cursor, highlight the sentence currently spoken, and follow its current word when it leaves the readable viewport. Pause/resume keeps the cursor; speed/voice changes restart only the current sentence. Explicit “start here” retargets a moved reading position. Resume state is account/book scoped in ReaderState, with source version, layer text fingerprint and the corresponding viewport checkpoint; stale results never map translation offsets to original offsets.

Use AVSpeechSynthesizer's actual willSpeakRange callback and NaturalLanguage sentence tokenization. Never use a timer to simulate audio progress. Queue one passage, continue sequentially through the current book, and release audio on pause/stop/interruption/background. Translation view reads its selected actual layer; parallel view follows the layer at the reading point; missing translation retains the original. No model, cloud audio or billing call.

TextKit uses drawing-only sentence backgrounds so speech never replaces native selection or rebuilds the text per word. Respect paged geometry, Unicode and Markdown source/display mappings. PDFKit uses separate highlightedSelections on the original page. Manual scroll/page turns/selection suspend following, and “back to listening” restores it. Initial play returns to the book so its highlight is visible; quiet footer controls allow pause/resume and settings without extra permanent height.

Text uses a bounded first-selection long-press recognizer and UIKit edit menu while retaining every system recognizer/delegate. It only handles an empty selection on an actual passage glyph; existing ranges, handles, double taps, VoiceOver and links remain native. Dynamic failure relationships avoid permanent rewiring of framework recognizers. The stable paragraph/layer is selected without moving its viewport; Copy and custom actions use the live range. PDF retains its separate native observation path and extracted text boundaries. Do not expand a handle drag, an existing selection or a link. PDF uses its extracted paragraph boundaries and never fabricates OCR. Keep a menu action for explicit paragraph selection. No custom always-visible selection overlay.

Alternatives rejected: paragraph-only highlight (cannot identify the heard sentence); guessed timing (can drift from speech); replacing the complete system selection interaction (loses native handles and editing). The agent chooses the existing system engine and native selection with small, typed adapters.

Validate actual spoken substrings/callback ranges, pause/voice/cold-resume, stale callbacks, source/translation/Markdown/Unicode, selection without scroll jumps, source anchors, native copy/handles/page-turn precedence, paged and scroll following, and PDF page mapping. Use isolated synthetic fixtures. Distinguish system callback/Simulator evidence, audible physical-device experience, CI, release and tester installation.


Native lifecycle finding: changing the selected range during the system word-selection gesture is overwritten at lift; rewriting it again closes the native menu. The bounded Text first-selection path avoids that word cache entirely. It uses the public UIEditMenuInteraction API with the responder chain's suggested actions, not a custom drawn menu. PDF long-press menu acceptance is separate from the Text UI proof.
