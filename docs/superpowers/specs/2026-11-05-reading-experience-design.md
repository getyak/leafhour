# iPhone 阅读体验改进

日期：2026-11-05。用户明确要求深度实现，并由独立 Agent 设计、测评和评分；本次确认主要针对 iPhone App。共用服务仅修改本次功能依赖的部分。

## 目标与取舍

新书添加后可立即找到并阅读；刷新不遮住已有书；阅读先展示可用内容，其他工作逐步完成。AI 和翻译不能阻挡书页出现。沿用现有原生阅读器、领域服务和账号隔离，选择本地优先及有界异步处理。仅用动画掩盖等待不能解决主线程开销；重做整套阅读引擎会增加位置与选文回归风险，本次不采用。

用户已授权直接实施，设计细节由执行者判断并记录，不增设设计确认。实际验证、合并、服务发布、TestFlight 和真机验收分别记录。

## 需求与验收

| 编号 | 需求 | 可观察的验收条件 |
| --- | --- | --- |
| R1 | 书架刷新稳定 | 保留已有卡片与滚动位置；成功相同快照不反复发布；失败保留书架；同账号元数据变化不重置书房 |
| R2 | 新书排序直观 | 默认按最近阅读或添加的实际时间排序，新导入立即靠前；固定项保留优先；用户主动选的其他排序不被偷偷改写；离线和重启一致 |
| R3 | 本地优先打开 | 本地完整副本不等待网络、上传、记录同步、封面或AI；同步后的同原件不再次下载才可阅读；版本不一致不可混用 |
| R4 | 首屏与后续分开 | 先载当前位置需要的正文和资源；后续校验、读取、排版可取消且不跳位置；大书首屏耗时有记录；损坏内容可恢复 |
| R5 | 每书AI阅读导览 | 每本书提供默认导览入口与非阻塞生成；说明阅读方法和必要背景；标AI、版本及取样边界；缓存复用；失败可重试，不伪造结果 |
| R6 | 每次回复三个追问 | 每个成功的AI回复附三个非空、不同且有上下文的追问；点击即走普通发送流程；生成中防重复；历史回复也可用；错误不伪装答案 |
| R7 | 目录内全文搜索 | 搜索章节正文，按真实目录章节分组，显示片段与命中位置；点击回到精确段落；标题搜索与页码仍可用 |
| R8 | 目录内AI搜索 | 用户显式发起语义问题；结果带实际章节与可核对定位；模型不得虚构可跳转位置；取消、无结果、离线与失败清楚呈现 |
| R9 | 下拉加书签 | 阅读区域向下拉达到阈值并松开添加当前位置书签；横向翻页/选文/普通滚动不误触；重复添加幂等并提供明确按钮及VoiceOver入口 |
| R10 | 书签显示与配置 | 右上角显示当前位置书签；点击可改色、命名或移除；颜色有文字；目录/列表可返回保存的稳定位置；重启与账号隔离 |
| R11 | 翻译显式开关 | 仅用户开启后跟随当前阅读位置向下翻译；每次范围有限，跳章/退后台/关闭后停止后续提交；不遍历整本书 |
| R12 | 真正取消翻译 | 叉关闭可停止当前请求和后续任务，取消信号传至供应商；迟到结果不得发布；失败取消不伪称已确认；幂等/计费恢复不丢 |
| R13 | 一行语言意图 | 用户直接写目标语言，默认英文；自动识别原文；不要求源语言选择；歧义、相同语言或不支持的目标给出可修改提示，不猜另一个目标 |
| R14 | 可视化翻译模板 | 原版、译文、对照三个缩略预览可点选；缺译文保留原文并标状态；切换不启动生成也不丢位置 |
| R15 | 对照实时配置 | 对照布局配置实时反映在模板和实际正文；窄屏、动态字号、横屏仍能读；原文、直译与意译归属独立 |
| R16 | 每项独立测评 | 各领域由独立Agent设计及审阅，保存测试证据与评分；95为目标，未知和未测不得算通过，不以自评分代替真机验收 |

## 共享约束

- 原文、两种译文、AI内容与用户书签/笔记分别保存；沿用稳定段落ID、原文版本和账号隔离。
- 不读取其他真实用户的数据，不写真实账号测试垃圾，不提交书籍、运行数据或密钥。测试使用合成或已有公版隔离样本。
- 原件留在本机；本机AI工具仅发送本次需要的摘录。无额外整书模型调用或站外推送。
- 所有新交互有44点触控入口，支持减少动态和动态字号；手势不作为唯一入口。
- 不安装或清空用户应用；模拟器、真机与线上证据分开。提交只包含本任务改动。

## 评分

每个需求按功能30、交互25、性能25、边界与可访问性20计100分。自动化通过、实际画面、实测性能、设备体验必须分别列证据。未验证项不折算成通过分。单项存在数据错误、越权、无法取消的持续生成或阻塞首屏时，不能验收。报告给已验证得分和未验证上限，不能补写95分。

## 官方实现依据

SwiftUI懒容器仅构建需要的视图，但仍需测量数据解码和正文布局：[Apple滚动容器性能](https://developer.apple.com/documentation/swiftui/creating-performant-scrollable-stacks)。Swift任务取消为协作机制，需在工作边界主动检查，并将信号传入网络请求：[Swift并发](https://docs.swift.org/latest/documentation/the-swift-programming-language/concurrency/)。Node实现依据项目实际支持版本，不能直接使用仅新版本存在的请求信号属性。
