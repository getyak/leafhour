# Web 交互与视觉精修

日期：2026-10-15。范围以公开仓库 `origin/main` 的现有功能为准。原工作目录正在开发的个人书房功能保留，不混入本次提交。

## 目标与分工

用户要求逐项列出官网和阅读器的可点击功能，使用 frontend-design 深度优化，并由三个独立 Agent 分别盘点、实施、评分。目标是每项设计体验达到 96 分以上。评分是按公开标准执行的专家检查，不代表用户研究或普遍满意度；未实测的路径保留未验收状态。

- 盘点：`docs/web-interaction-inventory.md`，控件、条件状态、作用、设计建议、验证覆盖。
- 实施：官网、书房、登录、阅读器、旁注、分享、氛围和听读的共同交互与局部缺陷。
- 独立复核：`docs/web-interaction-review.md`，按功能给出证据、评分和剩余限制。

## 设计判断

保留现有纸页、雾绿书架和布面书封。色彩沿用雾绿 `#e9eddf`、纸白 `#faf9f5`、墨绿 `#2b3c30`、动作绿 `#385844`、辅助文字 `#586553`；夜间用深绿 `#202b23` 和浅纸文字 `#e6ebde`。正文沿用 Songti 与 Georgia，界面使用系统中文无衬线字体。

官网的阅读空间是视觉中心。正文页以文字为中心：可点击区域大小与图形尺寸分开，主要操作明确，次要操作保持安静；边框只表达分组、输入和选中状态。悬停说明可操作，按下说明已接收，忙碌避免重复提交，完成与失败都有明确去向。焦点必须可见，弹层必须能返回打开处。图案与运动不能妨碍阅读，低动态偏好和夜间主题继续生效。

## 实施顺序

1. 建立公开 main 的独立工作副本，保留原目录未提交内容，运行修改前检查。
2. 盘点所有渲染入口与动态控件；区分源代码覆盖、真实点击和外部服务结果。
3. 在全部页面接入统一交互层，逐页修复发现的行为问题，维持既有内容和数据边界。
4. 实测桌面、390px 手机、键盘、夜间与低动态；测试正文选择、弹层关闭与恢复、语言切换、缺译文、分享及未配置服务。
5. 独立评分后返修，运行完整测试、正式构建与发布检查。
6. 按项目授权提交、推送、创建 PR，等待检查通过并正常合并；核对远程提交和已有生产发布流程。

## 数据与验收边界

本次界面检查使用公版样书与隔离的本机环境。不自动翻译整书，不发送邮件，不发起付费生成，不创建推送。真实账号、上传资源与个人阅读数据不进入源码、截图或评审记录。服务未配置时验证明确提示和恢复方式，不能把该检查写成供应商端成功。
