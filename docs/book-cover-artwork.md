# Original public-library cover artwork

The user approved four original literary printmaking sample covers on 2026-10-28 and requested the complete live 64-book public catalog, including Japanese users. The visual system uses restricted inks, tactile paper and a distinct content-related silhouette for each edition. The top paper field is left free for native language-aware titles and author attribution.

The checked-in WebP files are original Leafhour cover illustrations, not facsimiles of source editions or publisher covers. The source book, source language, selected translation, author/translator/editor roles and public-domain notices remain owned by the existing content service. A localized Japanese cover title does not claim Japanese reading text. Public edition IDs and chapter anchors are unchanged. Private imports retain their actual metadata and existing fallback binding.

Artwork generation uses the built-in image_gen tool, one call per distinct artwork; four approved originals are reused. Exact prompts and per-edition visual choices are in [prompts.json](design/2026-10-28-book-covers/prompts.json), with the four exact approved prompts in [approved-prompts.json](design/2026-10-28-book-covers/approved-prompts.json). No image generation happens in the reading application. Generated originals remain preserved locally; optimized final assets and their SHA-256 records are versioned here.

The exporter is tools/export-book-covers.mjs. It accepts --originals followed by the directory of preserved PNG originals, validates 2:3 geometry, and writes 320px and640px WebP variants at quality82. Each variant URL carries its own SHA-256 prefix so changed artwork cannot silently reuse a stale cache URL. A normal export refuses an incomplete catalog. The development-only --partial switch explicitly leaves the manifest incomplete, which cannot pass the coverage tests or be claimed as released.

app/book-cover-artwork.mjs contains only exact edition IDs and same-origin static URLs. Native cover text lives separately in app/book-cover-labels.mjs; its language decisions and sources are documented in [book-cover-localization.md](book-cover-localization.md). The shared renderer ignores arbitrary image URLs in book metadata. It keeps readable text on failed images and uses responsive sources, lazy loading and decoding to avoid a full-catalog image download at first paint.

The [design specification](superpowers/specs/2026-10-28-illustrated-book-covers-design.md), [implementation plan](superpowers/plans/2026-10-28-illustrated-book-covers.md) and [renderer verification](verification/2026-10-28-book-cover-renderer.md) record the implementation scope and checks. Acceptance evidence is maintained in the [delivery record](verification/2026-10-28-illustrated-book-covers.md). Asset generation, passing local checks, merged PR, Production deployment and real browser acceptance are recorded separately. Until that record confirms them, generation does not establish deployment.

Localized public display titles, volume identities and author names are included in local shelf search through an optional pure search-text provider. The domain filter keeps original book objects and does not index private books with public labels. The existing portal compiler emits a separate shared cover entry under the unchanged per-entry size limit, so all UI owners retain one language and cover-painter identity.
