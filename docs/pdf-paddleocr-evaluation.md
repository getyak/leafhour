## 需要避免的三项误判

**结构化结果不等于正确的阅读结构。** `normalizePaddlePage` 按供应商数组顺序保留块文本、类型、坐标和 `providerOrder`，并过滤部分页面装饰；它没有依据 `providerOrder` 重新排序或建立“脚注属于哪段”的关系。`makeBook` 把块转成段落并保留类型和坐标。完整 OCR 可能改善复杂版面，仍需核对实际正文，而非只看供应商 Markdown 或返回页数。

**直接 OCR 不自动继承原生目录。** 当前只有 `auto` 准备阶段读取 PDF outline。直接路径根据识别块中的标题及有限规则建立章节；不能建立时，仍按 30 段自动分组。改用 OCR 可能失去原 PDF 的书签边界，章节质量应纳入对照。

**同源去重不是候选版本管理。** 导入任务按账号和原件摘要去重，不把 `mode` 纳入身份。同一账号先上传 `auto`、再上传 `ocr` 会复用原任务；书房 `importExtracted` 也保留同源已存正文，不静默覆盖。原生段落 ID 来自原件摘要/序号，OCR 块使用 UUID，新的识别结果不保证 ID 相同。既有正文、评论和划线应留在原版本，不能凭“同一 PDF”把新结果覆盖到旧锚点。本次两个路径使用独立内存存储及捕获出口，避免这类污染。

依据：[规范化](../server/paddleocr.mjs#L17)、[章节与 ID](../server/document-import.mjs#L48)、[同源任务](../server/book-ingestion.mjs#L15)、[书房导入与独立校对版本](../server/library-service.mjs#L237)。

## 离线实验：能复现筛选限制，不能评定 PaddleOCR

运行 [离线工具](../tools/evaluate-pdf-routes.mjs)：

```sh
node tools/evaluate-pdf-routes.mjs --out <新建的登记产物子目录>
```

只生成三份各一页的合成英文 PDF，内容由工具生成并以 CC0-1.0 提供；不接收外部原件或真实供应商参数。单栏用真实文字层，扫描样本用本机生成的栅格图片，复杂样本包含双栏及底部脚注。字节与 SHA-256 在两条路径之间一致，每个路径各执行一次。栅格字体可能随平台变化；跨机器重跑以各次原件摘要为准，不要求与本机截图字节相同。

工具使用真实 PDF.js 原生检查与现有导入编排；供应商为内存假实现，返回醒目的 `MOCK OUTPUT ONLY`，书房出口只捕获结果。临时数据不写账号书房。识别质量、真实供应商延迟、账号额度和账单字段全部为 `null`。

| 合成样本 | 原生检查要求 OCR | `auto` 假供应商页数 | `ocr` 假供应商页数 | 观察 |
| --- | --- | ---: | ---: | --- |
| 普通单栏 | 否 | 0 | 1 | 文字直接提取；只证明本样本不需要分流 |
| 纯图片扫描 | 是 | 1 | 1 | 没有文字层，转入假供应商 |
| 双栏与脚注 | 否 | 0 | 1 | 预期 `L1,L2,R1,R2,F1`，实际 `L1,R1,F1,L2,R2`；顺序错误仍放行 |

各路径原件字节核对、逐页覆盖和未校对标记通过；假识别路径保存了假 raw 结果。真实 OCR 页数 **0**，真实书房写入 **0**。JSON 中的毫秒数只测本地编排，不能比较云服务速度。此样本只证明存在一个漏检案例，不能估计真实书籍漏检率。

机器证据：[离线结果 JSON](verification/fixtures/get209-offline-routing.json)。生成器使用 [pdf-lib 官方 API](https://pdf-lib.js.org/docs/api/classes/pdfdocument)，测试通过 [PDF.js 原生 API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html#getTextContent) 读取；不安装 OCR 模型。

## 真实 A/B：待满足的条件与采集规则

**当前阻塞：没有已核定的供应商免费权限及明确费用上限。** 已具备可外发的合成样本；没有已核定许可的真实样书集合，也没有真实 PaddleOCR 质量结果。历史私人扫描书验收只作实现背景，不读取、不重用、不推导本次账号额度，也不能代替三类版面对照。

1. **先冻结授权与样本。** 由操作员提供当前账号/模型可用免费额度的凭据、超额处理规则和总费用上限；默认费用上限为零，不能证明零费用时不提交。记录服务接收方、授权时间及最多三种版面、每份最多两页的许可来源。只能使用合成或许可明确的公开文件；本轮不授权私人书籍。
2. **先固定参考，再提交。** 在看到识别输出前人工确定逐页文字、块边界、期望顺序与脚注关联，保留图像依据、版次、样本 SHA-256、PDF/印刷页对应。中文目标需补许可明确的中文样本，不能拿英文合成结果代替。
3. **隔离两条路径。** 同一份原件进入各自独立实验存储，只捕获候选；冻结代码、SDK、模型字符串、选项、批次大小和超时。每份每路径只提交一次，总识别最多 12 页；`auto` 只计实际筛出的页，`ocr` 计全部页。提交前累加最坏页数并核对余额，先保存意图；结果未知只查回原 requestId，不重新付费提交。
4. **分别记录实际证据。** 保存实际外发页映射、handle/requestId 的安全摘要、原始与规范化结果摘要、端到端/排队/执行/本地整理耗时（不可得时为空）、真实识别页数及服务额度或账单前后凭据。前后余额有并行调用时不将差额全部归本实验。页面缺失直接判完整性失败；正文漏段、重复、顺序倒置和脚注错绑逐项列出。CER 用逐页 Levenshtein 编辑数/参考字符数，保留原始及仅空白归一化两种口径，不能用 CER 掩盖顺序错误。
5. **先作有限结论。** 用下面表格比较，再决定是否提出独立入口改版。三类至多六页只能支持有限样本判断；若结果冲突或人工核对不足，保留默认策略，不宣布全量识别更好。不得依据报告存在或一次免费活动就关闭核心验收。

| 待采集项 | 每个 sample × mode 的必要字段 |
| --- | --- |
| 来源与授权 | sampleId、许可/来源 URL、授权凭据引用、原件 SHA-256、页数、参考版本、整份或筛选页外发范围 |

## 路径取舍与暂定建议

| 路径 | 可预期收益（推断） | 代价及尚未验证内容 |
| --- | --- | --- |
| 自动分流 | 干净文字页不必外发识别，避免引入该次识别错字；OCR 实际页数可能更少 | 维持两套提取逻辑，现有规则漏掉复杂阅读顺序；有文字层也不证明正文完整 |
| 完整 PaddleOCR | 正文都来自同一种解析输出，可能改善双栏、扫描、页眉和脚注的结构一致性 | 全页外发、页数增加、队列与额度压力、潜在错字；现有 outline 路径差异仍需处理，未必更准确或更快 |

后续可把“完整解析”作为扫描或复杂版面的候选，把“快速提取文字”作为干净单栏的候选入口；开始前用普通语言说明外发范围和取舍。**这是待真实 A/B 验证的产品建议，本轮没有实现入口或改变默认策略。** 无论选择哪条路径，继续沿用分块、后台批次、失败查回、源文件指纹、来源页码、原始结果及未校对状态，禁止覆盖旧正文与个人锚点。

具体测试、独立审阅与交付状态见 [验证记录](verification/2026-10-21-get209-pdf-evaluation.md)。
