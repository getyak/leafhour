# 日历与退出的条件界面验收

2026-10-16，当前工作分支。日历重新载入、当日书籍、逐条记录、退出失败与成功已在1440×1000和390×844实际操作，各21项、合计42项断言全部通过。范围对应C06、C08、C09、C10、C14；不把隔离日历记录写成真实账号数据。

浏览器只使用共享公版《爱丽丝梦游仙境》的真实书籍与段落。身份、一天的四条记录和错误由浏览器响应构造，所有非GET均截获；实际捕获的两个POST分别是退出失败和退出成功，没有到达服务器，没有真实写入、邮件或生成。

初测发现两处焦点问题：日历重试成功时按钮隐藏，焦点退到BODY；退出503失败时按钮恢复可用，焦点仍为BODY。实现补齐恢复，并避免异步返回时抢走用户已移到其他控件的焦点。修复后两宽均回选中日期或退出按钮；退出成功则等待完成回执后核对登录入口焦点。日历失败日期现在读为“记录暂未载入”，不会冒充无记录。

日历书籍链接经键盘Enter实际进入公版段落，目标顶部为桌面160.24px、手机159.79px，与入口160px定位约定相符。问题记录经鼠标进入同一段落，旁注可见、问题页签选中且selectedId正确。阅读器按既有规则消费passage/note并清理地址栏；验证读取真实段落位置和旁注状态，不能要求消费后的URL继续保留查询参数。可见锚点getAnchor返回更上方尚在视野中的段落，也不能据此误报目标定位失败。

当天4条记录的数量、自己的笔记/未解决问题名称、book和passage及note类型均核对。记录折叠可由Enter展开；390px无横向溢出，记录链接和折叠入口均高于44px。这里验证链接与界面归属，没有读取、保存或恢复真实私人笔记。

可复跑脚本为`output/playwright/root-calendar-conditional-actions.js`，默认1440；以第二参数390运行同一函数即为手机场景。读回为`root-calendar-conditional-desktop.json`与`root-calendar-conditional-mobile.json`，初测两个焦点事实为`root-calendar-recovery-before.json`。图片为`root-calendar-error-{1440,390}.png`、`root-calendar-records-{1440,390}.png`、`root-logout-error-{1440,390}.png`。最初夹具曾用settings的innerText查输入值，并把被正常消费的查询参数和首个可见段落当作导航目标，均是断言假设不当，已改为实际账号名称、目标几何与旁注状态，不计作产品缺陷。

手机长记录另发现一个实际遮挡：关闭按钮的DOM尺寸为44px，但展开记录后的自动滚动使它只剩21px高可见。现将关闭固定在原有右侧位置；390px下横坐标319–363、纵坐标45–89，滚到末尾scrollTop=749.5仍完整可见。两宽均使用真实鼠标坐标点击关闭，未借助定位器自动滚动。修前几何保存在`root-calendar-close-before.json`，末端图片为`root-calendar-bottom-{1440,390}.png`。
