# GET-148: portable reading library — fixed design and acceptance

Frozen before implementation, 2026-10-17. Base ec6200d650090f667047794c84c0b028f82b434b. Source: getyak/leafhour. Owner: current continuous delivery chat. Native Git worktree is used because the app-managed worktree tool would use the unrelated Lighthouse repository. No Pi/MiMo, model generation, new schedule or external publication.

## Observed behavior
The existing authenticated library JSON/bounded book export preserves source versions, translations, personal records, positions and shelf state. It omits reader-chat transcripts and original file bytes. The modern settings UI has no backup/restore entry. Legacy schema-1 JSON restore prevalidates before writing and merges record IDs. Baseline: 44/44 export/HTTP/chat tests passed. Original downloads have authenticated ranges; hosted requests must stay below the platform request/response limit. The existing batch restore cannot guarantee whole-package rejection if invoked before every part is validated.

## Decision
Add a Data settings panel for three distinct outputs: (1) complete confirmed reading-library ZIP backup, with optional original uploaded files, (2) selected personal records Markdown/JSON including explicitly selected user questions or AI answers and time labels, (3) selected sharing Markdown/JSON, whose preview is the exact immutable download text. Nothing is published. Sharing starts with no selection, excludes time/position/book bodies and unselected questions, and includes an excerpt only by explicit checkbox. User text is rendered through textContent.

Use versioned manifest.json + per-book open JSON and SHA-256/length inventory + optional originals inside standard ZIP. Use pinned fflate 0.8.3 (already locked transitively), declare it directly, and vendor only its MIT browser ESM file with hash/license for buildless local/hosted parity. No CDN or new paid dependency. Reject duplicate/unknown/unsafe archive names, non-inventory bytes, malformed metadata, invalid anchors, source conflicts, excess sizes and checksum mismatches. Bound compressed and expanded package to 512 MiB, each original to the existing 256 MiB limit, at most 100 books; fail with a reason rather than silently omit content. Store-only generated ZIP avoids unnecessary compression CPU and ZIP bombs; accepted input decompression is bounded before allocation. Capacity is documented, never reported as unlimited.

Extend chat with credential-free export/validation/idempotent restore, preserving IDs, user/AI origin, terminal history, source versions and citations. Running history becomes interrupted on import and never resumes a model request. Account grants, request budgets, leases, runtime IDs, tokens and browser auth are excluded; imported chat scope defaults to the current-book boundary. Validate referenced source text against the packaged book set; no access to another real account. Preserve URLs only when free of embedded credentials/auth query parameters. Keep legacy marginalia identifiers and JSON import/export compatible.

Restore uploads the immutable ZIP through <=1 MiB parts, scoped to the authenticated owner and a server-issued operation ID, then verifies the whole inventory and all domain/conflict checks before any book/record/chat/original write. Existing storage/CAS is reused with bounded reusable staging slots and expiration; finish/cancel removes staged private bytes. I/O failures after a valid preflight are reported as incomplete and safe to retry, not transactional success. Duplicate import merges existing record/chat IDs without erasing unrelated target records or enabling AI. No schema migration or production target change.

This backup covers the reading-library contract (source/translated text, comments, questions, chat/citations, highlights, milestones, confirmed time, position and shelf). Runtime tasks, credentials, grants and unsynced browser drafts are not migration content; UI instructs users to save/export drafts first. The existing separate audio export remains available for generated audio files and listening-specific histories; the Data panel states this boundary. Do not silently promise an application-wide server/config backup.
