# GET-194 — a reading workspace beside the book

Status: implementation plan, not acceptance. Base: `3882bfad7584bbfd3385f0a520595309da2efc9f`. [Issue](https://linear.app/getyak/issue/GET-194/ai-ask-聊天框优化).

## Outcome and visual direction

Ask AI is available in one click while reading. The book and conversation share a desktop viewport; a phone uses the same conversation as a full-page surface. Timing remains available as a secondary reading tool. The composer contains a question, optional selected quotation, and send/stop controls. Permission configuration and its complete explanation remain available in More, without occupying the default composer.

Keep Leafhour's paper, ink, restrained green, existing interface type and Newsreader reading typography. Use one hairline divider between book and conversation, square-edged workspace geometry, generous message spacing, and a compact bordered composer. Avoid a second floating card, large explanatory footer, decorative gradients, or a new theme. Paper and night must both have visible focus, separators and meaningful status text. Touch controls have at least 44px targets.

[Fresh baseline evidence](../verification/2026-10-20-get-194-baseline/README.md) establishes current behavior. The comparison is about observable steps and space, not an invented superiority score. Official [Claude in Chrome documentation](https://support.claude.com/en/articles/12012173-get-started-with-claude-in-chrome) supports the beside-the-page pattern; [Manus Browser Operator documentation](https://manus.im/en/blog/manus-browser-operator) supports visible, reversible controls and activity. These are documentation references, not logged-in competitor UI audits. The historical Ask ChatGPT Atlas URL now redirects to the [Atlas retirement notice](https://help.openai.com/en/articles/20001371-chatgpt-atlas-retirement), so it is not evidence of a currently available product to copy.

## Batch A: layout, entry and composer

1. Move the existing chat-owned trigger host outside the concealed timing drawer. Ask AI is the primary visible action; the existing Read/timing action is secondary. Reader tools remain the sole owner of their toolbar, expanded state and conceal timer. Chat owns its own trigger and dialog ARIA. Companion unread state and focus return use explicit ports associated with the visible AI entry, without attaching a second handler to the timing button.
2. At viewport widths of at least 1100px, open a right-hand nonmodal workspace. Reserve real horizontal space for the book, page navigation, reading controls and header; never cover original text or truncate the only available navigation. Default width 440px, minimum 320px, maximum `min(640px, viewport width - 640px)`. A visible left separator supports pointer capture, arrows (16px), Shift+arrows (64px), Home and End; expose orientation, name and current/min/max width to assistive technology. Persist only a validated bounded UI width under a new local UI key. Storage failure leaves resizing usable in memory.
3. Below that breakpoint use a full visible-viewport conversation, including safe areas. Keep the same physical input and message nodes across viewport changes. Continue using nonmodal `show()` to avoid closing/reopening the native dialog during IME composition. In mobile mode, the workspace controller owns `aria-modal=true`, background sibling inertness and a Tab focus loop; record and restore pre-existing inert states exactly, including disposal and breakpoint transitions. Do not steal focus already inside the conversation. Escape and explicit close remain chat-owned. A short visual viewport must allow reaching the composer and close control; claim keyboard behavior only for tests actually performed.
4. Add a small layout controller, `app/reader-chat-workspace.mjs`, mounted only by reader-conversation. It owns the separator, width, layout classes/styles, viewport listeners and mobile focus containment, and cleans up all of them. The library-page chat retains its floating layout. Add an explicit `onViewChange(open)` chat lifecycle callback after actual open/close, including native close, reset/dispose, without duplicate notifications or a second modal owner. Keep `surface()` stable and add a `preferenceHost` for the companion control inside More. No hidden polling or data writes are introduced by layout.
5. Expose reader `closeNotes` through its existing bridge. Opening AI closes the note panel after preserving its existing saved draft; opening notes closes AI while preserving its draft, pending turn and retry identity. Read actual anchor/book/content identity before layout changes and restore the same passage after layout settles only while the originating book and generation are still current. Reuse existing pagination/ResizeObserver behavior, not synthetic resize or navigation events. Disposal and book/account changes fence outstanding callbacks.
6. Move the actual scope selector and full scope/cloud explanation to More. Keep current server-confirmed scope and revision semantics, explicit reversible changes, pending/error/unconfirmed states, retry and stop. No silent grant expansion. Move the companion preference there too. Remove duplicate long hints from the composer, keep accessible labels and meaningful status live regions. Use compact contextual information and a brief empty state. Do not hide errors to create a cleaner screenshot.
7. Maintain EN, simplified Chinese, traditional Chinese and Japanese through the existing runtime and catalogues. Locale changes relabel stable nodes only, preserving input value, focus, IME, text selection, scroll, active request and retry ID. Source, translations and AI/user messages are never rewritten by interface locale.

Batch A is a checkpoint, not issue completion. Do not expose a nonfunctional quote control or ship only the layout.

## Batch B: quotation into the conversation

Use the reader's existing validated selection snapshot for an explicit Quote to AI action from original text or either translation. Preserve exact selected text, book/content identity, passage IDs, layer/variant and draft provenance. Show a removable quote separately from the user's own question; never auto-send, overwrite a question draft, silently truncate, or relabel a translation as original. Guard stale, cross-book, oversized, running and uncertain-retry states before admitting a new quote.

The final quote contract must cover current-source validation at send, exact idempotency, persisted/recovered drafts and retries, model input attribution, history and portable export/import. A historical selected quotation is user-provided source data, not a newly verified model citation. Changed translations must not erase historical user records. Quote access must not widen the existing reading scope or add private notes, later text or a new model service. Freeze the precise domain contract before implementing this batch.
