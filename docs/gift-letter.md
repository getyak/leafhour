# 赠书信：浮起的信笺、静水与原文引文（GET-164）

2026-10-18。用户授权这封赠书信的两项增强：拆开后的信笺要真正“浮”起来，信笺背后有一片安静的浅水；随信附上一句默认引文，从这本书的原文中选出并标明出处。设计由父任务定稿，本轮做实现与有界验证，并按父任务复审批改了五处 P2（来源池越界、动效生命周期、响应字节、画布预算、恢复策略）。不改动首页、书房、阅读页与其他阅读故事。

## 拆信后的浮起与静水

保留现有可逆弹簧拆信/折信、纸张纹理、色彩与字体系统。变化只发生在信笺展开之后：

- 信笺在 `--spread` 随弹簧增长时获得克制的静态抬升（约 9px 上移、0.3deg 内的轻微旋转）与分层阴影（贴纸阴影 + 随展开增大的环境阴影，夜间用更深的 `--letter-float`）。这是静态几何，不是持续漂浮：没有 keyframes、没有上下浮动，正文、按钮、焦点目标的位置在展开后不再移动。
- 信笺背后是一片静水：`app/gift-waves.mjs` 是有界 Canvas2D 渲染器，只画四条低振幅正弦波带（缓慢漂移、近单色、低透明度），文字永远在其上方且不动。渲染分辨率与总像素一起限额（DPR ≤1.5、宽 ≤1200、高 ≤1600、总像素 ≤1200×1600，超出按比例同时缩小两轴、保持场景比例，长窄信笺不会撑出巨大高度），帧率上限 30fps。
- 生命周期由 `app/gift-waves.mjs` 里的窄控制器与页面接线工厂 `createGiftWaveScene` 统一管理，同一时刻只有一个渲染器、一条调度循环：信笺展开且可见、场景在场（以 DOM 真实可见性为准）、页面可见、未开启 reduced motion 时才运行；信笺折起、标签页隐藏、reduced motion、收信预览更新时立即停帧并清空。错误页先标记场景不可用再 dispose 渲染器，`visibility`/`pageshow`/重排/动效变更都会先向 DOM 核实场景可见性，因此隐藏的错误场景永远不会被恢复事件重新点亮。展示时先更新 DOM 并取消场景隐藏，再重建渲染器并重算几何，画布量到的是可见场景的真实尺寸，不是隐藏时的 1×1；`pagehide` 保留信笺意图状态并释放画布，`pageshow` 只在场景真实可见时恢复。每次同步都重新量尺寸，信笺状态不变的重排也能更新画布。测试直接驱动这套页面接线工厂（不是产品从不调用的内部方法）。
- 渲染器是纯装饰：`aria-hidden`、`pointer-events:none`、不接收任何输入。`getContext('2d')` 不可用时不留动画循环，`data-waves=static` 让 CSS 静态波纹层继续作为诚实退路（该层始终存在，画布只是在其上叠加缓动）；reduced motion 下同样只保留静态抬升与静态波纹，内容、控件与焦点流程不变。

## 默认引文架构

`server/gift-quote.mjs` 负责选句、生成与校验，只读当前这本书的原文：

- 有界来源池：最多 8 段、合计 ≤12000 字符的本书原文前缀（每段 ≤4000 码点，按码点截断，保留 chapterId/passageId），不读笔记、阅读记录或其他书。空来源即无引文，不调用任何提供方。池上限固定在服务端，不能被提供方返回的值放大。
- 有提供方时只发一次 `https://api.deepseek.com/chat/completions` 请求：`DEFAULT_MODELS.reading`（当前 `deepseek-flash`）、显式关闭思考（`thinking:{type:'disabled'}`）、temperature 0、`max_tokens` 400、15 秒超时、无传输重试。提示词声明输入只是资料、只许按 `passageId + start/end` 码点区间“选出”一句精确连续子串；模型输出必须是恰好七个键的 JSON，多余键、解释、代码块或夹带指令一律拒绝。
- 响应读取是有界的：Content-Length 先拒，流式读取同时受 64KiB 字节预算与块数预算约束，超限或读失败即 cancel/release，随后一次 fatal UTF-8 解码与 JSON 解析。未读取的响应体在快速拒绝与非 2xx 状态下也一律取消释放（cancel 异常不会掩盖回退），实际测试断言两种路径的流 cancel 都被调用且只发一次请求。请求体、响应体、Key、计量信息不进 UI 也不写日志（错误信息也不含响应内容）。
- 校验分两层，必须同时通过：对照**实际提交给模型的来源池**（同一 chapterId/passageId、且只允许落在提交给模型的前缀码点区间内，文本与区间切片完全相等），再对照**当前完整快照**（bookId、contentVersion、章节/段落、精确连续子串、≤240 码点、无控制字符、无标签形态文本）。第 9 段（池外段落）或池内段落超出 4000 码点前缀的选择都过不了第一层，即使它是完整原文的精确子串；UTF-16 偏移或改写在切片相等处失败。
- 任何失败都退回**确定性原文句子**（来源池第一段第一句），标签诚实写作「这本书的原文节选」，绝不写成 AI 选出，也绝不借别的书（比如爱丽丝）的句子。每个书各自的回退句来自各自的原文。
- 同一 owner+book+version 的并发请求合并为一次调用；有界缓存（16 条）**只缓存校验通过的 ai-selected 结果**，回退句是提供方失败后的恢复结果，不当作成功缓存，因此一次显式重试可以再次询问提供方。缓存键含 owner，绝不跨账号泄漏。单次请求永远只有一次提供方调用，没有自动重试。

`POST /api/library/books/:id/gift-quote` 是新的登录所有者专属路由（复用 `library.getBook` 授权）：只“准备”一个建议，返回原文、章节/段落定位、诚实选择标签与不透明收据（32 位 base64url），不创建分享链接，也不创建赠书信。

## 收据与封缄

预置选择保存在现有赠书数据存储（`server/book-gifts.mjs` 的 read/mutate + dataStore）中：按 owner 分文件、私有、15 分钟过期、每账号最多保留 20 条并随写入裁剪。不是内存态、不需要新增 Secret、不另建公开存储。

封缄（`POST /api/library/books/:id/gifts`）只接受 `quoteReceipt`（收据 ID 或 null），绝不接受客户端引文文本或 AI 标签：

- 封缄时从存储重新载入选句，对照**将要发布的精确快照**与该快照的来源池重新校验（版本、章节/段落、精确连续子串、前缀区间），标签沿用服务端记录（AI 选出 / 原文节选）。未知、跨账号、跨书、过期或对不上快照的收据一律拒绝（409，草稿保留，可移除引文或重新获取），不伪造归属。
- 赠书元数据只存“选中的原文 + 出处”（text、selection、chapterId/chapterTitle、passageId、start/end、码点数）。收信页只暴露原文与定位，收据永不外发。旧赠书信没有引文，渲染完全如常。
- 预览→封缄全程不第二次调用选句提供方；打开收到的信笺也从不触发任何模型调用。

## 撰写窗口与预览

- 明确打开某本书的赠书撰写窗口时请求一次默认引文（owner + 对话 ticket + book/version 守卫）。结果到达前，对话里就写明「引文会从这本书的原文中选出，不会用到你的笔记和阅读记录。」
- 引文在撰写纸与收信预览（iframe）里都显示原文、章节/段落出处与诚实标签；可「移除引文」「恢复引文」（移除后恢复原收据的同一段选句，不再请求）或「重新获取引文」（显式恢复动作，可能再次询问提供方）。旁注如实说明：重新获取只是恢复选句，不承诺换一句；已有引文可能保持不变。所有这些动作都不碰已写的赠言与收信人；不自动导航、不自动发布；唯一发布动作仍是「封好这封信，生成链接」。
- 慢响应在窗口关闭、账号切换或换书后到达时会被丢弃，不能替换当前对话，更不能喂给分享。`createGiftPreview`/`readGiftPreview` 对引文做同样的边界校验，且必须带合法收据，否则整条引文丢弃（fail closed）；同源与精确 sender-window 校验原样保留。收信预览仍然不创建、不收取、不下载真实赠书。

## 边界与未决

- 这是有界选句，不是全书阅读：来源池只是本书开头至多 8 段的前缀，选句被强制限制在这段提交范围内；文案与提示词都不声称读过全书。回退句是确定性的首句节选，不是编辑推荐。
- 波纹是装饰性静水，不是真实水体模拟；纸张抬升是静态几何，刻意不做持续浮动。Canvas 不可用或 reduced motion 时只有 CSS 静态层，这一点如实标注，不冒充动画。画布预算以 10% 内的相对误差保持场景比例，极端长宽比下波纹经整体缩放后会有可见的低分辨率柔化，这是限额的代价。
- 模型只被要求“选”，但选句质量仍取决于模型品味；结构风险由双层校验兜底。`thinking:{type:'disabled'}` 与 `deepseek-flash` 是当前约定参数，线上真实响应尚未验证。
- 真实浏览器的桌面/移动、深浅色、长信、开合与焦点验收尚未执行，由父任务负责；本轮只有 Node 侧合成夹具、记录型渲染上下文与 HTTP 集成测试，不等价于真机观感，也不代表浏览器检查已完成。
