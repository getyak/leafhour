原文、译文共用原生阅读器，独立选择左右分页或上下卷轴。原文长按查译使用浮层，返回后保留轻量译标；译文显式展开来源；手动对照收紧间距并隐藏常驻译法／校订标签。翻译状态与独立版本仍保留，未准备内容使用真实状态。自动翻译与预取、模型确认和计费策略未改。

## 审阅修复

- 显式传递非中文缓存目标；冻结浮层选段与章节。
- 缺译文占位固定实际来源切片锚点，排除选文、语音位置、语音绘制与书签范围。
- 分页译标按正文列定位并限制在可见视图内；标题不误显示原文收起。
- 点按开始时冻结清选区意图，避免原生手势先清除后的同次翻页。
- 上下模式跨章向前恢复实际内容尾部。
- 长原文已有真实译文可展示，避免按来源子窗重复读同一完整译文；缺译文时显式展开的长原文仍保留来源窗口，连续前后阅读不跳过余文。
- 连点改用逐次接触观察器，保持被动状态；段落长按不等待它失败，接触开始时冻结清选区意图及导航身份。听书原有单击识别保持不变。

## 连点问题的运行定位

十次普通前进与十次返回均完整；五次真实双击的十个接触中，有两次到达窗口时，旧离散识别器仍处于上一击的 `.ended`，UIKit 尚未重置，因此没有再次派发给阅读器。窗口诊断确认触点落在同一 ReflowTextView，队列没有丢失已接收的请求。固定屏幕坐标仍能复现，单独拦截原生 caret tap 也没有解决它。

修复以每次物理接触结束直接回调，过滤长按、移动和多指，不把每个短接触置为离散识别终态。临时诊断仅记录数值和类名，定位后已全部删除。[Apple 的 reset 契约](https://developer.apple.com/documentation/uikit/uigesturerecognizer/reset%28%29) 不保证终态后立即接收下一接触。

## 复现与产物

设备为共享池 Primary iPhone（iPhone 17 Pro、iOS Simulator 26.5），通过 dev-ios-session 串行运行，应用包为隔离的 org.leafhour.get417.testing。Core 以 2 个 jobs 跑完整套件；App Tests 运行 ReaderTap、ReadingLayers、ReaderPagination、ReaderViewport、ReaderSelectionState、ReaderPreferencesLayout、ReaderAutoPageController 与 ReaderLayout；UI 在 ImmersiveReaderUITests 中运行本次新增的四种十触点、浮层译标、译文原文及对照设置用例。

UI 将十次普通前进作为位置基准，十次返回核对起点，再以五次双击提供十个快速接触，对比稳定的正文屏幕裁剪。随后真实长按并点空白，核对该次只清选区、后续接触仍可翻页。屏幕坐标固定，避免用可变化的 TextKit AX frame 作为正文图像或快速输入的参照。

本机正式证据保存在 ~/.local/share/leafhour-reading-evidence/get-417-20261106，包含运行摘要、日志、诊断数值、合成样本截图与来源说明。原始登记产物根为 /private/tmp/ai-test-GET-417.8Kv8Qp；正式证据保存后只回收可重建内容。无用户真实书籍或账号数据进入仓库。
