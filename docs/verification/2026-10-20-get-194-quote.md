# GET-194 selected quotation — implementation checkpoint

The selected text is stored separately from the reader's own question and from AI citations. Original, literal and interpretive selections retain exact text, offsets and translation status. A bounded shared normalizer distinguishes current source validation from historical snapshot validation; historical user quotations do not relax existing AI answer citation checks.

The reader selection toolbar opens the existing AI workspace and a removable quotation chip, preserving the question and physical input. Opening never sends. Pending, uncertain and scope-changing operations block replacement. Four locale catalogues label the controls; text snapshots are never relabeled. An outdated source version blocks a fresh send until removal or reselection.

Quote drafts use owner/book-scoped revisioned heads and separate per-submission ACKs. Completion never rewrites or deletes a shared head. Explicit removal writes a tombstone. When storage writes fail but an older head remains readable, the current page keeps its new in-memory selection and labels its limited durability. A different explicitly persisted revision can still replace it. There is no localStorage CAS or atomic question-plus-quote transaction. ACKs are small records for successfully completed quoted turns; the existing 100-turn per-book service limit also bounds acknowledgements in normal service use. Legacy question draft clearing remains best effort.

The server compares the complete optional quote during idempotent claims. Exact terminal replay precedes fresh source checks; a changed quote conflicts. New source validation and the shared 24KiB input encoder run before turn insertion, personal-question recording, quota or companion interruption. Source/status is checked again before publishing a new answer. The real harness receives attributed `selectedQuote` data, while `reader_cite` remains the authority for AI references. The encoder retains at most six prior whole turn groups, trimming complete oldest groups to fit actual UTF-8 bytes. Existing service-generated no-quote formatting and custom input labels remain compatible.

Local checks: the first integration run found four incorrectly staged cross-tab fixtures (they loaded after pending recovery and were correctly locked); tests now stage an already-open second tab. An additional independent intermediate review identified readable-old-head/write-failure (P1) and stray revision on a no-quote pending record (P2). Both were reproduced with the real state module and fixed. The subsequent 163 integration tests passed, zero failures/skips. The broader focused run, build and public-build results are recorded in the next evidence update. The build passed without relaxing locale-owner permissions, graph boundaries or asset budgets; only actual runtime files were added to the release allowlist. Explicit self-host routes also serve the new files.

This checkpoint is not final independent approval, full CI, native text-selection acceptance, merge or Production acceptance. Tests use disposable synthetic accounts/books and deterministic generators, with no paid product model calls. Physical mobile keyboard, real IME, assistive technology and real-account model output are not claimed.
