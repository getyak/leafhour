# Public beta entry verification

The user selected direct iOS installation, anonymous Web trial and email feedback. The new /beta English alias and /{en,zh-hans,zh-hant,ja}/beta use the same renderer in the local server and hosted packaging. Homepage navigation, hero secondary action, iOS promotion and footer lead to the corresponding authored beta page. Canonical metadata, four-language alternates, WebPage data and sitemap entries are included.

The design reuses the public paper/green palette, Newsreader, native UI fonts and actual public-domain product captures. The page has a primary iPhone installation area, a Web sample entry, honest beta/points/data notes and an email composer. It introduces no service dependency or library/account/model bootstrap.

The email form prepares a mailto draft with an explicit platform, optional device/version and the reader's own description. It never sends or saves the form. The preview remains manually copyable; clipboard denial selects it for copying. Editing any input hides an older prepared draft. The form remains hidden if JavaScript fails, while ordinary support mail links and noscript guidance remain available. Inputs become text/encoded URI values, not HTML; arbitrary platform strings cannot become mail headers.

A full portable deployment suite reported 4,927 passes, zero failures and one existing platform-conditioned Node-binary license test skipped. The source release allowlist (1,616 software files), built public asset policy and source provenance checks passed. Additional route/release/typography checks passed after correcting new-file packaging, the shared action-radius token, the 12px functional text floor and sitemap expectations. Real pinned Vale/textlint copy validation passed with existing documented debt retained.

Chinese desktop/390px phone and dark mode, Japanese phone feedback, mobile menu language navigation, authored language after runtime startup, one appearance menu and Escape dismissal were checked. Preparing a synthetic feedback draft produced zero API requests. Unicode, markup characters and line breaks remained literal. The stale-draft reset and JavaScript-disabled direct-email fallback were observed. These are browser/static checks, not physical-device or arbitrary-mail-client acceptance.

An independent fresh reviewer found no confirmed P1/P2 issues, including a follow-up packaging/metadata review.
