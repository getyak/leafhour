## Changes

1. **P1 — ending hydration and save continuations.** `reading-session.js` captures the actual reader bridge, owner object/ID, book object/ID/version, draft store and session epoch. `openEnding` and `saveEnding` check that scope after source hydration; saves check it again after POST/JSON resolution and before acknowledgement, persistence, events or DOM work. Readiness changes and disposal invalidate the epoch, including A→B→A. A stale save releases only its original store's in-memory busy flag; it cannot create another UUID/request, persist, emit `reader:record-saved`, or change the UI. Live 409/retry still submits the original UUID/text and preserves newer input.
2. **P2 — palette account notification.** The reader adapter keeps explicit subscriber registrations and an exact, idempotent unsubscribe. Account-change callbacks run before reader disposal removes page listeners, so the palette can invalidate private results. Teardown then clears the registrations. An unsubscribed registration does not suppress a different live subscriber.
3. **P2 — dynamic listener ownership.** New composer/form/chapter-action and draft-list node handlers are owned by their nodes rather than the page's strong listener array. Detached targets and disposed owners are inert. The page array contains fixed listeners only, so repeated replacement does not retain each discarded DOM tree. Tests assert the actual closure's listener count across 25 composer replacements and 25 draft-list openings. This is a registry/reference-ownership check, not a native heap/GC measurement.

Only `app/reader.js`, `app/reading-session.js` and relevant tests changed in production/test scope. No new locale runtime, imports, dependencies, model calls, schema changes, provider use, parent-tree edits, push or external updates occurred. The legacy `reading-view` test now uses one stable reader-bridge object and executes the real scope helper; its existing failed-source, actual source-loading and quote assertions remain intact.
