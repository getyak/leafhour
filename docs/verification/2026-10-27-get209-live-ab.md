# GET-209 真实小规模 A/B 验收回执（2026-10-27）

这是 `docs/verification/2026-10-21-get209-pdf-evaluation.md` 的后续回执，解除其中登记的唯一生产
阻塞 `OCR_AB_QUOTA_AND_COST_UNVERIFIED`。2026-10-27 操作者明确授权：核实 PaddleOCR 官方服务
额度/费用上限，并按 2026-10-21 回执第 3 节冻结的协议运行小规模真实 A/B。本回执只报告实测数据；
产品结论在最后一节。

## 1. 额度与费用核实（先于任何提交）

- 官方规则（百度 AI Studio《API Quota Rules and Error Code Description》，
  `https://ai.baidu.com/ai-doc/AISTUDIO/pmjcld5qm`）：每个用户每个模型每天最多解析 3,000 页；
  超限后后续请求返回 429 且不能被处理。规则中不存在按量计费或超额扣费机制；额度不足的解法是
  通过问卷免费提额。PaddleOCR 官网首页另有“免费 API 每天最高 20,000 页”的营销表述，与 API
  文档的单模型 3,000 页口径不一致；本回执采用更保守的 API 文档口径。
- 账号侧可查性：仓库固定的 `@paddleocr/api-sdk@0.2.3` 只暴露 job 端点
  （submit/status/result/batch），没有任何额度/余额查询 API；AI Studio 网页控制台需要交互登录，
  本次未使用。因此“今日剩余额度”无法以数字形式读回——这是如实记录的边界，不是推测值。
- 令牌有效性零成本探针：用仓库 `.env` 中的 `PADDLEOCR_ACCESS_TOKEN`（只按名引用，不落盘）
  对一个不存在的 batch 做 `recover` 查询，API 正常应答（无此 batch），未返回 403
  （403 才是令牌无效，见官方规则）——令牌被官方 API 接受。
- 本账号历史：同一配置曾于 2026-10-17 完整处理 779 页扫描书（见
  `docs/verification/2026-10-17-paddleocr-upload.md`），全程无计费记录。
- 结论（成本上限为零这一协议条件）：该 API 的免费额度是硬上限、超限即拒绝，不存在产生费用的
  路径；本次 A/B 最坏 12 页、实际 8 页，占单模型日免费额度的 0.27%。零费用上限成立。

## 2. 协议执行

- 工具：`tools/evaluate-pdf-routes-live.mjs`（新增；离线工具保持不变）。两阶段：先 `--generate`
  生成样本、冻结参考与带哈希的 intent，再 `--run` 校验样本哈希与 intent 一致后才允许提交；
  运行需显式设置 `GET209_LIVE_CONFIRM=1`。
- 样本：3 类中文版式 × 2 页，内容为本工具内现编的合成短文（CC0-1.0，无任何私人书籍参与）：
  `zh-single`（单栏文字层，SHA-256 `841a3642…`）、`zh-scan`（纯光栅扫描图，无文字层，
  `31bc037c…`；生成后先用 macOS Vision 本地核验渲染文字完整，才获准提交）、
  `zh-columns-footnote`（双栏+页脚脚注文字层，绘制顺序按行交错，原生抽取顺序天然错乱，
  `73ae84e6…`）。参考文本、块边界、期望阅读顺序与脚注归属全部写在 intent 中、冻结于任何
  服务输出之前（`docs/verification/fixtures/get209-live-ab-2026-10-27/intent.json`）。
- 路径：生产 `createBookIngestion` 编排的 `auto` 与 `ocr` 两条路径；`ocr` 以 `consent: true`
  准备，`auto` 的扫描样本在流程中途走真实的 `awaiting_consent → consent` 步骤。Provider 为
  仓库 `createPaddleProvider` 默认项：模型 `PaddleOCR-VL-1.6`、`useDocOrientationClassify:
  false`、`useDocUnwarping: false`、`markdownIgnoreLabels: [header, footer, number,
  header_image, footer_image]`。唯一有意偏差：`batchPages=2`（与样本页数齐平，使每样本恰为
  一个批次/一个 requestId），在此登记。
- 提交纪律：每样本×路径只提交一次；无结果未知后的重复提交；6 条路径全部一次到达 `done`，
  无 resume。实际识别页数 8（ocr 路径 6 页 + auto 扫描回退 2 页），提交 4 次，低于冻结上限 12。
  实际费用：¥0。

## 3. 实测结果

CER 口径同 2026-10-21 回执：逐页 Levenshtein 编辑距离 / 参考字符数，同时给原始与去空白两版；
块缺失为去空白后整块严格子串未命中；顺序错误单独以逆序对计数，不并入 CER。

| 样本 × 路径 | 状态 | 识别页 | 总时延 | submit / result | CER 原始 | CER 去空白 | 块缺失 / 重复 | 逆序对 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| zh-single × auto | done | 0 | 0.08 s | — | 0.078 / 0.079 | 0 / 0 | 无 / 无 | 0 / 0 |
| zh-single × ocr | done | 2 | 18.78 s | 5.30 s / 8.50 s | 0 / 0 | 0 / 0 | 无 / 无 | 0 / 0 |
| zh-scan × auto | done | 2 | 12.12 s | 2.07 s / 3.65 s | 0.051 / 0.050 | 0 / 0 | 无 / 无 | 0 / 0 |
| zh-scan × ocr | done | 2 | 7.13 s | 1.30 s / 2.24 s | 0.051 / 0.050 | 0 / 0 | 无 / 无 | 0 / 0 |
| zh-columns × auto | done | 0 | 0.04 s | — | 0.561 / 0.556 | 0.546 / 0.540 | R2*（仅第 1 页）/ 无 | 4 / 6 |
| zh-columns × ocr | done | 2 | 8.15 s | 1.52 s / 3.46 s | 0.703 / 1.021 | 0.686 / 1.062 | 第 1 页 R2、F1；第 2 页 L2、R2、F1 / 无 | 4 / 3 |

*R2 在原生抽取中块体完整，仅尾随“。”被 pdfjs 分组到别处，按严格子串口径记缺失（测量伪影）。
脚注：`auto` 两页均检出 F1 且位于读序末位（归属块 L3 / L2 分列第 4 / 第 3 位）；`ocr` 两页均
未检出 F1。

## 4. 关键发现

1. 干净单栏文字层：原生（auto）去空白 CER 为 0 且毫秒级完成；OCR 同为 0，但耗时 18.8 秒并
   消耗额度。对已有文字层的书，全量 OCR 没有任何质量收益。
2. 干净扫描页：auto 的原生门禁正确回退到同一官方 OCR（与 ocr 路径同走一条通道，结果一致），
   6 行合成正文去空白 CER 为 0、顺序全对。此前 GET-209 缺失的“中文扫描”一格至此补齐：
   英文结论之外，中文干净扫描同样可靠。
3. 双栏+脚注（本次最重要的新数据）：OCR 不但没有修复栏序（逆序对 4 / 3，与原生的 4 / 6 同量级），
   文本保真度反而更差（去空白 CER 0.686 / 1.062 对原生的 0.546 / 0.540），且两页脚注全部丢失、
   另有正文块未整块命中。脚注位于页底边距带，生产冻结的 `markdownIgnoreLabels` 含 `footer`，
   页底脚注被标为 footer 后过滤，与此现象一致（机制为推断，现象为实测）。也就是说：至少在这类
   合成双栏版式上，把默认改成全量 OCR 会让结果变更差；双栏阅读顺序是两条路径共同的未解问题，
   不是切换默认能解决的问题。
4. 时延：任一 OCR 批次的整书时延在 7–19 秒量级（不含大书的多批串行），auto 对文字层书是
   毫秒级。配合第 1 点，全量 OCR 默认在时延与额度上都是净成本。

## 5. 证据限制（如实登记）

- 本次 runner 保存了逐页指标、原始结果摘要与规范化摘要，但未持久化假设全文；个别块未命中的
  逐字原因（字符级误识还是分块合并）无法事后逐字复核。后续若再做真实 A/B，应先给 runner 加上
  假设全文落盘。这一条不影响上表的 CER（全文 Levenshtein 在运行当时对全文计算）。
- 额度“剩余额度”无法通过 API 读回（第 1 节），核实层级为官方规则 + 令牌探针 + 本账号历史。
- 样本为合成短文与合成版式，结论外推到真实书籍的多样版式时需保留这一边界。

## 6. 结论

- 阻塞 `OCR_AB_QUOTA_AND_COST_UNVERIFIED` 解除：额度规则、零费用性质、令牌有效性与本次
  实际费用（¥0）均已核实并记录。
- 产品结论维持 `auto` 默认（网页上传仍 `mode: 'auto'`、`consent: false`）：真实小规模 A/B
  数据支持这一结论——OCR 在文字层样本上零收益、在扫描样本上与 auto 等价、在双栏+脚注样本上
  净负收益。没有出现推翻先验的数据。
- 后续（不在本 issue 范围）：双栏阅读顺序需要独立的版面分析方案，两条现有路径都解决不了；
  页底脚注在 OCR 路径下有被 footer 过滤吞掉的风险，真实书籍若依赖脚注，应在接入任何
  “OCR 优先”方案前先做专项验证。
