# Offline shell canonical URL correction

Production acceptance of PR #248 found a hosting-specific resource failure. Vercel's existing `cleanUrls: true` redirects `/offline-reader.html` to `/offline-reader` and `/offline.html` to `/offline` with HTTP 308. The Service Worker deliberately rejects redirects during integrity preparation, so no complete resource group was installed and “Ready to read offline” did not appear. Normal reading and conditional chapter reuse remained available.

The correction uses the public canonical URLs in the generated resource manifest and maps them to the original build files internally. HTML dependency discovery still reads the mapped files; the worker retains its no-redirect and SHA-256 checks. Legacy completed descriptors remain readable. The local compiled server serves the same canonical reader URL with HTML MIME type and the existing reader CSP.

Three regressions were observed failing before the fix and passing afterward: canonical build URLs and dependency closure, strict worker installation against a hosting layer that redirects every HTML-suffix route, and canonical local HTML GET behavior. The focused worker/build/static/release suite passed 34 tests. A local reverse proxy reproduced the Vercel redirects: real Chromium saved all 13 entries of the public Alice book, confirmed persisted completion and pinning, then reloaded successfully with the network disabled and an active worker controller. The existing production inline-style CSP console errors were also present before this change; this is not a zero-console-error claim. Safari and physical iPhone web behavior remain untested.

Full-suite verification exposed an existing audio fixture teardown race twice: cancellation assertions passed, but its after-hook deleted the temporary directory while a scheduled cancellation write was still completing (`ENOTEMPTY`). The fixture now collects the service's existing background completion promises and awaits them after closing, before deleting its temporary data. No production audio behavior or business assertion changed. The isolated audio service suite passed all 16 tests after this correction.

Local `npm run verify:deploy` completed with 4,159 tests: 4,158 passed, zero failed, and one platform-conditional skip. The isolated runtime, production build, public assets and release allowlist checks passed. Configured copy checks also passed; documented pre-existing warnings remain visible. Independent review found no remaining material P1/P2 issue.

Release and production acceptance results are recorded on the corrective pull request linked from this document's commit history. The first feature deployment is `93630028ff29e61af566af9fb454a6f5c120a11b`; its original incomplete offline acceptance must not be presented as a successful offline release.
