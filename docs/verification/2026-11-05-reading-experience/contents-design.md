# R7/R8 目录全文与 AI 搜索设计

日期：2026-11-05。范围：iPhone 已打开书籍的目录。本文是独立设计审阅，未改产品代码，未运行构建、重测试或设备验收。实现、自动化、模拟器、真机与发布状态应另行记录。

## 结论

目录内接入现有 `BookSearch`，按真实目录章节显示正文片段。标题和 PDF 页码匹配保留在同一入口。AI 模式由用户显式点击发送，统一使用现有 `/api/library/local-chat` 本机工具中继。云书也查阅当前已下载的正文快照。AI 选择与问题有关的原文，应用把经过验证的 `sourceRefs` 变成可点结果。

这条路径复用已有模型与只读工具，同时沿用计点和取消接口，能避免普通云端对话的书房范围影响目录搜索。`source: local-device` 必须保留。服务端核验的是设备返回片段的范围与引用关系，不能声称已经独立核验设备原件。

R7 和 R8 分别按 100 分验收。当前只做静态分析，两项产品验收已验证分均为 **0/100**，待验证上限均为 **100 分**。这不评价现有功能质量，只表示本次尚无运行证据。不能据本文填入 95 分或已通过。

## 目录中的交互

目录沿用原生 `List` 和章节字阶，保留当前章标记与 44 点按钮。沿用品牌色和系统背景，不加独立聊天卡片。搜索框下提供“全文 / AI”两种模式，VoiceOver 分别读作“本机全文搜索”和“AI 语义搜索”。空输入仍显示完整目录。

### 全文模式

输入后自动本机检索，沿用 150ms 合并与任务取消。顶部“目录匹配”保留 `ReaderContentsIndex` 的真实标题和 PDF 数字页码匹配，点击仍返回章首或对应页。正文结果按 `chapterID` 分组，顺序采用真实目录顺序，同章内部按段落顺序。

章节组标题显示“第 3 章 · 实际标题”，PDF 显示“第 12 页”。每段显示带命中强调的原文片段和“第 8 段”等可理解的位置。点击整行返回命中处。标题和正文结果分别计数。沿用一段一个结果的语义，写“找到 8 段原文 · 3 章”，不能把它写成全部词语出现次数。

“定位当前章节”清除查询、回到完整目录并滚到当前章，不改变书页。“从正文开始”和收起目录继续可用。工具面板原有“搜索”入口跳到同一个目录搜索组件，或采用相同 controller 与结果视图，避免出现两套检索规则。

### AI 模式

搜索框提示“描述想找的内容”。输入、切换模式和打开目录都不调用模型。点击“AI 查找”或明确的键盘提交动作才发送。生成中禁用重复提交并提供“停止查找”。沿现有 conversation 计点，报价流程仍使用本次请求 ID。本次已授权点击即发送，不加二次确认。

发送前在入口附近说明：“AI 会查阅本书片段，结果可能不完整。原件仍在本机。”本机保留原件不代表摘录不会发送到模型服务。若启用计点，按钮附近显示实际报价，不写死价格。

AI 结果也按真实章节分组。每行显示经过核对的原文引句、实际章节和段落位置，标明“AI 找到的相关原文”。AI 摘要可以作为简短辅助说明，但不能替代可定位结果。没有有效来源时不得显示成功结果列表，也不能从摘要中的 Markdown 链接生成跳转。

只保留两种搜索模式，标题/页码匹配直接附在全文结果顶部，减少窄侧栏中的切换层级。代价是搜索中少显示几行章节。收益是标题、正文与 AI 的区别可以在当前页面看清。

## 最小接口与文件责任

### 共享快照与结果

建议在 `LeafhourCore` 新增 `ReaderContentsSearch.swift`，只放值类型、结果分组和引用验证，不持有模型客户端或操作文件。搜索快照至少包含：

```swift
struct ContentsSearchSnapshot: Equatable, Sendable {
    let localBookID: String
    let sourceVersion: String
    let accountScope: String  // 本机范围或已捕获的账号身份
}
struct ContentsSearchHit: Identifiable, Sendable {
    let id: String
    let chapterIndex: Int
    let passageIndex: Int
    let anchor: ReadingAnchor
    let excerpt: String
    let origin: Origin       // localText / aiSelected
}
```

请求身份为快照、标准化查询和独立 generation token。原有 `ReadingAnchor` 继续计 Unicode scalar。UTF-16 只用于系统文字 API 的边界转换，不能混存。结果 ID 包含章节、段落和偏移，不以筛选后的行号导航。

`BookSearch.swift` 继续负责可取消的本机正文扫描和 Markdown 原文映射。首轮可复用现有线性后台扫描，不先建立新全文数据库。`ReaderContentsIndex` 继续投影真实章节，不能让模型重建或改写目录。分组与展示共用这两项来源。

### 独立 AI controller

在 App 层新增 `ReaderContentsSearchController.swift`，管理正文任务与 AI 请求，并处理取消和重试。`ReaderContentsPanel` 处理输入与模式切换，呈现状态并回调点击。普通聊天 `ReaderCloudTools.turns/question/retry` 不用于保存搜索状态。其计点准备代码若需共享，只抽取请求准备帮助函数，避免复制一份价格和报价校验规则。

AI 固定走已存在的本机中继路径：

1. 点击时捕获当前账号、`session.book`、本机 `sourceVersion` 与 requestID。校验原件完成后才允许 AI。校验中不阻塞普通目录导航。
2. 请求使用本机快照 ID 和版本，`history: []`。`localBook` 只附当前可读段落的有界上下文。云书的云端 identity 另保留用于账号和版本检查，不拿云端 contentVersion 冒充另一份本机原文版本。
3. 对 `/api/library/local-chat` 使用现有 conversation 报价与流式传输。每次运行创建独立 `LocalReadingTools`，固定当前书，不读取其他书、私人笔记或普通聊天历史，不写进度、不改变普通聊天 scope。
4. 模型根据语义问题改写关键词、读取真实目录与有界正文，再用 `reader_cite` 登记相关引句。关键词工具本身仍称原文搜索。AI 的作用是理解问题、扩展检索与选择相关片段。
5. 仅解码完成结果中的 `answer.sourceRefs`，通过下述验证后构造 `ContentsSearchHit`。流式摘要和中间工具结果不提前成为可点结果。

不新增 embedding 服务、整书上传或另一套 Agent runtime。每次只响应当前用户的搜索，工具按现有分页返回必要片段。不在目录打开时自动遍历整本书或预生成语义索引。结果说明本轮查阅范围，不能把有限检索无命中写成“整本书没有讨论这个问题”。

`CloudLibraryClient.streamChat` 已有账号变化隔离，可复用网络传输。新 controller 仍要在每次等待后核对当前请求、账号、书和版本。不可只依赖 UI 查询是否相同。工具请求到达后以及提交回执前均检查取消和身份。

### 来源与落点验证

每条来源必须属于本次捕获的 book/sourceVersion，且 `source` 为 `local-device`，`layer` 为 `original`。`chapterId` 和 `passageId` 必须能在当前快照对应章节中找到。章节标题从当前目录读取，不能使用模型提供的标题覆盖。

原文引句必须以 literal 方式对应保存文本的真实 Unicode 序列，不使用模糊相似度或规范化等价来认定引用。现有 sourceRef 无偏移时，只接受该段内唯一的精确 quote，计算其真实 scalar 起点。重复引句无法消歧就拒绝该来源。不默认为第一次出现。

可选的最小服务端补充是在 `server/local-reader-chat.mjs` 的 `reader_cite` 来源中返回 `charOffset/charEnd`，由本轮已读范围内的实际匹配计算。App 仍要独立核对范围、quote 和完整字符边界。多个可用匹配无法确定时继续拒绝，不让模型传一个数字解决歧义。来源只在当前章内唯一时仍可使用复合章/段标识。若中继无法区分重复 passage ID，就拒绝，不能跨章猜测。

点击结果前重新检查来源版本和实际章/段。文本使用既有 `onJump(chapterIndex, anchor)`。PDF 必须从当前文档的真实 `PDFPage.string` 核对源文本，将 scalar 起点转换为有效 UTF-16 range，再取得 `page.selection(for:)`，以真实 selection bounds 生成 `pageY`。可复用或扩展 `PDFTextAnchor`，不能把文字比例当成页面纵坐标。

PDF 文字层与保存文本不一致、扫描页无文字层或 selection 无法取得时，应说明“这页暂不能精确定位”。可另提供明确的“打开第 N 页”。这种页级回退不能记为精确片段定位通过。原版 PDF、重排正文与 Markdown 都需分别验证。

## 状态、取消与恢复

| 情况 | 可观察行为 |
| --- | --- |
| 本机书、未登录 | 全文/标题/页码照常可用；AI 保留问题，显示“登录后使用 AI 查找” |
| 云书有本机副本 | 全文不等待网络；AI 检索当前下载版本，不能混入服务器另一版本的章节 |
| 离线 | 已下载全文搜索可用；AI 给出联网重试，保留查询，不能把网络错误当无结果 |
| PDF 扫描页/没有正文 | 明确没有可检索文字；保留目录与页码，不自动启动付费 OCR |
| 正文零命中 | 显示没有匹配原文；目录匹配如有则继续显示 |
| AI 无有效来源 | 显示“本次未找到可核对的相关片段”；不显示摘要成功态、不宣布全书不存在 |
| 部分引用失败 | 仅显示可定位来源，并说明部分片段无法核对；无效来源不生成导航 |
| 模型/报价/工具失败 | 显示失败原因和相应重试；已有本机目录保持可用 |
| 查询变化/切模式/书或账号变化 | 取消旧本机任务；旧 AI 结果不得发布；AI 不随新输入自动再发 |
| 停止或收起目录 | 取消本机任务、停止接收和回传后续工具，向同 requestID 的 `/cancel` 发送取消 |
| 取消请求无法确认 | 显示停止状态待确认，保留请求ID；禁止把它写成服务端已停止 |
| 网络断开或应用重新打开 | 查询/恢复同一 requestID 的状态；“重试查看本次结果”不另建计费请求 |
| 原文替换或升级 | 旧结果失效并提示重新搜索；不按旧索引跳转，也不自动重新计费搜索 |

AI 状态至少区分 idle、draft、preparing、running、cancelling、completed、empty、failed 和 cancellationUnconfirmed。取消后即使迟到 completed，也不能覆盖当前界面或恢复工具执行。取消失败后，服务端可能继续至既有超时。需要如实显示未确认并提供恢复查询。

为支持关闭后恢复计点结果，按当前账号与书保存未终结请求的 requestID、冻结输入、报价/幂等信息和状态，使用搜索自己的本机记录，避免覆盖普通聊天草稿。终结后按现有保留约定清理。日志仅记耗时、计数和状态，不记录书籍正文或凭据。

- 目录已有内容首次可交互与搜索时键盘响应不被模型或全文扫描阻塞。输入至状态反馈不超过100ms。
- 20MiB 合成 TXT/Markdown 与至少50,000段文本分别测量：全文结果中位数不超过800ms，输入替换后旧扫描在100ms内停止，不在主线程进行整书扫描或 Markdown 解析。超过门槛再做分批结果/可取消游标或快照级缓存，不用动画代替修复。
- 大量命中使用懒列表，滚动不一次构建全部结果行。离开目录后任务与内存能回落。记录实测内存变化，不预填数字。
- AI 点击后100ms内显示准备/查阅状态，网络耗时单独记录。AI 正在查阅时可收起目录继续阅读。停止本机工具处理不超过100ms，服务端取消确认单独计时，不能以 UI 停止冒充供应商已停止。

这些是本次验收目标，并非 Apple 保证或既有性能事实。样本通过后只因新失败或新修改重复相关检查，构建和重测试由父任务统一执行。
