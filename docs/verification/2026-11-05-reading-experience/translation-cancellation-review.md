# 服务端翻译取消独立审阅

日期：2026-11-05。审阅提交：`b7b2d180`、`d904ec26`。

修复后通过审阅，没有遗留的 P1/P2 发现。规格符合与代码质量均通过。此结论限服务端变更。

## 已修复的 P1

**提交后断连会使已保存译文失去计费恢复路径。** 初版 `server/portal.mjs:657` 把连接取消信号传入计费层。原 `server/billing-service.mjs:173` 在领域服务返回成功回执后，先检查取消信号，再确认持久化完成。连接在译文保存后断开，会把账单置为 `cancelled`。`credit-gate` 又跳过已取消账单，后续恢复和同请求重试都不能结算。

独立隔离复现确认：先保存含本次 `generationReceipt` 的双译，再触发取消并返回结果，账单进入 `cancelled`、消费为零。恢复及同请求重试后仍如此。

`d904ec26` 已修复该问题。`server/billing-service.mjs:174` 以通过校验的持久化回执作为完成依据。`server/library-service.mjs:643`、`server/credit-gate.mjs:119` 在提交已尝试但回执丢失时，按原账号、原文版本和任务回执重读结果。暂时读不到时保留原任务，交给恢复流程核对。`server/generation-commit.mjs` 使用私有 WeakMap 标记可信错误，客户端字段和普通供应商错误不能伪造提交状态。

修复后的同一隔离探针得到 `settled`，消费为 1,000,000 单位，恢复后生成执行总数仍为一次。

## 规格符合

- HTTP 响应关闭触发领域服务的取消信号，配置的翻译器把该信号与超时信号合并，传给实际供应商 `fetch`。信号只放在独立调用选项中，模型的资料 JSON 不含信号。
- 本地写入在临时文件完成后、`rename` 前检查权限和取消。托管存储在异步 blob 上传后、CAS 提交前检查。提交前取消不会发布译文。已开始提交后保留结果核对与恢复路径，不承诺回滚远程提交。
- 原文版本检查、账号目录、独立双译、多语言投影和已审阅／并发版本的合并规则保留。已有完整译文仍可直接返回。
- 供应商忽略信号时，取消竞争会结束领域服务的等待。正常或异常退出都会移除监听并释放本次占用。迟到结果没有后续保存入口。

## 代码质量

通用 `mutate` 的可选提交检查保留了旧调用方式、本地串行队列和章节写入保护。托管 CAS 每轮重试都会重新执行检查。临时文件清理位于 `finally`。未发现这部分引入的 P1/P2 回归。

提交是否确定与请求是否断开分开处理，计费仍依赖原任务绑定的保存回执。新增辅助模块已列入 `release-files.json`，没有依赖序列化错误字段取得可信状态。
