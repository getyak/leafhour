## 两个结论

规格审阅结论为需要修改。窗口规划和取消代次符合设计，书签数据独立保存并使用持久化回执，但 R11 的真实用户导航门禁仍有两个入口问题。R10 在长译文页上的当前位置语义不满足精确返回；R14/R15 的 Markdown 缺译路径也没有使用同一显示契约。

质量审阅结论为需要修改。优先修复下列 P1，再补对应入口测试。现有 Core 结果支持模型行为，不能证明 UIKit 手势、实际翻译入口、VoiceOver 或真机体验已经通过。本报告不以源码推断补足 95 分。

## 可执行发现

### P1：程序跨章也产生翻译所需的新用户凭证

位置：`apps/ios/Leafhour/ReaderScreen.swift:327–328`、`502–508`；`ReaderReadingContent.swift:235–247,258–266`。

开启随读翻译后，听书自动进入下一章时，`followSpeechChapter` 会调用 `session.go`。`navigationID` 的通用观察器随即创建新的 `readingNavigationID`。新章正文产生有效可见页后，`follow` 会接受这个新标记并自动规划下一窗口。用户没有执行新的翻页或滚动，真实用户门禁已被程序导航绕过。自动翻页跨窗口或跨章也应沿同一入口检查。

应只在明确的用户导航入口创建标记，保留现有 user/automatic 来源区分。通用 session 导航变更只能撤销旧范围，不能授权新范围。补测应通过 ReaderScreen 或提取后的入口状态器触发听书跨章，确认请求数不增长。现有 App 测试是手工传入 marker，无法检出接线错误。

### P1：真实滚动开始后，旧窗口仍可连续提交

位置：`apps/ios/Leafhour/TextReadingView.swift:419–427,445–465`；`ReaderScreen.swift:648–654,663`；`ReaderReadingContent.swift:282–287,308–347`。

用户开始长距离拖动或惯性滚动时，TextKit 撤销了可见页并更新用户标记，但 `receiveVisiblePage(nil)` 不撤销正在运行的翻译。章内滚动不改变 session 的 `navigationID`。执行循环只对 `.page` 检查 `page.isCurrent`，对 `.following` 不作此检查。因此，新页稳定前，旧窗口仍可能逐段报价并 POST，直到下一次有效页回报才取消。此时用户已经离开旧页，队列仍在为旧位置提交。

应在真实用户导航开始时立即撤销旧执行代次并取消在途任务，保留显式开关，等待新的有效可见页。重排产生的 nil 不能被当作新的阅读授权。补测应延迟第一段返回，启动章内真实滚动后让请求结束，确认旧窗口第二段不会提交。新页稳定后只规划新窗口。

### P2：长译文页的书签都折叠为原文段首

位置：`apps/ios/Leafhour/TextReadingView.swift:531–557,613–618,714–717`；`ReaderSession+Bookmarks.swift:5–24,46–51`。

`sourceOffset` 对译文 span 固定返回 0。一个译文段落跨多屏时，在任意中页添加书签都会保存同一个原文段首。可见范围也一直是该段的 `[0,0]`，所以段首书签在每个译文页都显示为当前位置。后页的独立添加会被去重，列表返回段首。实现记录已披露此限制，但它仍不能满足 R10 的长段当前位置和精确返回要求。

不要推算虚假的原译文字符对齐。可以为这类位置明确提供“保存对应原文段落”的降级语义，并停止显示精确本页标记。若要满足当前规格，应另外保存可核验的译文快照、译法及显示偏移，同时保留原文锚点和版本。补测须包括译文独立模式与译文在前对照的第二屏。

### P2：Markdown 缺译路径绕过状态标签和对照样式

位置：`apps/ios/Leafhour/TextReadingView.swift:198–211`，对照通常路径位于 `242–260`。

完整 Markdown 窗口尚无任何缓存译文时，译文和对照模式仍进入 `MarkdownChapterLayout.attributed` 捷径。它绕过 `ReadingLayers`，正文没有“译文尚未准备”标签，原文相对字号、深浅和对照间距也不使用下面的真实渲染分支。面板小样会随设置变化，正文保持另一套表现。R14 的缺译状态和 R15 的即时一致性因此受损。

可将这条捷径限定为原版，或者让 Markdown 的缺译渲染也应用同一归属标签和偏好。用无译文的合成 Markdown 在实际 TextKit 中检查属性和标签，不能只检查 Core preferences。

## P2：旧 nil 语言目标需要迁移

`ReaderSession.swift:58` 对所有 `translationSettings == nil` 使用新的 English 默认。旧版英文书如果一直使用隐式中文目标，存档可没有这个字段。升级后会改为 English，旧中文缓存不再显示，并提示原文与目标相同。`TranslationFollowingTests` 只证明显式保存的 ja 仍保留，未覆盖旧 JSON 缺设置且已有中文译文的情况。

主执行者已接受这项 P2，将为旧 nil 设置补迁移，按可核对的旧状态保留原目标。修复与新增测试仍待后续审阅，本报告未将计划计作完成。
