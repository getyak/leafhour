# R1–R2 书架刷新与默认排序独立设计评审

日期：2026-11-05。评审基线：公开仓库提交 `11a89b3b4c047f0230076bfcda4b98d1fd040b26`。对齐 [总规格](../../superpowers/specs/2026-11-05-reading-experience-design.md) 和 [实施计划](../../superpowers/plans/2026-11-05-reading-experience.md) 的 Task 1。

本轮只分析代码、现有测试和官方资料，没有修改或提交产品代码，也未访问真实账号书籍或操作现有模拟器。测试代码存在不等于本轮测试通过，下面的性能阈值均为拟验收标准。

## 结论与取舍

R1 应保留既有书架，再按实际变化更新。当前并非每次刷新都先清空书架：已有 `ForEach` 使用领域 ID。同账号邮箱元数据变化会误走清空分支，这是可由代码确认的缺陷。重复本机载入和两次云端发布需要控制，旧缓存覆盖新回执、视图内重复排序也须测量。不能只关掉动画后宣布卡顿消失。

R2 按总规格采用“最近活动”：排序时间为真实加入时间与真实阅读时间的较晚值。保留 `recent` 存储值，将菜单文案改为“最近活动”。已选书名、作者或加入/书房顺序的用户继续使用原选择。新增导入不改阅读时间、不把未读改成在读，也不顶替“继续读”的真实阅读候选。

设计采用 `design-judgment` 的“时间与注意”和“功能减法”，并用 `swiftui-performance-audit` 检查状态、身份和视图计算范围。刷新要保留现有书的身份与封面，让选中状态和视口保持稳定。刷新只改变有新事实的部分，进度留在独立状态区。

| 方案 | 结果与代价 | 决定 |
| --- | --- | --- |
| 仅禁用书架动画 | 可能减少跳动，重复解码与排序仍在，无法解决误清空 | 不单独采用 |
| 保留内容、去重发布、维护身份、缩小重算范围 | 复用现有组件，可分别验证数据变化与像素稳定性 | R1 采用 |
| 改用整套 UIKit 书架 | 增加布局、无障碍及旧状态迁移工作，现有证据不足以支持重写 | 本次不采用 |
| 新增“最近加入”默认项 | 新书靠前，但之后续读不会回到前面，增加一种常用排序语义 | 已评估，按总规格不采用 |
| 默认“最近活动”，显式其他排序保留 | 新加入与真实续读都可靠前；需要同步修改菜单和测试，说明语义变化 | R2 采用 |

## R1：刷新稳定

### 根因与证据强度

**可由代码确认的缺陷。** `CloudAccount` 的自动 `Equatable` 比较包含 `email`（`CloudLibraryClient.swift:20–23`）。缓存账号和恢复账号的 UID 相同、邮箱不同或从空值补齐时，`reload` 仍会改变 `contextID`、清空书架并重新建立本机库。这与账号切换的真实含义不一致，会让缓存首屏消失。应按 UID 判断切换，同 UID 更新资料而保留库实例和视图。

**可确认的重复工作，运行影响待测。** 初次显示的显式调用链最多有三次本机书架载入，下拉链路有两次。同步两次取得账号回执并各自赋值，即使内容相同也没有相等判断。渲染路径会多次构建 `LibraryPresentation.items`，其中包含排序、去重和过滤。当前材料不足以把每次赋值等同于一次完整屏幕重绘，也不足以声称某个调用已经占主线程多少毫秒。

**可确认的并发语义风险。** `syncing` 为真时，新的强制刷新只设置 `syncRequested` 就返回，当前下拉调用者可能先结束等待。缓存读取只校验账号、上下文和缓存请求 ID，没有校验读取期间是否已有更新的网络快照被发布。延迟的旧缓存结果有机会在更新的网络结果之后出现。

**待 Instruments 归因的假设。** 高数量书目时，重复投影和逐本完整状态解码可能延长刷新。封面解码、任务生命周期及滚动布局也可能参与卡顿。工程使用 Swift 5.9，不能仅因调用来自 SwiftUI 就断言 `BookCoverResource.load` 的全部异步工作在主线程。先看实际调用栈和执行器，再决定具体移动哪些工作。

### 最小完整实现

1. **按账号身份切换。** 在 `reload` 中比较 `restored?.id` 与 `account?.id`。相同 UID 更新 `account`，保留 `library`、`books`、云端快照、任务上下文和书架状态。真正退出或切换 UID 仍立即隐藏旧账号内容并使旧异步结果失效。

2. **有内容时保持内容。** 首次缓存还未读取可显示加载态；读到缓存后，无论认证、网络或后续校验多慢，都维持书架。同步失败留在同一书架上，呈现可重试状态。网络成功回空也必须是经 owner 和完整结构校验的真实空快照，不能把失败解释为空库。

3. **集中发布快照。** 抽出 `applyAccountShelf(_:source:)`，对整个有效回执作值比较，相同回执不写观察属性。比较必须包含书目、封面、阅读、归档和置顶数据，不能只比较 `shelf.revision`，因为阅读活动可能变化而手动书架 revision 不变。每次真正接受网络回执推进代际值；缓存读取捕获代际，迟到时不覆盖更新的云端部分。

4. **合并等待和重复载入。** 给启动、回前台、网络恢复、下拉使用同一个刷新协调入口。复用进行中的工作，调用者等待相应工作完成。强制请求如果需要在当前工作后再查一次，只合并成一次后续任务，并让该调用者等待后续任务。启动缓存读一次，刷新末尾本机读一次；删除调用者重复 `reload`。保留有本机记录/置顶操作写入时所需的第二次网络回执。无写入、无需要重新确认的数据时可只发一次请求。

5. **按展示元数据投影一次。** 由展示层模型维护 `allItems`、`visibleItems`、`visibleIDs` 和“继续读”候选的派生快照，同一有效输入只计算一次。输入包含 owner、书目身份与版本、书名作者、加入/阅读时间、归档与置顶、查询和排序，不对整本 `LocalBook.chapters` 作深比较。进度、同步说明放入单独小视图，状态更新不重排全书架。若先用一次局部变量消除单次 body 内重复计算，仍需测量后确认是否足够。

6. **身份与封面连续。** 保留 `cloud:<bookID>` 与额外版本的 `local:<localID>`，不用位置、临时 UUID 或刷新 revision 作为整架 `.id`。同 owner、同书、同封面 key 的已显示图在任务重启时保留；版本/key 真变化仍校验来源，不能把旧账号图作为新账号占位。真实变化默认不为整架添加隐式动画。

7. **视口和选中状态。** 无实际差异时，不改搜索、筛选、排序、选中项、导航路径或滚动位置。真实增加书目时，上方新增内容不强制把浏览中用户拖回顶部。可见锚点仍在时保留它及相对位置；锚点被真实移除时保留最近仍存在的邻项。只对用户刚完成的本机导入提供“刚加入”及可点定位入口，用户主动点后再滚到那本书。

上述第 5、7 项要先记录基线再选择实现程度：若当前稳定 ID 已满足位置要求，不引入额外滚动协调器；若实测出现位移，才补按 ID 的可见锚点维护。不能为追求低更新次数漏掉真实阅读、置顶或归档变化。

## R2：默认最近活动

### 比较规则

继续保存 `recent`，菜单和无障碍值读“最近活动”。默认组内比较使用：

```text
真实阅读时间 = max(云端实际阅读活动, 此本机版本的实际阅读活动)
有效加入时间 = 云端实际 addedAt
             或纯本机/额外独立副本的 importedAt
最近活动时间 = max(真实阅读时间, 有效加入时间)
```

先按置顶与非置顶分组，各组按最近活动降序。并列时用有效加入时间，再用稳定领域 ID 比较。都无日期的旧书保留可验证的账号顺序作回退，同一输入必须确定性输出。服务数组顺序若随回执无意义变动，使用已保留的稳定次序或 ID，避免反复移动。

不能用收到回执的时间、下载时间、生成封面的时间或同步完成时间代替活动。已配对云端书的本机 `importedAt` 是下载/落盘时间：有真实云端加入时间时始终采用云端时间。云端加入时间缺失时保留未知，不把一次重新下载伪装成刚加书。额外独立副本有自己的本机身份，可按真实副本导入时间排序。

### 场景和预期

| 场景 | 应出现的行为 |
| --- | --- |
| 新导入，默认排序，尚无阅读 | 完整发布后立即进入首个非置顶位置；不等待网络、封面或 AI |
| 旧书刚读过，时间比新书加入更晚 | 刚读的书在新书之前；“最近活动”包含这两种真实事件 |
| 用户已置顶旧书 | 置顶仍在前，新书排在非置顶组前，不擅自取消固定项 |
| 用户主动按书名/作者/加入顺序排列 | 保留选择，新书按该规则出现；导入完成提供书名和“阅读/定位”，不悄悄改排序 |
| 原有 `recent` 存储值 | 保持 rawValue，菜单改为“最近活动”，采用新的比较语义；这项语义变化须记录在交付说明 |
| 搜索或筛选排除了新书 | 保留查询和筛选，不清除用户正在做的操作；完成提示可打开新书，可另给“在全部书籍中定位” |
| 已下载云端旧书，今天重新下载 | 维持真实加入/阅读排序，下载本身不提升活动时间 |
| 相同原件选择“保留原书”或“替换书籍” | 保留原书身份和真实加入时间，不造一条新加入事件；“作为新书添加”才有新副本时间 |
| 重启、离线、跨设备回执 | 用缓存真实时间重建相同顺序；缺日期保持未知 |
| 新书从未阅读 | `readingStatus` 仍是未读；“继续读”仍从真实阅读候选中选择 |

现有 `added` 分支尊重云端手动顺序，保留该存储与行为。建议文案使用“书房顺序”以减少与按日期排序混淆。若本次保留“加入顺序”名称，则菜单现有“云端书籍沿用书房顺序”说明必须保留。不要为新书排序改写服务端手动顺序。

R2 不需要新云端字段或付费调用。改 `LibraryPresentation` 比较器与 `LibraryScreen` 文案，并调整准确表达“阅读时间”与“排序活动”的测试。必要时给 `LibraryShelfItem` 分别增加 `readingActivityAt`、`additionActivityAt`、`shelfActivityAt`，防止相同字段被“继续读”和未读状态误用。

## 性能测量与门槛

先在同一设备、系统、提交、构建配置下记录前后。SwiftUI body 在主线程运行，身份关系影响状态生命周期，这些依据见 [Apple SwiftUI 性能](https://developer.apple.com/videos/play/wwdc2025/306/)、[身份与生命周期](https://developer.apple.com/videos/play/wwdc2021/10022/) 和 [Instruments 性能分析](https://developer.apple.com/documentation/swiftui/performance-analysis)。本节是拟定的产品门槛，不称为 Apple 通用标准。

| 测量 | 做法 | 拟通过条件 |
| --- | --- | --- |
| 书架投影 | 50/200/1000 本合成书，各 30 次；分开计首次、无变化刷新、单条变化、搜索；只测展示转换 | 1000 本热投影 p95 ≤ 8ms；相同输入不反复执行投影 |
| 缓存首屏 | 无缓存、热缓存、冷进程缓存分别记录；认证夹具延迟 2 秒；起点为书架任务，终点为缓存书可点击 | 有缓存时先于认证完成显示；200 本缓存 p95 ≤ 300ms。首次无缓存与大库数据解码单列，不删样本 |
| 导入后可见 | 起点为本地原子发布完成，终点为默认排序首个非置顶新书可操作；不计文件提取耗时 | p95 ≤ 100ms；不依赖网络/封面/AI；显式其他排序单列 |
| 刷新每帧稳定性 | 列表/网格中部，20 次相同回执及实际增量，至少 60fps 录屏；标出 refresh begin/apply/end | 无变化回执期间不出现临时空架、整架封面回退；静止内容锚点位置误差 ≤ 2pt |
| 卡顿与主线程 | Release/Profile，SwiftUI、Time Profiler、Hangs/Hitches；固定 30 秒滚动+刷新脚本，至少 5 轮 | 目标脚本无 ≥100ms 挂起；hitch time ratio ≤5ms/s；报告实际刷新率，不能把平均 FPS 当唯一结果 |
| 请求与磁盘 | 统计 fixture 请求、账号快照、缓存/状态解码次数，按刷新原因记 aggregate | 相同快照不发布；无记录变更时不产生无用途的二次 shelf 请求；单次刷新本机扫描至多一次 |
| 内存与解码 | 相同脚本测峰值及连续 10 次刷新后稳定值，统计同 cover key 重复解码 | 无随刷新次数持续增长；热刷新相对基线峰值增长 ≤10%，记录绝对值 |

标记只写事件、数量和耗时，不写书名正文、账号邮箱、令牌或访问 URL。记录 p50、p95、最大值、样本数、设备和构建配置。模拟器可证明功能和相对趋势，不能据模拟器 FPS 声称真机已验收。若达不到门槛，保留结果和瓶颈，不更改阈值来凑 95 分。
