# 托管翻译容量与上下文复审

日期：2026-11-05。只读核对本次四个文件的 diff 与实际调用链，未修改产品代码，未运行测试。报告不加入 release-files。

限定改动未发现新增的权限绕过、计费变化或平台容量保护失效。此前免费路径跳过计费 scopeFor 的长度检查，这次已由 library.translate 的通用生成前守卫补齐。

- 容量仍由同一份 `limits/translation` 和 CAS 原子修改维护。每小时100次、每日500次、全局2并发、同账号同书排他及原租约均保留。并发或容量拒绝分支在 push 前抛错，不会消耗一个成功预留。新增测试静态覆盖100/101小时边界、500/501日边界、跨账号并发和同书排他。本报告不把测试源码等同执行通过。
- 新守卫位于缓存命中之后、锁和 hosted reserve 之前。当前段超过4,000个 Unicode 码点时提前返回413。当前段与相邻段的 JSON 超过24 KiB同样拒绝。传给供应商的正是已检查的 translationContext，免费、计点和本地领域调用均经过此处。已有完整译文继续读取，不因新生成限制隐藏旧结果。
- 大邻段先检查 UTF-8 字节数，超限时不会继续 JSON 序列化。正常额外工作最多遍历4,000个当前段码点，并检查三个段落。每段通过字节检查后才序列化。既有整书读取与克隆未由此改动消除。本次没有性能实测，不能给出新的延迟承诺，也不能把免费路径描述成已有固定美元预算预留。

个人10次/小时、50次/日的移除作用于所有托管翻译入口，包含 iPhone、Web 与直接 API 调用。单账号可占满平台容量，是这次明确的公平分配取舍。平台请求总量并未提高。它不授予其他账号或书籍访问权，不开启计费，不修改报价，也没有新增客户端豁免字段。文档应将此记为适配本轮持续随读的实现取舍，避免写成用户另行明确取消全部翻译限制。

长段现在会明确失败，这是有界生成契约的落实。大书导入仍应使用短段验证翻译，不能通过恢复超长供应商上下文来让旧夹具通过。最后读取的邻段夹具已用左右各5,000汉字包住短段，覆盖单个邻段未超字节限额、合计上下文超限的分支。最终运行结果以主执行者的受影响测试及构建记录为准。此前全套通过不能代替本次验证。
