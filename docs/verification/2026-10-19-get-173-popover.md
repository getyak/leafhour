# GET-173: stock Chrome 113 popover compatibility

Status: source candidate verified locally; current-head CI, actual three-platform
screenshots, merge and production acceptance remain pending.

On the Android API 34 stock Chrome 113 acceptance run, the closed library filter
painted over book cards. The [original screenshot](get173/8912b1f-android-library-before.png)
and [rejected run](https://github.com/getyak/leafhour/actions/runs/39162519203)
retain the failure. [Chrome introduced the Popover API in version 114](https://developer.chrome.com/blog/introducing-popover-api).
The same missing capability also made JavaScript `:popover-open` queries throw.

## Implementation

`popover-controls.mjs` owns one controller per real element. Supporting browsers
retain their native top layer, declarative triggers, light dismissal and toggle
events. Older browsers use `hidden` and `data-popover-open`, a scoped layer,
Escape and outside pointer/focus dismissal. Initial CSS hides closed markup
before JavaScript loads. Focus returns only to a connected, visible, non-inert
opener when the user has not deliberately focused another surface.

The library filters, dynamic book menu and reader book info use this boundary.
Palette, conversation, companion and toolbar guards use its safe open-state query.
Filter history, choice clearing, current book-menu trigger and owner reset remain
connected to the existing controllers.

The reader keeps basic metadata and close controls eager. An actual book-info
open loads its optional introduction/share enhancement once, through
`reader-book-actions-bootstrap.mjs`. It injects the exact same popover handle;
the external enhancement does not create a second registry. Primitive book,
content-version and owner stamps plus a generation fence cancel stale work on
close, reset, session change or page leave. A late import can cache code but
cannot mount private UI, request an introduction, construct a gift controller or
move focus after cancellation. Failure exposes an explicit retry.

One precise dynamic-import edge was added: `reader-book-actions.mjs` only from
`reader-book-actions-bootstrap.mjs`. The original six importer/kind fences and
320KiB JavaScript / 200KiB CSS caps remain unchanged. The shared popover controller
stays eager. Both static server maps and the release allowlist register the new
modules. Records and screenshots under `docs/verification/`, along with runtime
data, are outside that allowlist.

## Independent review repairs

Three checkpoint P2 defects were reproduced against the actual modules and fixed:

1. Terminal disposal removes action listeners, keeps controls inert and fences
   late gift-controller construction. Ordinary close preserves unsent drafts.
2. The whole import-and-setup chain consumes failures and rolls partial setup
   back; an explicit retry does not duplicate listeners or dialogs.
3. Late mounting and return focus reject computed `visibility:hidden/collapse`
   as well as detached, hidden, inert and zero-box triggers.

Final integration review also found and repaired the gift dialog's broken heading
reference and a bootstrap status clear that erased the enhancement's pending
introduction announcement. Both new production regressions failed before their
fixes and passed afterwards. Status ownership transfers before enhancement mount.

A composition review also found that the five-second toolbar timer could hide
the info opener while its enhancement was still loading. The same timer now
holds while a dialog or owned popover is open, observing both `open` and
`data-popover-open`. Native and fallback composition regressions cover a
six-second import, a long-open popover, Escape to the still-visible opener, and
normal timer release after focus leaves. The visible-opener guard and remote
readiness timeout were preserved.
