## Repair batch (independent review freeze1) — defects closed

1. **P1 bootstrap never opens** — `mountPaletteBootstrap.open` now runs
   `controller.open(opener)` on every gesture (first open and reopen after
   close), the controller factory runs once (one dialog owner/keyboard listener
   set), a failed import resets the cached loader for retry and reports through
   a visible `role="status"` notice instead of an unhandled rejection.
   Tests: "the bootstrap actually opens the controller, reopens after close…",
   "a failed palette import is visible, safe and retried…",
   "the real dialog controller keeps one owner and listener set…".
2. **P1 private owner cache boundary** — `createPaletteLibrary` fences owner
   state in view/search/load/adoption; `subscribe` hooks plus
   `invalidatePaletteLibraries()` wire synchronous invalidation into real
   lifecycles (portal.js `clearPrivateUI`/adopt; reader `reader:session-changed`
   dispatched from reader-conversation's established session guard). Rendered
   DOM and cached search clear synchronously on transition; no-adapter pages
   clear before fresh session verification on reopen (no previous-owner flash).
   Tests: palette-library owner tests, "owner transition clears rendered
   results…", "page account lifecycles synchronically invalidate…",
   reader-conversation session-change notification test.
3. **P2 async load refresh / HTTP errors** — load settlement refreshes the
   already-typed query; `response.ok` is checked on session and library;
   HTTP 503 renders as error (never ready-empty) with a real retry action;
   loading/error/empty announce even when page commands also match.
   Tests: "load settlement refreshes the typed query and errors offer a real
   retry", palette-library HTTP/session error tests.
4. **P2 fullscreen adapter dropped** — the fullscreen command falls back to the
   production `adapter.fullscreen` (reader.js registers it); the default no-op
   no longer wins. Test: "reader fullscreen runs through the production palette
   adapter path" (uses the exact adapter shape reader.js registers).
5. **P2 night palette contrast / targets** — command-palette.css now derives
   every colour from the owning page's theme-aware tokens (reader
   `--panel/--wash`, home/library `--surface/--surface-soft`, consoles
   `--paper`) with ink-mix fallbacks, reuses shared hairline/focus/shadow
   tokens, reserves input trailing space so text never runs under the close
   control, and sizes close/options/input to the shared `--action-target`
   (44px). Native 1200/390 paper/night contrast review remains parent-owned.
6. **P2 home body shell** — home.html keeps its byte-exact `<body>`; the palette
   page kind resolves from the existing `library-page` class (or explicit host
   metadata) and the self-mount gate keys off real palette hosts. Test runs the
   actual `portalDocument` output for `/` and `/library` (body replace, full
   authored content, GET180 card markup) plus page resolution.
7. **P2 coordinator holds across both surfaces** — the coordinator holds the
   single conceal timer while the focused header is hovered or focused (the
   panel holds were already wired); header targets stay operable while held.
   Tests: "composed tools hold concealment while the focused header is hovered
   or focused" (real toolbar+immersion composition).
8. **Architecture not ratified (bundle budget)** — the unauthorized
   reader→bootstrap immediate edge is gone. `palette-bootstrap.mjs` is
   statically bundled (it is the palette's whole initial cost);
   `command-palette.mjs` + `palette-library.mjs` load only on a real gesture
   behind the permitted `command-palette.mjs`/`palette-bootstrap.mjs` fence. No
   new lazy module/caller exists: the prior five exceptions are preserved and
   the launcher drag positioner left the reader bundle via dependency
   injection (portal.js supplies it to the library launcher). Initial JS now
   fits without raising any gate. Tests: build-graph tests assert the real
   graph (bundled bootstrap, lazy palette, no reader→bootstrap edge, wrong
   callers stay bundled), and the bootstrap test asserts no import happens
   before a gesture.
9. **P1 hover reveal steals focus** — pointer reveals pass `focus:false` through
   `onExpandedChange` → `showTools({focus})`; hover never moves `activeElement`,
   explicit click/keyboard may focus the revealed header. Test: "composed tools
   keep hover reveals from stealing focus while explicit clicks may focus"
   (real module composition).
10. **P2 legacy companion default API** — the default (generated launcher) API
    works again beside injected mode: launcher described-by and message dot
    wiring preserved, both modes covered with once-instance/dispose fixtures.
    Test: "the default standalone companion API keeps working beside its
    generated launcher" plus the injected fixture.
