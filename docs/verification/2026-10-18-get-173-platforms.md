# GET-173: actual platform typography acceptance

This adds a remote anonymous acceptance harness and repairs the stock-platform CJK fallback and catalog checkout defects it exposed. The scoped workflow runs installed Chrome on standard Ubuntu24.04 and Windows2025 hosted runners. It checks the exact PR head and records actual OS/image/browser versions. No system font installation, paid device service, credentials, user records or provider calls are used. Source development remains on macOS; local user browsers are never driven by this script.

The actual home, authored Chinese home, library and source reader run through `createReaderServer` with isolated temporary data and all providers disabled. The cold test withholds the font request, observes fallback glyphs on the actual hero, captures it, then releases the request and captures loaded text. This is a controlled delayed-font condition, not a natural-network performance benchmark. Actual browser font response bytes must match source SHA256. `CSS.getPlatformFontsForNode` records real glyph usage, custom status and PostScript names on direct text nodes. An inherited span isolates the actual public Alice title apostrophe for glyph/width inspection; original strings remain unchanged. The reader citation uses the actual public source package's stable passage ID and content version, then checks that passage's visible original italic glyphs.

Machine assertions cannot judge CJK serif quality, mixed-script baseline harmony or visual resemblance across operating systems. Every screenshot and stock-font report must be reviewed before claiming those criteria. Windows Server2025 proves that environment, not all Windows desktop installations. The workflow keeps at most seven anonymous PNGs, stock font inventory and one receipt per OS for three days; runtime records and browser profiles are excluded from artifacts.

## First actual run and repairs

PR125 head3b8fb83 ran both actual OS jobs. Linux Chrome155.0.8059.39 rendered the Latin hero in Newsreader, but the stock image contained no CJK font: language links appeared as boxes and the Chinese heading used Newsreader missing glyphs. The test correctly failed. Windows failed before browser startup because Git autocrlf rewrote structured catalog JSON: Flatland source036a5e8f… becameb3a78ab3… despite equivalent parsed JSON. Neither run is an acceptance pass.

The repair preserves `catalog/world/*.json` original bytes with Git attributes, retaining all content versions and passage IDs. An actual autocrlf checkout counterexample reproduced529CRLF changes; after the attribute fix the original036a5e8f… SHA was restored. A focused regression verifies every structured original, not just Flatland.

The CJK repair adds88 unchanged OFL Noto Serif SC WOFF2 subsets from the official Google Fonts endpoint,5,891,588bytes total. CSS restricts selection to actual CJK cmap ranges, leaving Latin and proportional punctuation with their existing fonts. Local Songti/Noto Serif CJK faces stay ahead of the web fallback. Interface sans stacks use it only as a final CJK fallback; this does not make every platform's UI the same sans family. Independent fontTools4.67.0 verification found12,834 declared real codepoints and removed116 unsupported upstream compatibility aliases. An independently pinned bundle test verifies all bytes and ranges. Font CSS is self-hosted, uses swap and does not preload all subsets; actual whole-page requests and bytes are captured rather than estimated from visible characters. Chat, source review, evaluation and Canvas font boundaries use the same fallback; Canvas explicitly requests only its card model’s unique CJK characters before measuring.

Local focused verification: the28-test sharing/HTTP run initially exposed one test-buffer limit; after bounding Git output at16MiB, all11 CJK/typography tests passed. The sharing and typography HTTP tests had already passed unchanged. The software release allowlist now contains676files, including every font asset and the serving module. These are local code/integrity results, not a cross-platform pass.

The repair also updates the public-build validator with an independent CJK pin and keeps unknown, changed, jointly forged assets rejected. The reader bundler permits only the exact approved font-face import from typography.css. Canvas font loading is a caller-fenced on-demand module: initial reader JS327,227bytes and CSS164,219bytes stay within their existing budgets. The latest CJK/reader-build/sharing test group passes28/28, and the actual hosted build, public asset validator and676-file release allowlist pass.

The repair commit69465ec passed full CI. Both real OS jobs passed all30 source-byte checks and rendered the four Chinese language characters with valid CJK faces (Linux Noto Serif SC, Windows Microsoft YaHei). Their language-link assertion still failed because CDP also reports the actual CSS-generated middle-dot separator in Liberation Sans / Segoe UI. This is a harness classification defect, not evidence of missing Chinese glyphs. The revised probe preserves the original parent font record and wraps only existing CJK text runs, checking original text, glyph widths and overall layout remain unchanged before checking their actual font usage. The next run2169c31 exposed two further harness assumptions: Linux encountered an invalidated protocol node after navigation, and Windows reached the reader but rejected its existing deliberate removal of consumed citation parameters. The probe now waits for the actual ready state, records and re-resolves one specific invalidated node ID, and validates the actual reader book/version/layer plus already-visible stable passage before any probe scroll. Only the unchanged requested URL or the existing exact book-only cleanup URL is accepted. These revised remote assertions and remaining screenshots still need to run and be reviewed. Android still needs an actual official SDK environment and stock browser; a desktop390px viewport does not satisfy it. GET-173 remains In Progress until all required environments and visual criteria have evidence.
