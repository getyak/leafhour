# GET-427: Bottom AI navigation and finite chat scrolling

Request: restore the iPhone's bottom AI entry, unify the shelf/journal profile and settings, and investigate dragging beyond the end of a conversation.

## Implementation

- The native bottom bar has Bookroom, 松鼠 AI, and My Reading. The shelf's top-right leaf action is removed. All three pages use the existing native pager.
- Shelf and My Reading use the same account-scoped avatar component, in the top-left corner, and open the same complete settings screen. Its account row uses that avatar too. Account identity, login, existing avatar choices and stored reading data are retained.
- Global AI is a full tab. Book-specific reading conversations retain their half-sheet presentation and first-sentence positioning. Global conversations follow the newest reply until the user browses history; browsing still preserves the earlier passage.
- The conversation's own vertical scroll view stops at its actual content boundary. It does not change the root pager, journal, book reader, or global UIKit appearance. The focused composer offers an explicit keyboard-dismiss action in portrait and landscape.

## Investigation

The old conversation applied `.scrollBounceBehavior(.always, axes: .vertical)`. A hosted native test confirmed `bounces=true` and `alwaysBounceVertical=true` for both a short and long reply. The short case had only 353.67 pt of content in an 844 pt viewport, yet still forced vertical overscroll. The regression test failed before the correction (one test, four assertions).

This establishes an unbounded *gesture affordance*, not an unbounded history download. No claim is made that message count or content height grew indefinitely. The fix disables overscroll only on the owning history scroll view while retaining normal scrolling, text selection, history virtualization and keyboard dismissal. Apple's [UIScrollView.bounces contract](https://developer.apple.com/documentation/uikit/uiscrollview/bounces) specifies that `false` stops at the content boundary. SwiftUI can refresh the separate `alwaysBounceVertical` preference during layout; the regression asserts the effective `bounces` boundary and retained scrolling, rather than requiring that inactive preference to stay false.

The first UI run additionally exposed a distinct positioning mismatch: the root AI tab still used the reading-margin mode. The third long reply was present, but screenshot OCR showed ROUND2END followed by the third reply's opening rather than ROUND3END. Global chat now uses its ordinary latest-message anchoring; the reader's margin mode is unchanged. A missing portrait keyboard-dismiss control in the draft-switch test was also corrected.
