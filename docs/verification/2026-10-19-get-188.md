## 关键决策（与设计一致的落地口径）

- 关闭原因：user / navigation / auth-handoff / palette-handoff / breakpoint。仅 user 关闭返回初始
  opener；断点关闭回退可见品牌；auth 与 palette 交接先关闭 sheet、聚焦真实可见菜单触发器、再立即
  打开既有 auth / 发出 palette 请求；导航关闭不被后续焦点恢复抢走。
- 同页锚点不 preventDefault（保留默认滚动）；一个受保护的 destination RAF 聚焦真实目标；
  已有 tabindex 原样保留，仅在目标完全没有 tabindex 时补标准 `-1` 焦点入口。
- 续读行仅来自 `chooseCurrentBook` 的真实当前进度，链接仅用 `readingBookUrl(book, null)`
  （book-only 协议，GET-186 阅读器独自验证恢复完整续读）；书名/作者直接 textContent，不经 homeText。
- palette setup 失败重试修正：历史复现显示「两次显式 open → import 1 / setup 1 / open 0 / notice 0」
  （失败不可见且拒绝链被缓存）。修正回归断言修复后行为：拒绝缓存被清空后 import/setup 会重试、
  notice+retry 可见且随成功消失、只回滚自建部分 DOM/监听、不产生第二个控制器/浮层、不抢新 modal 焦点。

## 上一候选的真实失败事实（已确认，非推测）

候选 1 在真实原生 Chrome、隔离 ReaderServer（仅 `/command-palette.mjs` 一次 503）下：
初始触发器、再次触发、notice 重试、重试键盘回车共四次操作，只有一次 GET 到达服务端；
其后全部命中 Chrome 已安装的失败模块映射缓存。`loading=null` 只重置 JS promise，
纯注入式 import 重试测试通过并不等于真实浏览器可恢复。截图中打开视口内没有任何错误
提示，须滚动整页到底部才能看到 body 尾部的未样式化 notice。

## 修复对应与实现口径

1. P1 导入恢复：初始字面量 `import('./command-palette.mjs')`；仅 import 阶段被拒后，
   显式重试用恰好一次字面量 `import('./command-palette.mjs?retry=1')`；setup/open 失败
   复用已载入模块身份（不再次 import）；有限重试用尽后仅剩手动触发的「重新加载页面」
   兜底（不自动刷新、不丢草稿、不伪装成模块重试、不宣称对任意依赖失败可恢复）。
2. P2 可见反馈：notice/重试/重载兜底固定于当前视口，paper/night/interface token，
   共享样式入既有 `interaction-craft.css`；成功后隐藏；不强制焦点、不新建 modal。
3. P2 同 owner 刷新：`refresh()` 每个 generation 起始同步清除可选续读行，integration
   回归直接执行 app/portal.js 的真实 refresh 函数体（非手动调用 clear）覆盖 pending 与
   失败两种路径。
4. P2 身份行：session 采纳后立即 `updateIdentity`；回归覆盖「已登录 + library 失败」
   与 owner 过渡（guest→登录→登出）及陈旧 revision 拒收。
5. P2 结算栅栏：adapter 新增 `getOwnerToken`（ownerScope 的 owner+revision 单调 token），
   `getOwner` 仍返回真实 user id/null；成功与失败副作用同栅栏；回归覆盖 A→B 拒绝后
   不弹 notice、A→B→A 令旧请求失效、后续有效请求正常打开。
6. P2 setup 回滚：内部创建的 palette library 在 setup 失败时被 dispose（订阅释放、全局
   实例移除，用真实 createPaletteLibrary/invalidation 计数验证）；外部注入的 library
   不被 dispose；DOM/监听只回滚本次 setup。

构建策略：唯一新增外部件为 `app/palette-bootstrap.mjs` 的动态 import 字面量
`./command-palette.mjs?retry=1`，映射同一 `app/command-palette.mjs` 发布条目；错误
query/错误调用者/静态 import/缺发布条目均被策略拒绝（5 个真实构建夹具回归）。原 7 条
lazy 例外与 320KiB/200KiB 上限未动。父任务补齐发布 import 覆盖检查：移除 URL 的
query/hash 后核对实际发布文件，同时检查引号与静态模板字面量，不能靠更换定界符
避开扫描。重试使用普通引号字面量；缺失背书文件仍失败，构建围栏继续限制精确 URL。
