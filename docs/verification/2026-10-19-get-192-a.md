## Implemented and independently reviewed boundaries

- A single external mutable runtime owns UI language. English is the complete
  initial/default catalogue. Explicit language changes validate and load first,
  commit history before preference storage, preserve current same-context
  query/hash/history state, and fence stale navigation and retry work. Failed
  storage is session-only; failures do not silently save English.
- The Acorn graph audit follows actual app/server/api/deploy import syntax,
  checks lexical shadowing and executable URL aliases, fails closed on opaque
  imports/requires, and permits only physical UI owners and six fixed non-English
  catalogue edges. Pure shared helpers receive formatting through their callers.
- Auth errors carry bounded semantic IDs through actual local/hosted service,
  public JSON adapter, owner scope and dialog flow. Labels do not restart
  requests, timers or cooldowns, clear inputs, or move focus. Unknown errors use
  a truthful generic message. Server/client return validation preserves exactly
  one supported language across reader, upload and 43-character gift returns;
  duplicate/conflicting values are rejected.
- Profile, reading preferences, shell account chrome, appearance, palette,
  home navigation, filters and choice controls use owned IDs and label-only
  updates. Palette navigation preserves UI language, disposal permits a clean
  remount, and home locale events perform no identity/library reads. Choice
  labels preserve the displayed candidate set, keyboard selection, IME and
  selected values; cancelled IME applies the deferred closed-control label.
- Upload progress retains cached semantic state per operation/owner, without
  replaying upload calls on a locale event. Actual book titles, filenames,
  source excerpts, questions and AI prose are not treated as translation keys.

Independent frozen-source reviews have closed the original runtime and
navigation P1 findings, URL-alias and gift-query findings, and choice keyboard/
IME findings. This does not constitute complete A or B acceptance.

## New owner work awaiting follow-up review

- PDF onboarding owns progress/consent/action/preview chrome. Language events
  retain job IDs, consent state, progress, poll timers and original excerpts.
  Preview completion is fenced by owner, generation and latest preview intent;
  closing or cancelling the dialog invalidates outstanding preview publication
synchronously before the native close-event task. Older row
  requests still release their own busy controls.
- Book actions own information/menu/archive/trash/calendar chrome. Each physical
  trigger is tracked separately; replaced nodes are removed immediately and
  other detached nodes are pruned after synchronous batch mounting, and stale menu rejection cannot overwrite a
  newer view after clear/dispose/new menu. Only an explicit calendar submission
  generates localized ICS prose; UID, times, recurrence and source URL semantics
  remain unchanged.
- Library data owns backup/restore/selection chrome, status descriptors and
  record-type labels. Language changes preserve checkboxes, selected book,
  format, preview bytes, textarea selection and focus. A new explicit Markdown
  preview receives localized fixed labels. JSON and archive schemas and all
  literal user/source/AI content remain unchanged. Pending operations cannot
  resume after owner invalidation/disposal; cancelling a pending restore-start
  acknowledgment still clears that operation's staged slot.
