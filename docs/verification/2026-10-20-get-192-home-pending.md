# GET-192: preserve authored navigation during initial catalogue loading

Post-merge acceptance of PR #133 found a new P1: on a non-English home page, the navigation owner synchronously stamped the runtime’s temporary English state onto canonical links before the selected catalogue settled. A fast native click on the Simplified Chinese home reached `/library?ui=en`. Holding only the Japanese catalogue response on actual Production reproduced `phase=pending`, authored `lang=ja`, and the incorrect English CTA; after settlement the CTA became Japanese. The prior CI and Production smoke passed but did not cover this click window. GET-192 remains unfinished pending the corrective PR and same-commit live acceptance.

The existing locale runtime now exposes a navigation-only choice: before its first settlement, a recognized authored route keeps its path language. After success or honest fallback, every navigation choice uses the effective locale, including all later pending requests. `uiHref` uses this choice; OAuth return construction and command-palette home/settings/calendar destinations use the same helper. `getUiLocale`, catalogue formatting, document language, source data and transaction/storage semantics are unchanged. The home controller accepts the same default runtime as an optional test port; it holds no additional readiness flag or language state. There is no extra timer, runtime owner, model request, visual component or catalogue change.

Regression coverage mounts the actual controller with the real locale runtime and deferred catalogues for Japanese, Simplified Chinese and Traditional Chinese: pending links, success, failure to English, retry, account/resume links, actual portal-owned link and auth-return construction, command-palette destinations, canonical-library behavior, physical node/focus retention, unchanged identity/book reads and disposal before settlement. Six cases failed against the prior implementation. The regression suite also checks all nine localized home/MCP/privacy routes before initialization, during first pending, after fallback and retry, plus later-picker failure and preference-write boundaries. Related home, portal, runtime, transaction, palette, OAuth and module-graph tests are run against the final change. These are local deterministic results; current-head CI, exact Production and final browser acceptance remain separate delivery gates. Screenshots and prior broad native evidence remain in the original integration report; this correction does not claim they cover the newly discovered pending window.


The first corrective CI failed two test gates, retained as failed evidence: new test catalogue imports used a computed prefix that the release-import guard correctly rejected, and an existing gift-download test assumed WebCrypto completed after eight event-loop turns. Tests now use the three explicit static catalogue imports, and the gift fixture awaits actual next-part and download-blob receipts under a bounded test timeout. Package-byte, hash, operation, UI-language and saved-status assertions remain. No production file or gate was changed by this CI correction; the four product files remain identical to the reviewed native candidate.
