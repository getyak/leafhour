## Reusable source and boundaries

- `tools/get273-mirror-control.mjs`: one admitted touch command/native call, zero move queue. Every begin/move checks the inherited real live owner; frame checks before capture and before delivery. End of an owned gesture bypasses the owner check so lease loss cannot prevent its release. State clears only when that end promise fulfills. A failed or pending end remains active/uncertain.
- `tools/get273-mirror-adapter.mjs`: fixed existing Primary `02B4F0C1-A92F-469D-9DCC-5ED13F119507`. Only `/`, `/frame.jpg`, `/touch` on a random `127.0.0.1` port. Exact Host, supplied Origin, POST Origin and fixed body schema are validated. Frame and touch both require a fresh memory-only header capability. No Cookie is emitted/read; client requests omit credentials. A different localhost port cannot embed a frame using a host-wide cookie. Capability values never enter URLs, logs, reports or the freeze.
- The actual page coalesces moves into one latest point and serializes requests. A pointer hold released before begin acknowledgement is preserved for at least its recorded duration **after that acknowledgement**, with compensation capped at 1,200ms. The final unsent move is delivered before end. Cancellation/blur bypasses this dwell. This is a bounded scheduling policy; actual OS gesture recognition still needs native frames and product/selection evidence.
- `tools/get273-mirror-runtime.mjs`: signal handling exists before the first native resource construction. Persistent SIGTERM/SIGINT handlers stay installed during blocked cleanup. Startup, close, receipt failure or unresolved native work retains a live owned child and a blocked state. Blocked/uncertain paths have no forced exit or kill. The actual entry now shares the reviewed `createAdapterRuntime` construction, which requests normal process exit only after all close operations and a synchronous stopped receipt succeed; startup failure remains exit 1. Actual-entry retained-handle tests cover the wiring.

The native call deadline is 2 seconds; the hold watchdog is 5 seconds; the release receipt wait is 3 seconds; frame and handle-close deadlines are 2 seconds. A deadline reports uncertainty and prevents new input; it **does not cancel an underlying native promise**. Once a pending begin/move settles, its own end is attempted without admitting new moves. A failed end is not retried in a loop.

`operationsQuiescent` proves only that this JS controller has no active or in-flight work. `cleanupComplete` proves only completion of the owned close promises and receipt write. The native Swift method returns void and may return without an OS acknowledgement; `osReleaseVerified` therefore stays false. Neither field alone attests a physical up, long press, continuous capture or Safari selection. Keep actual pre/post frame evidence and passive synthetic selection observations separate from these lifecycle receipts.
