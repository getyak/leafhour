# GET-143 · 本机实例目录与持久化验收

任务：[GET-143](https://linear.app/getyak/issue/GET-143/建立本地阅读服务与稳定内容个人记录存储)。设计及固定 S1–S8 标准见 [实现前计划](../superpowers/plans/2026-10-17-get-143-local-instance-storage.md)。开始基线 `1ca9bcc0e9214cf60abf2f5b8d8e64411424f76c`；实现后安全同步 PR #62 的最新基线 `62d89cfc9a4119c62d00384b8f9d76e573c30109`，相对该基线审查与验证。

## 根因与实现

标准入口此前没有把实例路径传给 `createReaderServer`，因此即使提供 `READER_DATA_DIR`，本机状态仍会写到源码下的默认位置。先运行真实 CLI 回归：子进程只获准写入合成测试目录，旧入口尝试写默认 `local/service/portal/auth`，被拒绝并触发预期失败；没有真的向默认书房写入数据。接入 `recordsPath` 后，同一测试通过，既有构造函数将书库、身份、个人记录、对话与音频状态统一派生到所选根目录。默认路径、JSON 格式和托管存储保持兼容。

安装阶段另复现 npm 12.0.2 的 `EALLOWREMOTE`：锁文件的旧 npmmirror 解析地址与默认 npmjs registry 不同。首个项目 `.npmrc` 映射方案在默认 registry 下安装成功，但独立 reviewer 发现混合主机在用户选择镜像 registry 时仍会被 npm 12 拒绝。最终移除这份配置，仅将 743 个旧镜像的锁定解析地址规范化到 npm 官方主机，继续由 npm 原生规则映射用户 registry。机械比较证实除 `resolved` 外所有字段、版本及 integrity 完全一致，`package.json` 未改。保留 `allow-remote=none`，没有重算依赖图、升级包或修改用户全局 npm 配置。最终本机干净安装成功，690 个当前平台依赖包在 44 秒内安装完成，安装后的 package 文件与源码逐字节一致。本机安装使用 `--ignore-scripts`，正常安装仍由当前提交 CI 验证；安装日志有既有 `node-domexception` 弃用提示，不是零警告安装。

## 已验证的行为

本机使用 Node 22.23.2，`node:test` 串行执行 8 个相关测试文件，**78 项通过、0 失败、0 跳过**；其中新增的 5 项 CLI 边界测试覆盖默认值、空值、真实重启及独立目录。标准输入/输出、HTTP、文件存储和进程退出均使用真实实现，没有模拟服务或付费模型调用。

## 范围限制

本机 JSON 实例一次只支持一个服务进程；多实例需使用不同根目录与端口。本次不引入跨进程数据库锁、不搬迁用户已有数据、不改托管数据目标。合成账号和本机 HTTP 验证不能代替真实邮箱、Supabase 迁移或真实用户试读。生产仍沿用既有仓库 main 的 CI/Vercel/Production 流程；不使用本机成功或网页 200 提前宣称发布完成。
