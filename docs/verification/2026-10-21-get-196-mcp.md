# GET-196 reading skill and OAuth MCP

Date: 2026-10-21. Scope: this issue only; no OCR, model generation, new provider account or preview deployment.

## Implementation

The repository now includes the installable `skills/leafhour-reading` skill and a stateless Streamable HTTP MCP endpoint at `/api/mcp`. DCR and authorization-code/S256 PKCE reuse the existing authenticated website session and one-book domain grants. Remote grants last one hour and permit only text/source reads. Existing stdio grants and tools remain compatible. Website OAuth login retains a strictly validated opaque MCP consent return.

Public metadata, authorization, consent, exchange and revocation route through the existing server/function. The browser consent captures one verified owner and selected book; remote tools cannot select an owner or read notes, conversations, activity, audio or write actions. Hashes, bounded state, CAS/local locking, single-use codes, request-time authorization, same-origin CSRF protection and persistent throttling enforce the boundary. Client labels are explicitly unverified; URLs in DCR do not cause server fetches.

Reference research checked Tencent/WeChatReading README and Apache-2.0 license. No reference code or installation script was reused. OpenAI's current [authentication](https://developers.openai.com/plugins/build/auth) and [connection](https://developers.openai.com/plugins/deploy/connect-chatgpt) guides establish the supported DCR/none/S256 path. MCP SDK 1.x remains on its existing negotiated protocol.
