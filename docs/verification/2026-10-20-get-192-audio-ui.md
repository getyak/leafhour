## Fix round 1 — P2-1 scene-source wait fence

The independent review of `3296355d962ee5bd585136a998b5b2355900fe0d` found that `ensurePassages()` bypassed the API disposal fence: Ask could emit a stale question and source loading could replace a newer preferences panel or mutate playback after teardown. The initial lifecycle claim above has been narrowed to the paths actually tested at that checkpoint.

The two actions now capture the reader bridge, account owner, book ID/version, session ID, immutable clip ID/index, playback epoch, audio-panel revision and a local scene generation. Each successful or rejected wait checks that ticket before any UI/media/storage/event side effect, including the caller's wait around the scene helper and the second source wait. Reader-ready/session-change events and actual clip changes invalidate the generation, detecting observed owner/book and clip ABA transitions. A locale commit does not invalidate it. The source action applies its pause/position effects only after its final wait is accepted (or an accepted current failure), and a new question uses the captured owner/book.

The [initial RED receipt](2026-10-20-get-192-audio-ui/fixround1-red.json) records 45 failed and 7 passed among 52 new actual-callback cases. A separate [six-case RED](2026-10-20-get-192-audio-ui/fixround1-clip-red.json) verified that clip IDs must be captured as values rather than read back through the mutable clip object. The final [related-test receipt](2026-10-20-get-192-audio-ui/fixround1-related.json) and [TAP](2026-10-20-get-192-audio-ui/fixround1-related.log) record **97 passed, 0 failed**, exit 0, across the actual audio owner, legacy audio UI and unchanged typed-transport assertions. The final set contains 58 new scene-wait cases: both waits, success/failure, replacement panel, stop/replacement session, clip replacement/ABA, owner/book ABA, disposal and valid completion through four locale commits. No full repository suite was rerun for this correction.

The [fix-round actual build](2026-10-20-get-192-audio-ui/fixround1-build.json) still rejects **342780 JS bytes**, **15100 over** the unchanged 327680-byte cap (768 bytes above the reviewed checkpoint). The CSS cap is unchanged and the JS guard still prevents a passing build claim. All measurements ran after the narrow tests, with no simultaneous build. This correction is submitted for the parent's independent re-review; it does not close native acceptance or the aggregate release budget.
