## Owned runtime and evidence contract

One standard Ubuntu24.04 GitHub runner checks KVM and the currently served
official manifest, then uses only official SDK tooling for one API34 PlayStore
x86_64 image, pinned revision14 / `x86_64-34_r14.zip` /1,510,752,654 bytes /
SHA1`01d32617fd1937e540faf8731d70cf50e35af854`. Drift fails explicitly.
No local Mac SDK, emulator, browser driver, paid device cloud, external CDP,
unofficial APK, account or product model call is used.

A phone definition is selected from the installed official SDK inventory;
2048MiB AVD RAM is written explicitly. The emulator uses official
`-camera-back none -camera-front none` options. Its real PID, exact serial,
AVD paths, forward/reverse endpoints and launch readback are recorded.
Stock Chrome uses only the reviewed FirstRun switch in a proper argv file
(`_ --disable-fre`); effective flags, package/APK/version, OS fingerprint,
API/ABI, WM size/density, emulator/ADB versions and KVM facts require actual
readback. No typography/locale/network-rendering override is accepted.

Device-side `reverse --list` is invoked on the exact owned serial and parsed
as device-side `(reverse)`/legacy `UsbFfs`/API34 `host-N` output. Host-side forward listings
retain their owned serial check. Each mapping is registered as soon as it is
created, so a later setup failure cannot leak an earlier mapping.

Native foreground and a valid nonempty Chrome uiautomator hierarchy must
prove that FirstRun is absent; a system PNG provides separate visual evidence.
The small non-executing parser requires exactly one hierarchy root containing
all nodes, balanced tags, unique quoted attributes with separators, full
numeric-reference grammar and legal XML1.0 characters. It decodes entities
before checking native FirstRun phrases; DTD/external entities, malformed XML,
empty/unavailable output and non-Chrome hierarchies fail closed.

The shared observer runs the real anonymous home, authored Chinese/Japanese
homes, library and reader with providers disabled. Cold interception precedes
the first product navigation. Exact font source bytes and actual glyph faces
are checked. Each product route binds its own actual CSS width/height/DPR/UA;
`chrome://version` has a separately named viewport. Android never calls
Emulation viewport/UA overrides. A hidden original-title probe requires a
visible same-title counterpart or an honest unsupported result.

At most9 anonymous PNGs and one receipt are retained for3days, excluding
profiles and runtime records. Native screenshots still require visual review.
AVD x86_64 evidence does not establish physical ARM/OEM/touch/AT or every
Android environment.

## Cancellation and cleanup

Production uses `createProductionAndroidAdapter` with the actual lifecycle;
a missing shared stopping fence fails before side effects. Fences cover each
asynchronous mutation boundary, boot polling and the desktop spawn boundary.
The main server/CDP path tracks the complete acquisition and late disposal;
disposal errors/timeouts are recorded. New work is refused during normal or
cancelled finalization. Unsettled acquisitions remain explicit cleanup errors.

SIGINT/SIGTERM share one idempotent bounded finalizer. Owned child exit must
actually be observed before state removal; only the owned PID may receive
fallback signals. Missing exit proof or unsettled acquisition keeps state.
No broad device/PID shutdown or wipe is used. Cleanup errors fail the result.
Signal handlers stay installed through all awaited receipt writes; a changed
cancellation state causes a rewrite, followed by synchronous detach/exit-code
selection. There is no later asynchronous success write. Cancellation has one
transition, so this rewrite is bounded.

## Native scroll completion observation

Head `72b5f94…`, run `39155587134`, successfully executed the fresh native
`No thanks` action, recorded a clear 27-node hierarchy and an unobstructed system
image; cleanup reported no errors. The next failure was the Simplified Chinese
heading: actual rectangle y1060.43/height84, scrollY0, viewport393×722, fonts
loaded, 14 actual Noto Serif SC glyphs. That receipt establishes the failure
location; it does not establish its sole cause.

The exact Chromium113 [scroll alignment implementation](https://github.com/chromium/chromium/blob/113.0.5672.136/third_party/blink/renderer/core/scroll/scroll_alignment.cc)
maps non-smooth options, including `instant`, to `auto`; its
[scrollable area](https://github.com/chromium/chromium/blob/113.0.5672.136/third_party/blink/renderer/core/scroll/scrollable_area.cc)
can then honor the page's CSS smooth scrolling. An independent VM reproduction
of the old production observer showed its final assertion at frame2, before a
native scroll scheduled to begin at frame5. Two frames alone were therefore
not a scroll-completion contract.

The shared observer now registers scroll observation before one native
`scrollIntoView` request. It considers actual scrollports, scroll-padding and
scroll-margin, records ancestor positions/events/time, and waits for native
movement followed by stable frames. An unstarted scroll cannot count as
complete when movement is needed. No-motion completion and a bounded 10-second
timeout are distinct; timers/RAF/listeners are disposed, and the complete
observation is recorded before failure. CSS and viewport are not overridden.
The original final glyph and visibility assertions each run once; cold probes
still do not wait for the withheld fonts. Delayed-start, no-motion, blocked and
scroll-padding synthetic models exercise the actual serialized observer. The
next remote run must establish the actual scroll timeline and remaining pages.

Independent review caught newly required outer scrolling and a layout shift
before native scroll start. Completion now checks current scrollport obligations
on every frame; no-motion completion also requires current no-move geometry and
consecutive stable frames. Real serialized-function nested/shift models cover
both cases without issuing a second scroll or retrying final assertions.

Run `39156885417`, head `9c5d7c9…`, retained three real failure timelines. Both
desktop platforms had a sticky navigation link y18–62, root scrollTop0 and
scroll-padding-top90: the required negative scroll offset was clamped to0, so
waiting for movement was wrong. Needs now compares the attainable clamped
nearest offset with each actual scroller position, including maximum ranges.
The padding regression now checks both attainable movement at scrollTop200
and correctly unchanged geometry at the top boundary.

Android's cold hero had no scrolling and remained in view while CSS arrival
moved y138→116, with only two RAF callbacks in3.254seconds. No-scroll stability
therefore uses actual scroll positions and current scrollport obligations; it
does not confuse an on-screen layout animation with unfinished native scrolling.
The bounded observation deadline is10seconds, within the existing30second CDP
request timeout, allowing four stable frames at the measured slow cadence.
Proofs include range/style, visibility/focus and first16 RAF timestamps. These
facts do not establish background throttling or device sleep as the cause.
The owned remote page is normally activated through `Page.bringToFront`, with
no new rendering flag or CSS override. The unobserved pre-probe italic centering
was removed, leaving only the factory's one observed native scroll per probe.
