# Leafhour native iOS

This is the native iOS reader, with optional Leafhour account login and cloud synchronization. Device-local import and reading still work without a login or network connection. System listening runs locally; cloud translation and reading conversations require an explicit action. After sign-in, opening a book without a cached guide also starts a non-blocking AI reading guide from bounded opening samples; a device-local original stays on the device. See [current iPhone behavior and data boundaries](../../docs/ios-reading-experience.md) and the [November 5 verification record](../../docs/verification/2026-11-05-reading-experience/README.md). The checked-in debug identifier is for unsigned local development only; distribution must reuse the separately verified existing Leafhour App Store Connect app.

## Build and test

Requires Xcode 16+ (iOS 17 minimum), Swift 5.9+, and the existing shared iOS guard on this Mac. ZIPFoundation 0.9.20 and Swift cmark 0.6.0 are vendored with upstream blob checksums. No sample books or personal data ship in the app. `node tools/verify-ios-vendor.mjs` checks both dependencies without network access.

The Xcode project is generated from `project.yml` with XcodeGen and committed for build reproducibility. `Config/Signing.local.xcconfig` is ignored. Release configuration intentionally has no default registered application identifier.

The optional `LeafhourUITests` scheme tests system selection, EPUB chapter XII/cold resume, note drafts after relaunch, and a 73-page PDF. ## Local data and import contract

Files selected through the system picker are copied under the current device or account's Application Support library before parsing. Original bytes identify duplicates and content versions. An identical-source import explicitly offers Keep original, Replace book or Add as new book. Keep reuses the original identity; Replace republishes verified content under that identity and preserves personal state. Add as new uses a durable operation identity and starts independent, empty personal records; retrying that operation reuses its copy identity. Replacement uses the existing staged repair journal and retains a recovery path after interruption. Matching titles alone do not establish a duplicate. Complete EPUB spines and their local assets are parsed in order; every local PDF page remains available in the original PDF, including pages with no extractable text. Markdown retains its original source and renders CommonMark/GFM as native attributed text. Parsing never invents text, translations or OCR results. Source files never enter this Git repository.

Archive entries are bounded by count, per-entry size and total expanded size. Absolute paths, parent traversal, symbolic links, duplicate archive names, unsupported encryption and missing spine content are rejected. CRC and offline file hashes are checked. A staged import becomes a book only after the complete original, content index and resources have been written and verified. Failed/interrupted jobs retain their copied original and offer an explicit retry; reconnecting never starts a paid task.

Imported books are already on this device. “Available offline” means the complete local manifest has passed verification; it never means a network request merely started. Cloud downloads retain all text chapters, source IDs and available translations as a verified reading copy. Original EPUB/PDF files stay separate; a text copy is not a downloaded original. Device-local identity and authenticated account UUID scopes are isolated. Account tests use fixtures; production login/read checks and real-device acceptance are recorded separately.

Cloud reading copies first use an owner-bound gzip archive, downloaded in 1 MiB parts and checked against its SHA, declared size and final source snapshot before atomic publication. Limits are 96 MiB decoded, 32 MiB compressed, 5,000 chapters and 300,000 passages. An older server that returns 404/405 for the archive plan uses the existing bounded chapter fallback. The default “Recent activity” order uses the later of actual shelf addition and actual reading time, so a newly added book can precede an older reading session. A cloud copy's device download time is not its addition time. An explicitly saved sort remains in effect. Addition order remains selectable and uses actual cloud addition dates or the account's saved manual order; pins remain first and cached dates survive offline use. Unchanged snapshots do not republish the shelf; a failed refresh retains loaded books, and same-account profile changes retain the library. [Cloud arrival verification](../../docs/verification/2026-10-31-ios-cloud-book-arrival.md) separates actual-book transport checks from simulator UI and physical-device acceptance.

The shelf uses the public catalog's artwork and authenticated original-file covers, cached by owner and content version for reloads and offline use. Existing local EPUBs recover their declared cover without rewriting the saved index; PDFs use their actual first page. Missing artwork keeps a readable title fallback and never blocks opening the book.

Email/password and email-code login reuse the website's authenticated APIs. Session credentials stay in Keychain and an isolated URLSession. Saved notes and positions write locally before synchronization; retries keep stable note IDs, and newer cloud positions require an explicit choice. Local drafts remain on the device. Signing out hides the account's cache and returns to the separate device library. Uploading a local original is explicit; only unique exact source matches migrate its notes and position, with unmatched records retained in the source book.

The quiet reader has no persistent time, AI or listening footer. Center tap reveals tools and progress; native long press reveals selection actions. Foreground-estimate timing starts silently on entering the visible reader by default, with a profile-scoped opt-out; focus timing still starts explicitly. Manual pause and finish are preserved across tools. Listening, Chat, tools and backgrounding do not accumulate reading time. Book-specific history reads local intervals and authenticated cloud month summaries separately, without adding overlapping totals. Time checkpoints and shelf actions use account-scoped durable queues and matched receipts; background/hidden-reader intervals do not count, and device overlap is unioned by the service. The complete account shelf snapshot supplies reading state, recent continuation, pins, manual order and explicit archive state. Downloaded originals/copies and drafts remain on their device. Cold launch presents the cached shelf before authentication and background synchronization; Continue reading opens only after an explicit tap. Repeated foreground refreshes within 30 seconds reuse a successful account synchronization unless local activity, pending actions or retry errors require work; pull to refresh always rechecks. Reader-first opening verifies the local source, index and visible resources before presentation, then checks the full package and synchronizes records. Unchanged decoded indexes are reused with device/inode/size/mtime/ctime checks. Deferred failure freezes the reader and preserves a source-bound recovery snapshot, exportable immediately or later from book details. Source observations are distinct from upload acknowledgements, so delayed offline progress cannot become the most recent reading merely by arriving late. See [reading-time semantics](../../docs/reading-time.md).

Google and Apple sign-in use the system authentication browser and the existing hosted providers. The account screen lists actual linked identities and allows a signed-in account to link another provider while keeping its ID, native session and offline library. Supabase owns automatic linking for the same verified email; Apple relay and different provider addresses require explicit authenticated linking. An occupied identity is a conflict, never permission to merge reading data. The native callback contains only a short-lived one-time code and state; a verifier-bound HTTPS exchange obtains the opaque session. See [social sign-in operations and acceptance limits](../../docs/ios-social-sign-in.md).

Stable chapter/passage identifiers and source versions bind reading position, notes and drafts. State writes are atomic and serialized. Keep/Replace duplicate imports leave existing personal state intact; Add as new creates separate records. Native text selection keeps copy available; author text, a selected quote and personal notes are labeled independently. Source and translation selections have separate draft identities; translated quotes retain their literal/interpretive variant and source paragraph anchor. No literal/interpretive translation is fabricated when none is available.

## Reading controls and sharing

- New profiles and missing navigation settings default to horizontal pages; valid saved scroll settings are preserved. Native page curl follows a committed tap or swipe; it does not continuously track the finger.
- Bundled Noto Serif SC and WenKai Lite, PingFang and a rounded Latin pairing apply to reflowable text; Latin faces can be chosen independently; original PDF typography stays intact. All reading preferences are shared across books within the same `LibraryScope`, including typography, paper, navigation, reading layer, translation variant, listening speed and automatic-turn interval. Positions, notes and drafts remain book-specific; device and account scopes stay isolated.
- Quick consecutive contacts each turn a page without a double-tap selection wait; native long press retains selection and Copy. Navigation settings → More interactions holds the profile-scoped 0–500 ms response delay (default immediate) and optional always-visible progress (default off). VoiceOver keeps its system activation gestures, and PDF pinch zoom remains native.
- Contents retain the actual chapter order and mark the current chapter/page. Original-text search covers local chapter bodies as well as titles or PDF page numbers, grouping verified excerpts under their real entries. Explicit AI search uses only the current book's frozen device snapshot through read-only tools, with a separate conversation namespace; it does not read other books, private notes or the web. Only source references validated against the snapshot become jump targets. Locate clears the search and scrolls to the current entry without changing the reading position. No inferred hierarchy is added.
- Bookmarks are independent device-local records, separate from notes. Pull down and release at the reader's bookmark threshold, or use the explicit button/VoiceOver action. The current-location marker and book list support naming, color changes and removal. Original positions retain source anchors; translated positions additionally retain the translation fingerprint, variant, target language and UTF-16 offset. Changed or unavailable text must be checked before jumping. Bookmarks are included in native reading-record exports; no cloud bookmark synchronization or Web-backup channel is claimed.
- Listening uses temporary local PCM for each passage and a draggable 0.5×–5× playback-speed slider. Opening the panel or adjusting speed does not start playback; word markers follow the actual player clock.
- Automatic page turning starts explicitly, with a 5–120-second interval in 5-second steps, defaulting to 30 seconds. Touch, selection, tools, listening, VoiceOver and backgrounding pause it. Continue starts a fresh interval; returning to the app never resumes it automatically. It stops at the book's end and does not restore a running state after relaunch.
- Reading styles combine classic, spacious and compact typography presets with nine named papers including warm, white, sage, mist, sand, apricot, dusk, night and system. Settings preview changes before returning to the page; typography presets preserve content, navigation and listening choices.
- First-line indentation offers None or Two characters. TXT source padding is removed only from the displayed paragraph; selection still maps to the unchanged source. Book-specific translation uses automatic source detection and a one-line target-language intent. New books default to English; Chinese, English, Japanese, Korean, French, German and Spanish names and supported aliases are accepted locally. Ambiguous, unsupported or same-language input needs correction before generation. Saved targets remain unchanged; legacy books without the defaults-version marker retain the old Chinese-source → English / other-source → Chinese fallback, including when their state file is absent or a package is repaired. Language selection alone never starts generation. Existing Chinese translation formats remain compatible; other targets, offline caches and uncertain requests are retained separately by language.
- Sharing separates images, full text, eligible links and files through the system share sheet. Paper, ink and night card styles share the same measured pagination and complete quotation. Selected text keeps its source/translation attribution and paginates into 4:5, 1:1 or 9:16 cards without truncation. Authorized public/gift links include a native QR code for image forwarding. Card rendering is capped at 12 pages; longer selections remain available as full text. Installed apps determine the available destinations.

Gift publication requires an explicit action. The Web gift page's “Import in the iOS app” button opens a `leafhour://gift/<token>` preview; accepting and downloading require confirmation. Validated `leafhour://read?book=<id>` links also preview before opening. Private or unknown-visibility books do not receive fabricated public reading links.

See [GET-352 implementation and verification](../../docs/verification/2026-11-01-get-352-ios-reading.md) for recorded local evidence and delivery references. Universal Links require separate associated-domain/AASA and device verification. Real-device social destinations, VoiceOver and audible quality at extreme playback rates remain separate acceptance gates.

```mermaid
flowchart LR
  Welcome[Start on this device] --> Library[Library]
  Library --> Open[Tap book: open or download]

  Library --> Picker[System file picker]
  Picker --> Copy[Retain original]
  Copy --> Parse[Parse complete EPUB / PDF]
```

## Local-book conversations

A book imported into the current device/account library can use AI without uploading its original or creating a cloud-library entry. The official DSH runtime requests read-only context, outline, chapter pages and search from the iOS device; each result is bound to the current account, frozen book version and request. Private notes, arbitrary paths and other books are unavailable in this scope. Requested excerpts reach the model service; “local book” does not mean offline model inference. Image-only pages require extracted text first.

Send publishes an immutable outgoing message before session/billing round trips, then streams provisional answer text. A completed receipt remains distinct from partial output. Unknown outcomes retain the exact request and billing key for recovery; original messages and local drafts are preserved separately. Shared tool receipts support reconnecting to a live run across hosted processes. An expired/killed runtime becomes interrupted rather than silently creating another paid generation.

The conversation uses a compact assistant text style with Dynamic Type, one sent quote and one response status. Each completed answer offers three distinct follow-up questions without another model request; tapping one sends it through ordinary chat while preserving unrelated draft text, voice and selected excerpts. Guide follow-ups store a server-validated AI `guideContext` separately from the user's question `text`, including in history and recovery. Returning keeps the underlying native reader and selection; Markdown and immutable book-index caches avoid repeated parsing during layout and local state saving. Durable reading records still flush before returning to the shelf.
