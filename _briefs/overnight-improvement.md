用户于 2026-10-12 授权自主设计、实现与每半小时改进。截止按 Asia/Singapore 2026-10-13 08:00；心跳 automationId=8，到期暂停。当前请求覆盖完整用户路径，实施方式为当前会话直接实现，不等待重复设计批准。不开新付费服务、不自动部署、不公开私人样书。

## 设计依据

参考 https://reader.humanitext.ai/ 的实际官网：出版物式文字层级、实物书页的空间感、轻量顶栏、正文与译文的对应示例。采用旁读自己的内容与视觉，不复制品牌和数量。

Notion Product Design：https://app.notion.com/p/3f6a444a6c00815192bff9c8a7dc19d9。保留安静阅读、按需辅助、稳定锚点、个人数据可迁移和书籍授权。现有七章私人样书继续在本机旧阅读入口使用，不纳入公共目录。

## 实现边界

官网 `/`，书房 `/library`，通用书页 `/read?book=ID`，原有私人样书 `/read`。现有 Node 服务增加入口适配，浏览器与 MCP 共用 library-service；原有私人样书 API 保持本机限定。

新增本地领域服务：按用户隔离书籍、记录与进度；文件原件和提取结果保存在忽略的 local 目录。PDF 使用本地 PDF.js，文本与 Markdown 同样可读；扫描件没有文本时明确要求 OCR，不冒充已解析。默认库为 Project Gutenberg 的公版作品，保存出处、译者、许可提示与完整原文；不预先调用模型翻译。

邮箱采用一次性验证码、HttpOnly 会话、验证码哈希与过期/限频；通过配置的 SMTP 发信。没有发信配置时不声称已发送，明确提供独立的本机书房入口。本机入口仅限环回地址且不代表已验证邮箱；后续公开服务必须关闭该入口并完成真实邮件和多用户持久化验收。

按用户点击生成当前段落与最多前后各一段的中文直译、意译，独立保存草稿、模型与来源版本；失败保持原文可读。有配置的 DeepSeek 才调用，响应严格核验，设置超时和并发上限。

MCP 使用官方 SDK 的 stdio，凭网页生成的按书与数据类型授权令牌访问同一服务。默认只读，个人记录另选，写评论单独授权；撤回立即阻断。完整书房导出不包含凭证，能在干净实例恢复。

## 验收顺序

先验领域边界：匿名不能读私人书或写记录、账户相互隔离、源文件格式/大小检查、PDF 成功提取与失败、独立译文、有界上下文、幂等评论、撤回授权。再用真实浏览器检查官网→书房→上传→阅读→按需翻译→保存/导出，核对手机布局、文字选择和无横向溢出。

真实邮件没有配置或收件证明时仍列为未验收。扫描 OCR、EPUB、远程 MCP OAuth、自托管上线可进入后续改善事件，不能把第一轮支持范围写成所有功能已经完成。
