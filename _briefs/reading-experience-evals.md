# Leafhour · 真实阅读体验 Eval

> 当前品牌为 Leafhour，正式网站为 https://leafhour.com。本文保留原设计或验收日期；其中旧名称只表示当时的品牌。

2026-10-12。把产品目标落实为可演示、可检查的阅读过程，作为开始写代码的验收规格。以下场景使用真实书籍锚点，但提问和读者回答是设计用例，不是已经发生的用户反馈。未运行的验收保持 pending。

## 评什么

一次好的帮助让读者能回到原句，解释自己以前卡住的关系，并继续阅读。体验可以安静，也可以有探索；不能用按钮点击、完成计时或接受作者观点替代理解。

每个案例分别看三件事：功能是否可靠，Agent 是否根据原文给出合适的帮助，读者是否留下了独立理解的证据。前两项可以准备自动检查，第三项需要真实试读；模型自评不能把三者合成一个“深读分”。

源文本整体仍为 extracted_unreviewed，译文为 draft。用例中的解读标准属于有锚点的评审候选；正式学习实验前先核对底本和反馈。源版本与摘要保存在 eval 数据中，整书和个人记录不复制进 Git。

## E00 · 我可以直接安静地读

读者晚上打开书，从上次位置继续，阅读两段，选择一句复制，切换原文，再进入专注模式。他没有发起 AI 帮助。

好的过程只呈现正文。选文不跳语言，切换保留段落，目录和设置按需打开；没有自动概览、关卡邀请或模型费用。关掉页面后能在原处继续。

功能验收要求零生成请求、零主动弹出活动；原位置恢复且用户记录不受影响。不参与探索是成功阅读路径，不生成“缺少耐心”或“没掌握”的记录。

这是其余案例的共同基线。只有产品保持这条路径可用，才讨论 AI 带来的增益。

## E01 · 一句话终于有了抓手

**Entry:** 读到 §1 的目的区分，读者问“无限游戏就是永远玩不完吗？”。

**Good Path:** 从当前段落进入“帮我理解”。Agent 先取得 fig-1986-s001-p002 的原文，用短解释指出该句按目的区分：取胜与让游戏继续。必要时只加一个标为编辑补充的例子，不展开全书理论。原文引用能在同段打开，解释可收起。

默认先显示一小段约 60–140 个中文字的解释；展开后才增加细节。字数是体验目标，不能为满足字数删掉限定。第一次解释不要求读者先答题。

**Understanding Evidence:** 在自愿试读中，读者面对“一个持续十年的比赛，最后产生冠军并结束”，能解释为什么持续很久仍不足以改变本段的目的区分。原话是否更清楚由评审记录，不预设每个读者都会改口。

**Failure:** 直接写“无限就是没有终点”“无限总比有限高级”，强制玩卡片，或给出一屏无出处的哲学概述。引用存在却不能支持结论也算失败。

## E02 · 我亲手发现，同一种活动会变

**Entry:** 读者请求“用一个小实验让我理解”，本段为 fig-1986-s001-p002。

**Good Path:** 一个两三分钟的可选活动，同样是读书会：一组以选出最有说服力的观点、宣布胜者结束为目的，另一组以让讨论继续为目的。读者先解释自己的判断，然后交换目的，观察自己是否需要改变判断。场景标为编辑构造，原文一直可达。

提示和反馈分开，用户可直接看解释或退出。控制只改变情境数据，拖动和选择不逐次调用模型。完成后返回原段，留下用户自己的理由。

**Transfer Probe:** 使用没在活动中出现的情境：“一家经营十年的公司每月评选第一名，它整体就是无限游戏吗？”接受有理由的“材料不足”：存在月度评选和持续经营，仍需了解整体目的。不能靠活动名称或年限直接判断。只有引用并取得 §14 原文后，才进一步讨论有限游戏置于无限游戏中的关系。

训练时的两个目的已经明显给出，选对只能证明会操作。迁移问题和读者独立解释才是理解证据；直接看反馈后作答标为 assisted，不能记成独立完成。

**Failure:** 只换了颜色和标签，选项背后没有理由；给“无限”更高分；把公司或人生一律判成无限游戏；结束后找不到原句。玩完但解释仍混乱，记录为“活动完成、理解未证实”。

## E03 · 我可以不赞同，但质疑更清楚了

**Entry:** 读到 §2，读者问“裁判判赢不就结束了吗，为什么还要所有玩家同意？”。

**Good Path:** 取得 fig-1986-s002-p002 到 p004，先说明作者在这里把共同承认胜者作为决定性结束的条件，再指出邻段确实讨论了裁判与观众。用户的反例保持原样。

Agent 可以提出一种解释或一个更精确的问题，但须标为编辑解读。例如“是否接受赛事规则就意味着接受判决”是待讨论的解释，不能假装这几段已明确证明。允许读者追问“现实中不服判决的比赛仍然结束，这是不是在重定义结束？”。

**Understanding Evidence:** 读者能区分作者的概念条件、现实比赛的行政结束与自己的质疑；保留不同意见仍可成功。评价理由的清楚程度，不评价是否被作者说服。

**Failure:** 自动迎合“作者完全错误”，或替作者断言“同意规则必然等于同意每个结果”；凭空补其他哲学家的背书；把用户异议改写成已接受作者结论。

## E04 · 下次读英文，我能少看一次翻译

**Entry:** 语言学习模式中，读到 fig-1986-s002-p001，读者问“If…must 在这里怎么理解？”。

**Good Path:** 保留英文在主位置，同段查看直译、意译与条件关系。解释 must 在这个句子中连接的是“若要有胜者，就必须有明确结束”，不把它译成鼓励竞争的“应该争取胜利”。只解释本次真正卡住的关系，不把每个词变成任务。

用户可以关掉帮助继续读。自愿试读时，用一句新的、难度相近的条件句让他独立复述；记录实际用了哪些提示。下一次相似段落不强制弹译文，用户仍可请求。

**Understanding Evidence:** 在新句里保留条件与必要关系。一次查词、一次复述都不能升级为整体语言能力，跳过也不能降低能力标签。

**Failure:** 全页替换成中文、两个译法混成一份；每个词都需要点击；让读者照抄原译文再宣称已掌握。

## E05 · 过几天回来，我自己的问题还在

**Entry:** 用户之前在 §1 留下问题“如果公司持续经营，但每年都有冠军，怎么区分？”，几天后点击“从我的问题继续”。测试使用临时实例里的合成记录，不读取真实私人评论。

**Good Path:** 同一位置和原话仍在。获得个人问题授权后，Agent 引用这个问题，用一条可选择的续接建议，让用户决定回到 §1、查看相关 §14，或继续当前正文。没有授权时仍能按阅读位置继续，只是不取私人问题。

用户作出新的解释后，可以保存原话和仍未解决的问题；AI 整理是独立候选，明确接受后才进入认可笔记。导出后在干净实例恢复，原话、归属和锚点保持；旧假设可以被纠正，而非不断重复旧标签。

**Understanding Evidence:** 读者愿意接着自己的问题思考，能说明这次新增或仍不确定的部分。回来本身只证明接续可用，不能证明记忆或理解提高。

**Failure:** 用泛泛摘要替代原问题，夸称“你已经掌握”，读取其他书的私人评论，或把 AI 整理当成用户原话。没有日程授权不得发外部提醒。

## 共同的失败边界

取消生成后正文立即可用，迟到结果不能重新打开探索或写理解记录。超时、额度不足与模型不可用都能退回原文；错误不生成假成功。来源更新让旧资产失效，不能继续展示其为已核验引用。

首轮体验目标为点击后立即看到本次范围与取消入口，8 秒内得到第一层可用帮助；这是假设目标，需分别记录冷启动和后续请求。超过目标时可以继续读正文，达到既定 60 秒期限后明确结束任务。不能用尚未校验的半截脚本、空动画或首个 token 冒充已经有用的帮助。关闭帮助通过一个入口或 Esc 返回同段。

生成调用有真实官方 Harness 事件和 Host Run 关联；换已存译文、字号和活动里的选择都不重复计费。脚本只使用可信组件；越权、未知组件与失效锚点是必须阻断的失败。

## 开始写代码所需的 Eval

首个交付范围为 E00 + E01 + E02。它足以验证官方内核、一次准确帮助、可选探索、回到原文与退出。E03–E05 的完整体验后续实现，第一阶段保留其输入作为防止迎合、翻译失真和跨范围读取的评审案例，不能谎报已支持全部流程。

E01 需要受限解释产物：正文文字、归属、sourceRefs 与来源版本。它与 E02 的 Chapter Script 分开校验；不能把解释硬塞进 compare_purposes 组件。写代码前明确这两个输出契约，复用同一 Run、来源核验与渲染入口。

**Deterministic Checks:** 断言来源/版本/摘要、组件结构、允许的动作、Run/owner 关联、模型请求次数、取消结算、保存与回跳。固定组件回放必须可重复，模型每次生成的用词不要求一致。

**Content Review:** 每个案例单独核对相关性、来源支持、限定保留与干扰；可分别记 0/1/2 并写理由。LLM judge 只提供候选，初始参照由人工检查正反例。不能用字符匹配或模型自己给高分证明语义正确。

**Reader Study:** 同一时间预算比较安静阅读与固定活动，再比较固定活动与 Agent 选择。使用不同但相近的段落并交错顺序，保留提示使用和退出记录。另测自愿参加者七天后的复述与新例子。小样本用于发现问题，不宣称统计证明。

**Release Gate:** 第一阶段每条必须阻断的失败都通过；E00–E02 技术链路均有真实回执；内容参照经过人工核对；至少完成一次真实读者的过程观察才能说“已试读”。后续理解效果和留存没有结果时仍写“未验证”。测试用户操作成功、来源可追溯与读者理解是三种独立结论。
