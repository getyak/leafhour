MCP で AI Agent を自分の本につなぐ。

Leafhour ドキュメント · 2026 年 10 月 16 日更新

Leafhour の Model Context Protocol（MCP）アダプタを使うと、対応する AI ホストがあなたが許可した一冊の本を読めます。ウェブと同じ読書サービスを使うため、アクセスは一冊の本と選んだデータ種別に限られます。アダプタを導入しただけでは何も許可されません。

これは技術的な連携です。リーダー画面は英語・簡体字中国語・繁体字中国語・日本語に対応しています。許可管理の画面はまだありません。許可の作成と取り消しは、対応クライアントか認証済みのサービス API から行ってください。ご不明な点は support@leafhour.com までご連絡ください。

OAuth で ChatGPT に接続する。

ChatGPT Plugins でカスタム MCP サーバーを追加し、URL に https://leafhour.com/api/mcp を入力して OAuth を選びます。ChatGPT が動的登録を拒否する場合は、接続の説明に従って事前登録済みの公開クライアントを使います。Leafhour でログインし、アカウントを確認して一冊を選びます。権限は既定で一時間の読み取り専用です。クライアントが注釈権限を要求した場合、同意画面でハイライトと AI 評論を個別に許可できます。追加項目は既定で未選択です。個人メモ、注釈内のユーザーの返信、読書記録は含みません。reader_get_connection で対象の本を確認でき、権限は一時間後に失効します。それより前に取り消す場合は下記の認証済みサービス API を使います。ウェブには接続管理画面がありません。

skills 対応ホストでは getyak/leafhour から leafhour-reading をインストールできます。skill のインストールだけでは MCP への接続や認可は行われません。インストールと OAuth の説明を参照してください。カスタムサーバーの追加は ChatGPT のアカウントとワークスペースのポリシーに従います。下記のコマンド設定は stdio ホストで引き続き利用できます。

reader_add_highlight で選択文を保存し、reader_add_annotation で AI 評論を追加します。reader_get_annotations は保存済み AI 解説を読み取ります。操作ごとに権限が必要です。追加 OAuth 権限の要求方法は接続の説明をご覧ください。

Agent に読ませる範囲を選びます。

権限許可されること
content原文と保存済みの訳文、書籍情報、ページ分けされた章、その本内の検索。
notes個別に許可した個人のコメントと質問。
activity保存済みの読書位置と最近の読書セッション。
comment:writeユーザーが明示的に渡したコメントを、段落に紐づけて保存します。本の編集は許可されません。
highlight:write一致する選択文をハイライトとして保存。
annotationsAI 注釈を読み取り、非公開のユーザー返信は除外。
annotation:writeExternal Agent と表示する AI 評論を保存。Leafhour のモデルは呼び出しません。

まずは content だけをお勧めします。許可は 7 日で失効し、それ以前にも取り消せます。取り消した後のサービス認証は失敗しますが、AI ホストにすでに複製された内容は消せません。

アダプタをつなぎます。

  1. リポジトリの手順で Leafhour をローカル実行するか、ホスティング済みの読書サービスを使います。自分の書斎で本を取り込むか、公開サンプルを選びます。
  2. 対応クライアントか認証済み API から、POST /api/library/grants で bookId と scopes を指定して許可を作成します。トークンは一度だけ返るので、AI ホストの秘密の設定に保管してください。
  3. GET /api/library/mcp-setup を読み、設定ビルダーでホスト設定を作ります。ローカルのソースでは node server/mcp.mjs がアダプタです。ホスティング側の接続では実際のデプロイ済みソースコミットが返り、生成される設定はその不変のソースパックに固定され、HTTPS の書斎を明示的に許可します。デプロイ由来が確認できない場合は遮断します。
  4. 対応 AI ホストで MCP サーバーを有効にし、ツールのリクエストに許可された本の ID を渡します。使い終えたら POST /api/library/grants/{id}/revoke で取り消します。

アダプタは次の環境変数を使います：

READER_SERVICE_URL=http://127.0.0.1:8330
READER_AGENT_TOKEN=<your book-scoped grant>

# For your configured HTTPS service only:
# READER_SERVICE_URL=https://leafhour.com
# READER_ALLOW_REMOTE=true

ログインパスワード、セッション Cookie、Supabase キー、許可トークンを公開文書やリポジトリに書かないでください。MCP の許可はウェブのログインとは別物です。ホストに秘密情報の保管機能があれば使ってください。

まず一節を取得して、そこから深めます。

reader_get_manifest は本の出典情報と章の識別子を返します。reader_get_context は段落と前後の段落、安定したアンカーを返します。reader_get_chapter は一度に最大 20 段と続きのカーソルを返します。reader_search は許可された本を検索し、アンカー付きの結果を最大 20 件返します。

追加の権限では、reader_get_notes がコメントと質問を、reader_get_reading_activity が位置とセッションを、reader_add_comment がユーザーが明示的に渡した文を保存します。Agent のアクセスが読書カレンダーに時間として加算されることはありません。

例：「許可された本から友情についての段落を探し、出典の章と段落アンカーを見せて、作者の言い回しを比較してほしい。」Agent には本の ID が必要です。プライベート書庫全体を検索する許可があるとは推測できません。

現在の制限を知っておきます。

アダプタは音声ツールも公開していますが、ホスティング側の音声生成は有効になっていません。ローカルの音声は別途の設定と権限が必要で、生成にはプロバイダーの費用がかかる場合があります。MCP は現時点で本のアップロード、書庫全体の自動翻訳、通知の自動スケジュールは行いません。

組み込みの読書アシスタントは読み取り専用の独自の境界を持ち、この外部 MCP の許可とは別物です。ホスティング側の処理詳細はプライバシーとデータの取り扱いをご覧ください。

正確なツール定義と現在のサービスの挙動は、アダプタのソース、サービスのルート、本ごと権限の MCP 読み取り仕様をご確認ください。このガイドは現在の実装を説明するもので、将来の機能ではありません。
