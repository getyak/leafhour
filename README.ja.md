# Leafhour

[English](README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-Hant.md) | **日本語**

**Stay with a book.** Your personal reading room, with AI by your side.

Leafhour は、読みたい一冊を少しずつ読み切る手助けをします。今日は前回止めた原文の文から続き、読み終えたら自分の理解をひとこと残し、明日また戻ってくる。本文は静かに保たれ、原文と二つの訳、個人のメモ、精読の手がかりは、必要なときにだけ現れます。

開発は唯一の公開リポジトリ [getyak/leafhour](https://github.com/getyak/leafhour) で行われ、コード・設計文書・実行計画・検収記録は AGPL-3.0 でオープンソースです。既定のパブリックドメイン英語原文と出典・許諾は `catalog/` に置き、個人の本、個人の訳文、メモ、読書記録、サーバー側の秘密鍵はソースと一緒に公開されません。

読書ページのリスは、ログイン後は既定で読書に付き添います。手動で閉じた本はその選択を覚えており、最初の約 90 秒は静かに読み、以降は現在と最近フォアグラウンドで読んだ断片に基づいて 5 分以上の間隔でひとこと残します。ぴったりする内容がなければ沈黙します。一度の読書で能動的に話すのは最大 3 回。吹き出しは無視・折りたたみ・既存の読書対話の開け閉めができ、個人の下書きは上書きされず、対話の中からいつでもオフにできます。リスはドラッグまたは Alt + 矢印キーで動かせ、位置は現在のブラウザに保存され、吹き出しはキャラクターと共に移動します。「読書中」バッジの常設表示は廃止しました。文字選択、メモ、チャット、バックグラウンド中はポップアップを出さず、個人のメモを読まず、サイト外へ送信もしません。

## いまできること

本機では完全な導線が通ります。公式サイト → 公開カタログ → ローカル書斎またはメールコード → PDF / EPUB / TXT / Markdown のアップロード → 段落ごとの二訳 → 個人記録と読書対話。既定カタログには『不思議の国のアリス』『自省録』『ウォールデン』の完全な英語原文を収録し、出典と許諾を `catalog/` に保持しています。訳文はリクエスト時に生成され、最初から全訳済みとは主張しません。既定カタログに私的なサンプル本はありません。

新しい書斎はローカルサービスと Vercel + Supabase の両方に対応します。クラウドは独立したプライベートテーブル、コンテンツバージョン確認、プライベートな原ファイル保存を使い、既定の公開書は匿名で試し読みできます。ホスティング版はメールとパスワードでのログインが既定で、メールコードは予備です。新規書斎とパスワード再設定は先にメールを確認してからパスワードを設定します。Google と Apple のログインにも対応し、セルフホストでは設定した方法だけを表示します。

書斎は前回止まった段落から続き、他の本は下段の棚に残ります。検索、アップロード、読書カレンダー、読書対話は折りたたみ可能な左サイドバーにまとめ、左下のアイコンと名前でプロフィールを編集でき、ログアウトと外観は「設定」にあります。スマホはドロワー導線です。旧「データと Agent」パネルは廃止しましたが、そのデータとドメイン API は残っています。読書記録、計時の定義、下書き、バックアップは [読書とデータの保持](docs/reading-journey.md) を参照してください。

本棚は霧緑の紙目と細い棚板を使い、夜間表示とシステムの視差効果削減設定に対応します。公開書 64 冊すべてにオリジナルの版画風イラストがあり、書名と著者名は選択してコピーできる文字で、画面の言語に合わせて英語・簡体字中国語・繁体字中国語・日本語に切り替わります。同じ版は棚・検索・続きから読むで同じ絵を使い、表紙の言語を変えても読む本文は変わりません。個人の本と未収録の本は、実際の書誌情報と布装を保ちます。[表紙の絵](docs/book-cover-artwork.md)、[書名・クレジットの出典](docs/book-cover-localization.md)、[検証記録](docs/verification/2026-10-28-illustrated-book-covers.md)を参照してください。紙目の素材の出典とプロンプトは引き続き [ブランド素材](app/brand-assets/README.md) にあります。

本にホバーまたはフォーカスすると操作が増え、タッチ端末ではボタンを直接表示します。表紙とハンドルのドラッグで並べ替え、メニューで前後に移動でき、ハンドルの矢印キーでも同じ操作ができます。ログイン後の並びはアカウントごとに保存されます。ゴミ箱へ移しても原文・訳文・読書記録は残り、棚に戻せます。完全削除はありません。

「読書予定を追加」で時刻・長さ・繰り返し・通知を設定して `.ics` ファイルをダウンロードします。通知は自分で開いてシステムのカレンダーに追加してから有効で、アプリが直接カレンダーイベントを作ることはありません。

「この本を贈る」では相手の名前と贈り言を書き、開ける紙の質感の贈書レターを生成します。リンクには本の紹介が含まれ、受け取った側は完全な読書パックをダウンロードし、ログイン後に自分の棚へ追加できます。原文とチェックした既存の訳文はレターと共に贈られ、個人のメモ・質問・読書位置・計時とは分かれます。訳文は下書きなどの状態を保ちます。リンクを取り消すと以後のアクセスは止まりますが、ダウンロード済みのパックや受領済みの本が遠隔削除されることはありません。ホスティング受領は原文と訳文の合計 3.5 MB までで、大きいパックは本機にダウンロードして受け取れます。

贈書は「贈り言を書く → 封を開ける様子を見る → 封をして共有」で進みます。プレビューは実際の受取ページを再利用し、ブラウザ内で見える紹介だけを渡してリンクを作りません。明確に封をしてから自分でリンクをコピーまたはシステム共有を使います。同じアカウントでウィンドウを閉じても、今回の下書きや封をしたリンクは残ります。受け取る側はログイン前でもレターを開け、ログイン後も開いたままです。封筒とカードはオリジナルの不揃いな紙の縁、消印、柔らかな紙目を使い、アニメーションは折り返せて視差効果削減にも従います。

- 中国語・英語・対照の三つの読み方。直訳と意訳は別々に保存し、訳の欠落は原文を一度だけ表示して欠けた版を明示
- 匿名試し読みで翻訳を求めても同じ原文段落を返し、もう一度明示的に押して初めて生成。サービス未設定時は正直に入口を無効化
- 段落原文、注釈、思い、質問は安定した ID で整列
- X-ray 論証透视、スタンス反転ページ、エコー添削、控えめな章の対話
- 文字を選ぶと淡黄色のプライベートハイライトを保存。クリックで解除かひとこと追記し、「自分の記録」から原文に戻れる
- 文を選んだら設定可能なモノリンガル／バイリンガルの共有画像を生成
- 書体、字号、行送り、段落間隔、字間、字下げ、紙面テーマ
- 読書カレンダー、毎日の目標、自分の理解と質問を原文の位置で回訪
- 明示的に開始するフォアグラウンド読書計測と、章・本の読み終わりの手動確定
- ハイライト、コメント、質問、読書位置、セッション、読書マークの入出力
- ローカル JSON 保存、または Vercel + Supabase のプライベートホスティング

## オフライン読書

書名を開き、「この端末に保存」を選びます。「オフラインで読めます」と表示されたら、接続がなくても保存した章を開き直せます。最近読んだ章も自動で保存します。既存の原文と訳文を使い、生成や有料の処理は始めません。メモは端末の下書きとして残し、再接続後に自分で送信します。

ログアウトや端末の本の削除でローカル読書を閉じても、未確認の下書きは別に保管します。ブラウザーが保存データを消去する場合があるため、書斎のエクスポートも保管してください。`npm start` はオフライン用の公開ファイルをビルドしてからサーバーを起動します。[検証結果と制約](docs/verification/2026-10-29-offline-reading-cache.md)も参照してください。

## ローカル実行

Node.js 22.13 以降：

```bash
npm ci
npm test
npm start
```

`http://127.0.0.1:8330/` が公式サイト、`/library` が書斎です。旧プライベートサンプルの入口は `/read` に移動し、`/read?book=ID` で新しい書斎の特定の本が開きます。本機にプライベートなサンプルがなくても既定の公開カタログで起動します。本機のアップロードと記録は Git 管理外の `local/service/portal/` に置かれ、公開ソースには入りません。

個人データをソースディレクトリ外に置くには `READER_DATA_DIR` を設定して `npm start` を使い続けてください。ディレクトリ構成、再起動、更新は [ローカルインスタンスとデータ](docs/local-instance.md) にあります。未設定では従来の `local/service/` を使い、既存の書斎を自動搬送することはありません。

読書設定では精読／語学学習の目標、優先言語、表示方法、直訳／意訳を独立して選び、切り替えても段落位置を保ちます。古い記録は原文優先のままです。[読書の目標と言語](docs/reading-preferences.md) を参照。

保存した思いと質問は作成時刻・引用・原文位置を保ったまま個別に編集できます。別の編集と競合したら、新しい言葉を読んでから明示的に保存します。失敗した再試行は新しい下書きを残し、出典が不確かなときはジャンプ先を推測しません。動作と下書きバックアップの境界は [自分の思いと質問の編集](docs/personal-records.md) を参照。

AI が欲しいときは、唯一のテンプレート [`.env.example`](.env.example) を `.env` にコピーし、必要なキーを入れます。`DEEPSEEK_API_KEY` は翻訳・読書対話・講義スクリプト用、`GEMINI_API_KEY` は本機の音声用です。モデルは既定で選ばれており、読むだけなら設定不要です。`npm start` は設定を読み、起動メッセージで設定済み／未検証、および現在のデプロイで音声が使えるかを伝えます。同じテンプレートにコメントアウトされたホスティングと高度な設定があります。[設定](docs/configuration.md) を参照。

PDF は最大 256 MB・1,200 ページ、EPUB とテキストは最大 20 MB に対応します。PDF は文字層を先に抽出し、明示的な許可後に設定済みの PaddleOCR で必要なスキャンページを認識できます。EPUB は書内の読書順序に従い、暗号化・DRM 版には未対応です。PDF のしおりと EPUB の目次を優先し、目次がない場合は 30 段落ごとの自動グループを使用します。抽出した本文は校正待ちとして保持します。

書斎と読書ページのチャットから添付またはドラッグで本を追加できます。同じ本カードで進捗を更新し、質問の下書きと読書位置を保持します。完了後に読書を始めるか、対話の本として選択できます。ホスト版の PDF は非公開ストレージへ分割して直接送信し、ローカル版と従来のクライアントには互換経路を残します。[アップロードと章別保存](docs/book-upload-reading.md) を参照してください。

出典パネルでは自分のアップロードした原ファイルを校正用にダウンロードでき、ダウンロード前に内容を検証し、原ファイルは所有する書斎アカウントにのみ提供します。JSON バックアップに原ファイルがない場合は明示し、同じ原ファイルを再アップロードすれば既存の訳文と記録（他のアカウントから移した本を含む）を保ったまま補えます。原ファイルのダウンロードは既存 MCP の本文権限には含まれません。

書斎は最後に読んだ章を表示し、「続きを読む」でその段落と組版に戻ります。ログイン後はサーバー側の位置が優先され、匿名試し読みはローカルブラウザにのみ保存されます。複数タブで同時に読んでも古い位置が新しい位置を黙って上書きせず、ページは内容を保って新しい位置かここから続けるかを選ばせます。エクスポートも同じ確認に従います。

読書設定の「ページレイアウト」はスクロール読書とページ送りを選べます。原文と中国語訳はどちらも開いた本のような見開きで読み、← → キーやページ下部のボタンで送れます。幅 900px 未満は 1 ページ表示です。章末を送ると次の章へ、逆方向は前の章に戻れます。日英対照は並びを保ち、切り替えてもページ送りの設定を覚えています。幅 980px 以下では本文と棚のためドロワー導線になります。

長い段落には段落内の読書比率も保存され、再読み込み、字号変更、別のウィンドウ幅でも段落内の近い位置に戻れます。古い記録は従来どおりピクセルオフセットで復元します。比率位置は一字一句の同一を保証せず、原文と段落識別子は変わりません。

思いや質問は保存中も書き続けられます。保存確認はその提出だけを消し、後から書いた文字は下書きとして残ります。下書きと未確認の提出はブラウザにアカウント・本ごとにキャッシュされ、確認喪失後は正確に再試行でき、再読み込みはまず保存済み記録と照合します。ブラウザが下書きを保てないときはコピーを促します。読み終わり記録の未完了は「下書き」から戻り、タブごとに思いを分けます。書斎のエクスポートは本機の未同期セッションと章マークを結合し、読み終わりの下書きは別にバックアップされます。ウェブから復元しても本機の下書きのままで、保存して初めてメモになります。段落の余白パネルと読み終わり記録は下書き入口を共有し、旧版の段落下書きも探し出せ、エクスポートできます。

匿名試し読みから個人記録を開くと、ログインして同じ原文段落とパネルに戻れます。復帰意図は一度だけ使い、以後の再読み込みは通常の続き位置に従います。ログイン済みで記録読み取りが失敗した場合はその場で再試行でき、新しい位置を読み取ってから続きを読む場所を選びます。エクスポートも同じ保護に従います。引用上限を超える長い文は記録の引用に書き込まず、原文と段落の関連を保って同じ提出 ID で再試行します。

### 本と目次

上部バーの書名と現在の章はクリックでき、既存の紹介・著者・原文出典・現在の章が書誌オーバーレイに開きます。Esc、閉じるボタン、外側クリックで閉じ、本文の位置は変わりません。左の「書斎」と「目次」はアイコン・間隔・タッチ高さを揃え、目次は章ごとに並び、現在の章を示して行全体で入れます。番号付き節の本は節を展開して対応する段落に戻れます。

### 読書の雰囲気

読書ページ右上の「雰囲気」は森のページ、雨の窓の夜読み、小屋の炉火、海辺の朝、「紙面だけ」を選べます。風景は本文の周りに残り、余白パネルを開くと本文は不透明な紙面を保ちます。狭い画面では文字を優先し、夜間モードとシステムの視差効果削減は有効です。

シーンを選ぶと対応する軽い音楽と環境音が既定で有効になり、シーンを変えると音も一緒に変わります。二つの音量は独立に調整でき、ゼロでその系統をミュートし、シーン変更後も覚えています。パネルを閉じても読書は続き、上部バーで音を一時停止できます。再読み込みはシーンを保って自動再生せず、ページを離れると停止し、読み上げ開始時に背景音を下げます。音楽は本機でピアノ音と和音を合成し、環境録音と画像はアプリに同梱され、実行時にサードパーティのメディアサービスへ接続しません。出典・加工・許諾は [素材について](app/assets/atmospheres/NOTICE.md) を参照。

「シーン演出」は本文の裏の森の光、雨脚、炉の暖色、海の緩やかな動きを制御し、パネルのプレビューも追従します。夜間モードは利用でき、本文は安定します。演出と音は別々にオフにでき、バックグラウンドでは動きを止め、システムの視差効果削減が優先されます。

テーマ、音量、演出の好みは現在のブラウザにアカウント・本ごとに保存され、まだ書斎のエクスポート／復元には含まれません。音は読書や翻訳の前提ではなく、読書時間やモデルリクエストを増やすこともありません。

### メールと翻訳

本機でメールログインを使う場合は同じ `.env` に SMTP を設定して `npm start` し、変数は [設定](docs/configuration.md) にあります。コードは実際に SMTP で送られ、10 分で失効、1 回のみ、5 回失敗で無効化。登録とログインは同じ入口で、セッションは HttpOnly Cookie に保存されます。SMTP がなければ送信を装うことはなく、本機書斎は独立した一人用で、メール身分の検証済みを意味しません。

ログアウトでページ上のプライベートな書名、権限リスト、表示中のトークン、ファイル選択を消します。本と作成済みの Agent 許可はサーバーに残り、取り消しは書斎で行います。アカウント切り替え後、古いリクエストは新しいアカウントのページを更新できず、古い復元タスクも書き込めません。他のタブから戻るときは現在の身分を確認します。

`DEEPSEEK_API_KEY` を設定すると、段落をクリックして「この段落を翻訳」を選びます。現在と前後一段ずつだけを送信し、直訳と意訳は AI 下書きとして別々に残ります。字号変更、既存訳の切り替え、読書自体はモデルを呼びません。段落翻訳は DeepSeek API を使い、サンプル本のエコーは公式 DSH を使い続けます。

翻訳中も他の段落へ移動でき、結果は元の段落に帰属します。翻訳中の段落に戻っても再送信できません。離れたり選択を外したりしても、遅れて届いた結果が表示言語を強制的に変えることはありません。失敗と再試行も元の段落に対応します。既存の二訳はローカルで開き、サービス未設定では生成入口を正直に無効化しつつ原文と既存訳を残します。

中国語原文はそのまま読め、既存訳がないときは原文表示のみで、英語や訳欠落とは表示しません。中国語段落に中国語翻訳サービスは呼ばず、既存の二訳記録は読み取れます。抜粋は「中国語原文」と表示し、メモの引用は原文と訳文どちらを指すかを別に保存します。中英判定はテキストのヒューリスティックで、古いプライベート本の読み込み時に初期の言語マークも訂正します。任意の混合言語の本を正確に判別できるという意味ではありません。

書斎の「設定 → データと移行」で、開かれた ZIP バックアップと復元、選択した個人記録の Markdown/JSON、内容が一致する共有プレビューを使えます。同期済みの読書内容、対話と引用、記録と位置を含み、元ファイルの同梱は任意です。認証情報、権限、未完了の AI 処理は含めません。未同期の下書きと聴読データにはそれぞれの復旧・書き出し方法を使います。[読書書庫の移行](docs/library-portability.md)を参照してください。旧 JSON と権限 API の互換性は維持します。

復元は全ファイルの一覧、原文の版と移行先の競合を検査してから書き込みます。不正なパッケージは理由を示して拒否します。有効なパッケージでも書き込み中の I/O 障害では途中の状態が残り、成功とはせず再試行が必要です。同じ ZIP を再度読み込んでも ID は重複せず、移行先の既存の位置と訳文を保ちます。空のインスタンスではバックアップの位置の日時と版を保ちます。モデル処理や権限は再開しません。

### 読書対話

サイドバーの「読書対話」は現在の本をめぐるウィンドウを開きます。まず原文・直訳・意訳を読め、質問を明示的に送ってからモデルが動きます。回答は AI 解釈候補と表示され、引用から原文へ戻れ、質問は対応する段落に保存されて読書カレンダーから回訪できます。

対話は公式 DeepSeek Harness を使い、既定では現在の本だけを必要に応じてページ送りします。送信ボックスの横で「書斎、公開カタログ、ウェブ」を選んで保存できます。送信されるのは質問、書名、現在の章と段落位置、許可範囲内の直近最大 6 往復、必要に応じて読んだ文と検索語で、個人のコメントを自動読み取りすることはありません。範囲、クラウド処理、復元規則は [読書対話の参照範囲](docs/reading-chat-scope.md) を参照。各生成に文脈・時間・コストの上限があります。ウィンドウを閉じても下書きを残し、停止は実行中のインスタンスに中断を送り、再読み込みは同じ質問を再生成せず元のリクエストをまず復元します。モデル未設定では下書きを残して送信を無効化します。1 冊あたり質問は最大 100 件で、ウィンドウから会話をエクスポートできます。これは有界版で、無限履歴はありません。

### 読み上げと章の解説

文字を選んで「選択を読み上げ」、または段落のその他メニューで「ここから聴く」。章頭の「この章を聴く」は導入ガイド、現在位置からの読み上げ、二人の解説を提供し、一冊全体のツアーへ進めます。DeepSeek が原文からスクリプトを分批で整理・検証し、Gemini が声を当て、スクリプトはいつでも展開・編集できます。下部プレイヤーは一時停止、速度、段落送り、出典へのジャンプ、ダウンロードに対応し、スマホでは内容タイトルをタップして操作が増えます。

声と二人の案内役の設定は「読書設定 → 聴く → 声と速度」にあります。速度変更は本機で完結し、再生成しません。初回プレビューは固定の短文を生成し、再試聴は既存の声を再利用します。未翻訳の内容は明示し、対応する原文を聴く選択もできます。

文字は DeepSeek、音声は Google 公式 Gemini 3.8 Flash TTS に直接つなぎ、WAV 音声を受け取ります。日常は `.env` に `DEEPSEEK_API_KEY` と `GEMINI_API_KEY` を入れ、モデルは統一既定値を使います。上書きは `READER_TRANSLATION_MODEL`、`READER_AUDIO_SCRIPT_MODEL`、`READER_SPEECH_MODEL`。旧 `.env.audio`、`READER_DIALOGUE_MODEL`、`npm run start:configured` も互換を保ち、優先順位は [設定](docs/configuration.md) にあります。画像の生成入口はまだなく、既定テンプレートは画像モデルを表示しません。実環境の設定は Git やエクスポートに入らず、公開テンプレートは変数とプレースホルダだけを残します。

音声生成には有効な残高が必要で、不足時は実際のエラーを表示し、課金の再試行や自動プロバイダー切替はしません。キャンセルは以降のセグメントを止め、遅れた結果を拒否しますが、プロバイダーへ送信済みのリクエストは課金される場合があります。聴く位置は読書位置と時間から独立し、復元後は再生タップを待ちます。

音声設定からスクリプト・声・設定・再生位置を含む聴読バックアップをエクスポート／復元できます。復元パックは 32 MB までで、大きい記録は音声を個別にダウンロードします。インポートはすべての出典と声のハッシュを検証してから書き込み、編集済みスクリプトとの競合を上書きしません。本自体は通常の書斎バックアップで移行します。章頭と音声設定の「保存済みの聴読」は音声とスクリプトを開き、復元後は再生を待ちます。吹き込みに使ったスクリプトの版は別に保たれ、後の編集が古い音声の根拠を書き換えることはありません。聴読リストはスクリプトと位置だけのエクスポートもできます。

本機とホスティングは聴読のドメインロジックを共有します。ホスティングのジョブは Supabase プライベート保存、並行リース、有界のバックグラウンド処理を使い、ページを離れても保存済みジョブが未提出の続きを終えます。本文、解説、読書位置は別々に保存します。「ここで聞く」は音を一時停止し、出典付きの既存対話下書きを送信せずに開きます。範囲・費用・復元の詳細は [ガイド付き読書](docs/guided-listening.md) を参照。本人の声の複製は未提供です。

現行の導聴実装と検証は [2026-10-17 検収記録](docs/verification/2026-10-17-guided-listening.md) にあります。実際の公式 Gemini 二人サンプルを生成し、本機ブラウザで再生、原文ジャンプ、質問下書き、セグメント継続を検証しました。

検証の証拠は Git 管理外の `local/verification/audio-reading/` にあります。以前の記録（2026-10-15）：実際の DeepSeek 合成は 8 往復の資料スクリプトで引用チェックを通過。Gemini の最初の短文リクエストは 402 を返し、実音声は生成されていません。プレイヤー、編集、移行は隔離音声で検証しており、Gemini の音質や再生遅延の合格を主張するものではありません。

### MCP 接続

新しい書斎はトークンと設定生成パネルを廃止しました。既存の MCP クライアント、本ごとの許可と取り消しは互換を保ち、プロトコルと範囲は [_briefs/mcp-contract.md](_briefs/mcp-contract.md) にあります。ページ内の読書対話はログイン中のアカウントの単一書権限を直接使い、別の MCP トークンを必要としません。

トークンを折りたたむのはこのページの表示だけを消し、取り消しは以後のアクセスを即座に止め、ページのトークンと設定プレビューを消します。すでに他所へコピーされた内容は自動削除されません。公式 MCP SDK の stdio エントリが同じ本機読書サービスに接続します。既定ポートでの手動例：

```json
{
  "mcpServers": {
    "marginalia": {
      "command": "node",
      "args": ["/absolute/path/to/leafhour/server/mcp.mjs"],
      "env": {
        "READER_SERVICE_URL": "http://127.0.0.1:8330",
        "READER_AGENT_TOKEN": "your-scoped-token"
      }
    }
  }
}
```

ツールは `reader_get_manifest`、`reader_get_context`、`reader_get_chapter`、`reader_search`、`reader_get_notes`、`reader_get_reading_activity`、`reader_add_highlight`, `reader_get_annotations`, `reader_add_annotation` and `reader_add_comment`。本文、メモ、活動、コメント書き込みは個別に許可し、書き込みはユーザーが明示的に渡した言葉のみを受け付け、冪等キーで二重保存を防ぎます。Agent の読み取りが読書時間を増やすことはありません。本機設定はループバック接続、クラウド設定は認証済み接続エンドポイントが返す実際のデプロイ済みソースコミットに固定し、ソースパックから同じ stdio アダプタを起動し、設定中の HTTPS 書斎を明示的に許可します。完全コミットは実際に動く版を固定し、npm がホスティングのソースパックを直接取得できるようにします。リモートアクセスは引き続き本とデータ種別ごとの許可で、リダイレクトを拒否します。これはリモート OAuth MCP エンドポイントではありません。設定生成はユーザーの Agent へのインストールを意味しません。

## プライベートホスティング

公開コードとプライベートデータは分かれます：

```text
Public repo: feature branch → PR → main → Vercel verification and deployment
                                 │ server-side secret
                                 ▼
                         Supabase private tables
                         ├─ book + translations
                         └─ notes + reading state
```

スキーマのマイグレーションは `supabase/migrations/`。現行版は専用の `reader_documents` テーブルとプライベートな `reader-originals` バケットを使い、RLS が有効で `anon` と `authenticated` に直接の表権限はありません。旧い 2 枚の単書テーブルは互換のために残り、公開入口ではありません。Vercel Function はサーバー側 secret でアクセスします。完全なデプロイ手順は [deploy/README.md](deploy/README.md)、自動化は [docs/ci-cd.md](docs/ci-cd.md)。

ブラウザにサーバー鍵は不要です。唯一のテンプレート [`.env.example`](.env.example) の「ホスティングデプロイ」節に必要な変数があり、実際の値は Vercel Environment Variables に、ローカル実行は Git 管理外の `.env` に入れます。

現在のデータベース構造、アカウント分離、原ファイル保存、既定のテストデータの帰属は [データベースと既定のテスト書斎](docs/data-workspace.md) を参照。
